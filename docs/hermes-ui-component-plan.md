# 헤르메스 대화 UI 공통 컴포넌트 도입 계획

2026-11-21 작성. 도구 검색에서 생성기를 고른 사용자와 작업 결과에서 후속 생성기를 고른 사용자가 같은 폼에서 편집을 시작하도록 한다. 이번 계획의 대상은 헤르메스 대화 GUI다. 실행·결과 연결 정책이 충돌하면 [워크플로우 설계](hermes-generator-workflow-design.md)를 우선한다.

## 적용할 기술과 경계

assistant-ui는 메시지, 스레드와 대화 상태를 담당한다. 검색·편집에는 shadcn/ui의 Command, Sheet, Field를 필요한 순서대로 도입한다. 컴포넌트 소스는 GUI에서 관리하고 Python 생성기, 세션 저장소, 대기열은 기존 게이트웨이 명령을 통해 사용한다. [assistant-ui Thread](https://www.assistant-ui.com/elements/thread) · [shadcn/ui](https://ui.shadcn.com/docs)

현재 GUI는 React JSX와 esbuild를 사용한다. 첫 패치에서 별도 작업 사본에 검색 컴포넌트 하나를 적용해 설치 전후 직접·전이 패키지와 압축 번들 크기, CSS 빌드 단계를 기록한다. 기본 shadcn 스타일을 쓰기 위해 Tailwind 빌드가 필요한 경우 기존 CSS와 함께 빌드하는 비용을 비교한다. 도입 비용이 큰 컴포넌트는 Radix 기본 요소와 공통 CSS로 같은 사용 흐름을 구현한다. 직접 import하는 패키지는 GUI의 직접 의존성으로 선언하고 잠금 파일과 배포 번들을 함께 검증한다. [GUI 빌드 설정](../gui/package.json) · [Radix Primitives](https://www.radix-ui.com/primitives/docs/overview/introduction)

## 사용자가 경험할 변화

| 장면 | 조작과 피드백 |
|---|---|
| 도구 검색 | 작성창에서 검색을 열면 검색어에 포커스가 간다. 생성기와 조회·검수 도구를 함께 찾고 이름과 기능으로 식별한다. ‘대화에 추가’는 기존 문장을 보존한다. 등록된 입력 템플릿이 있는 도구에는 ‘입력 폼 편집’을 제공한다. |
| 입력 폼 편집 | 검색과 결과 화면은 같은 편집 패널을 연다. 상단에는 생성기와 편집 대상, 본문에는 라벨·값·필드별 오류를 표시한다. 저장한 폼을 복사하면 원본 이름·버전을 표시하고 복사본으로 저장한다. 닫고 대화로 돌아가도 같은 세션의 편집값을 이어 쓸 수 있게 한다. |
| 작업 결과 연결 | 결과 카드에서 원본 실행·단계·출력을 확인한다. 등록된 후속 단계에는 연결할 입력과 전달 효과를 보여준 뒤 선택을 확정한다. 완료된 텍스트로 새 작업을 시작할 때는 호환 필드를 고르면 공통 편집 패널에 값이 채워진다. |
| 대기열 확인 | 작성 중인 메시지를 유지한 채 실행 상태와 결과를 확인한다. 대기·실행·실패는 문구로 구분한다. 결과를 닫으면 직전에 선택한 항목으로 포커스가 돌아간다. |

## 패치와 검수 순서

1. **검색과 디자인 기준.** 버튼의 주 동작·보조 동작, 입력 라벨, 선택 상태, 포커스 표시를 공통 스타일로 정의한다. 검색에서 화살표·Enter로 도구를 고르고 Esc로 닫는다. 한글 조합 중 Enter, 빈 검색 결과, 카탈로그 조회 실패를 각각 검수한다. [대화 셸](../gui/app.jsx)
2. **편집 패널 통합.** 검색·저장된 버전·작업 결과 진입점이 동일한 편집기를 사용하도록 한다. 필수값을 비운 채 저장하면 해당 필드에서 수정할 수 있어야 한다. 복사본 저장 후 원본 값과 버전을 다시 읽어 비교하고, 편집 중 생성 접수가 0건인지 확인한다. [폼 목록](../gui/FormLibrary.jsx) · [단계 편집기](../gui/StepBuilder.jsx)
3. **결과와 실행 상태.** 번역 결과를 이미지 프롬프트에 연결하는 격리 예제로 원본 출력과 대상 입력을 대조한다. 새로고침 후 확정된 연결을 다시 조회하고, 선행 실패나 오래된 결과 선택 시 후속 작업이 접수되지 않는지 확인한다. [결과 화면](../gui/WorkflowResults.jsx) · [대기열](../gui/QueuePanel.jsx)
4. **반복 검수와 반영.** 각 패치에서 같은 세션 데이터로 데스크톱 1366×813과 모바일 390×844를 비교한다. 키보드로 검색부터 결과 복귀까지 이동하고, 검색·편집·닫기 과정에서 초안과 스크롤 위치를 확인한다. 모바일 가로 넘침 없음, 상단 100px 이하, 데스크톱 대기열 기본 보기에서 대화 높이 480px 이상을 확인한다. 발견한 문제를 수정한 뒤 같은 절차를 다시 수행하고 변경·측정값·미검증 항목을 커밋에 기록한다. [기존 UI 검수 기준](hermes-ui-review-plan.md)

도입 여부는 첫 흐름의 브라우저 검수와 빌드 결과로 결정한다. 격리 데이터에서 접수·실패·재시도를 검증하고, 운영 화면에서는 배포 번들 로딩과 기존 세션 조회를 확인한다.
