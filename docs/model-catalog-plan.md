# 모델 카탈로그와 `.model` 관리 계획

상태: 실행 목표 · 2026-11-24

## 현재 상태 · 2026-11-26

- `.model/models`와 `.model/audio`는 제거됐고 해당 모델은 독립 경로에서 관리한다. Hugging Face 캐시는 Git에서 제외한 `.cache/huggingface`에 있다. 아래 이관 기록의 이전 경로와 미완료 표시는 당시 시점의 기록이다.
- 현재 숨김이 아닌 모델 디렉터리 34개의 일반 백업 대상에 완료 스냅샷이 있으며, 파일 경로 1,917개가 크기와 기록된 원본 수정 시각 기준으로 일치했다. 각 스냅샷에는 백업 당시 SHA-256 검증 완료 이력이 연결되어 있다. 이 확인은 34개 전체를 현재 다시 해시한 결과가 아니다.
- 실제 Samba에서 Demucs와 AnimationGPT 스냅샷을 각각 별도 임시 루트에 오프라인 복원해 파일 해시를 확인했다. 모든 모델의 복원 또는 추론 시험은 아니다. 스냅샷은 원본 심볼릭 링크와 공유 관계를 파일로 펼쳐 저장한다.
- 이관된 `flux-report-vision`의 완료 스냅샷 `5e1152761eb84a7e892cc49b9889638e`도 별도 임시 모델 루트에 오프라인 복원했다. 40개 파일 총 1,019,894,686바이트가 스냅샷 매니페스트의 SHA-256과 일치했고 수정 시각 불일치 및 미완료 확장자 파일은 없었다. 공급처 연결을 차단한 상태에서 가중치를 CPU에 로드해 테스트 이미지 추론을 수행했으며 임시 루트는 제거했다. 공급처 진본 인증과 다른 입력의 품질 검증은 별도다.
- 같은 FLUX 스냅샷의 별도 임시 복원·해시 검증을 다시 수행하고 로컬 복원 이력을 기록했다. 실제 카탈로그 화면에서 해당 일반 백업 대상의 스냅샷 ID, 시각, 파일 40개, 수정 시각 불일치 0개 및 미완료 확장자 0개가 과거 복원 기록으로 표시되는 것을 확인했다. 기록은 사용자별 로컬 파일이며 최신 스냅샷 상태나 추론 성공을 보장하지 않는다.
- 2026-11-26 현재 Hermes의 Qwen 준비 기록 검사, TranslateGemma 매니페스트·파일 존재 검사, MiniMax 이미지 필수 파일·크기 검사는 각각 준비 상태를 반환했다. 이 조회는 새 가중치 전체 해시나 GPU 추론을 실행하지 않았다.
- 같은 날 HeartMuLa와 Dasheng의 다운로드 준비 기록을 현재 독립 구성 모델의 파일 속성과 대조한 검사도 각각 참을 반환했다. 이는 준비 기록 이후 크기·시각 변경 여부에 대한 검사이며 전체 파일 재해시나 이관 후 GPU 추론 성공을 보증하지 않는다.
- 관리 화면에서 모델별 조사와 대상별 백업 상태를 확인할 수 있다. 정리 후보 종합 기능, 미확인 의존성과 복원 시험 결과의 완전한 연결, 회수 가능 용량의 근거는 아직 미완료다. 보존 원본과 미완료 다운로드 조각은 삭제하지 않았다.
- 2026-11-26 카탈로그 조회에서 선언 40개와 미분류 최상위 대상 0개를 확인했고 백업 목록 접근 오류는 없었다. 마지막 파일 조사 기록에도 변경 및 오류 표시는 없었다. 과거 `huggingface`, `prompt-translation`, `writer-agent` 경로는 각각 현재 캐시 또는 독립 모델 경로가 대체 설치본으로 표시된다. 폐기된 Wan 2.1과 TRELLIS 경로는 활성 설치본이 없으며 TRELLIS 보존 원본은 별도로 표시된다. 이 조회는 숨김 경로 전체나 모든 파일 소비자의 완전한 분류를 증명하지 않는다.
- 미분류 대상에도 완료 스냅샷 존재 여부와 해당 대상의 백업 비교 이동 버튼을 표시한다. 로컬이나 기존 공유 디렉터리가 없고 스냅샷만 있는 경우도 구분할 수 있으며, 존재 표시는 내용 검증 결과가 아니다.
- 임시 모델의 완료 스냅샷을 만들고 원본 디렉터리를 임시 위치로 옮긴 격리 시험에서 백업 목록과 카탈로그가 해당 대상을 로컬 없음·기존 공유 없음·완료 스냅샷 있음으로 전달함을 확인했다. 같은 시험에서 스냅샷 메타정보 조회와 매니페스트 해시 검증 및 손상 탐지도 확인했다. 실제 관리 화면의 스냅샷 전용 항목 이동은 별도 검증이 필요하다.
- 실제 관리 화면에서 스냅샷만 있는 등록 항목 `huggingface`를 카탈로그에서 백업 비교로 이동했다. 로컬 원본이 없어 비교와 새 백업이 비활성화되고, `스냅샷 자체 무결성`을 선택하면 SHA-256 검증 버튼이 활성화되는 것을 확인했다. 검증 작업은 시작하지 않았다. 미분류 항목 이동은 실제 미분류 항목이 없어 별도로 확인하지 못했다.
- 이후 스냅샷만 있는 항목을 선택하면 `스냅샷 자체 무결성`이 자동 선택되도록 개선했다. 실제 화면에서 `huggingface`를 직접 선택하고 로컬 `animationgpt`로 전환한 뒤 카탈로그를 통해 다시 이동해 자동 선택과 일반 대상 복귀를 확인했다. 해시 검증 작업은 실행하지 않았다.
- 2026-11-26 빈 임시 모델 루트와 실제 Samba 설정을 사용해 HeartMuLa의 Demucs 준비 함수를 다운로드 허용 상태로 실행했다. HTTP 공급처 요청을 차단한 상태에서 공용 다운로드 경로가 Samba 스냅샷의 가중치를 복원하고 준비 함수의 고정 SHA-256 검사까지 통과했다. 시험용 설정과 복원 파일은 임시 디렉터리와 함께 제거했다. 이 시험은 Demucs 한 파일의 백업 우선 준비 경로이며 GPU 오디오 분리 실행이나 Hugging Face 전체 오프라인 자동 복원을 검증하지 않는다.
- 격리 시험에서 손상된 스냅샷의 해시 불일치 시 해당 백업을 수정하지 않고 모의 HTTP 공급처의 정상 파일을 검증해 내려받는 경로를 확인했다. 대상에 해시가 맞지 않는 기존 파일이 있으면 백업 복원과 HTTP 요청을 모두 하지 않고 파일을 보존하는 것도 확인했다.
- 로컬 복원 이력은 시간대가 없는 시각이나 파일 수를 초과하는 미완료·수정 시각 불일치 개수를 유효한 성공 기록으로 읽지 않는다. 잘못된 이력은 확인 불가로 취급하며 스냅샷 파일 자체를 변경하지 않는다.
- 관리 화면의 `미완료 다운로드 관측` 영역에서 해당 경로의 이전 조사 크기, 선언 서비스, 대기·예약 관측, 최근 백업 작업, 스냅샷과 복원 기록을 함께 볼 수 있다. 실제 화면에서 MiniMax 세 경로의 파일 수와 당시 할당 크기 및 각각의 직접 백업 대상을 확인했다. 대기·예약은 전체 프로세스 관측이 아니며 삭제 가능성이나 회수 가능 용량을 판정하지 않는다.
- 이관된 설치본의 기본 표시는 같은 경로의 일반 백업 대상이 있으면 이를 우선한다. `catalog-*` 별칭 대상의 이력은 별도로 남겨 두며, 다른 경로의 설치본을 선택한 것으로 취급하지 않는다. 실제 화면에서 TranslateGemma와 작가 임베딩의 일반 대상 스냅샷 있음 및 별칭 스냅샷 없음을 각각 분리해 표시하는 것을 확인했다. 존재 표시는 해시 검증이 아니다.
- 현재 경로 해석 함수를 읽기 전용으로 실행해 Hermes, TranslateGemma, 작가 임베딩이 각각 독립 모델 경로를, Hugging Face가 `.cache/huggingface`를 가리키는 것을 확인했다. HeartMuLa와 Dasheng은 `.local/audio-model-runtime`의 준비 기록과 별개로 각 모델·코덱·Demucs·인코더·토크나이저의 독립 경로를 찾았고 해당 디렉터리는 존재했다. 이번 검색에서 찾은 이전 `models/`, `audio/` 경로 참조는 이관 기록 및 구형 설치 호환 분기에 있었다. 경로 존재 확인은 파일 무결성이나 실제 추론 성공이 아니다.
- 오디오 준비 기록을 현재 코드와 대조한 결과 HeartMuLa와 Dasheng의 다운로드 완료 기록은 각각 유효했고 `prepared.json`에 기록된 런타임 코드 해시도 현재 파일과 일치했다. Dasheng 준비 기록에 나열된 파일 27개는 모두 현재 독립 경로에서 존재했다. 파일 내용 재해시나 오디오 추론 검사는 아니다. 이 준비 기록은 `.local`에 있으므로 모델 디렉터리 스냅샷만 다른 환경에 복원해도 자동으로 함께 복원되지 않는다. 특히 Dasheng은 준비 기록이 없으면 준비 과정에서 공급처 다운로드 경로를 호출하므로 공급처 없이 새 환경에서 전체 서비스 준비가 완료된다고 보장하지 않는다.
- Dasheng 세 모델의 현재 Samba 스냅샷에는 Hugging Face 로컬 다운로드 메타데이터도 포함돼 있다. 그러나 격리 시험에서 사용 중인 `huggingface_hub` 0.36.2의 `snapshot_download(local_files_only=True)`는 필수 모델 파일이 전혀 없는 비어 있지 않은 디렉터리도 반환했다. 따라서 단순히 오프라인 옵션을 켜는 것만으로는 완전한 모델이나 고정 리비전을 증명할 수 없다. 오프라인 재준비에는 스냅샷 매니페스트의 파일 목록·해시와 소비자 필수 구성 및 실제 로드를 검증하는 별도 절차가 필요하다.

모델별 저장 공간 관측을 갱신하려면 프로젝트 루트에서 아래 명령을 실행한다. 파일 내용과 모델은 수정하지 않으며, 결과는 Git에서 제외된 `.local`에 기록한다. 조사 도중 파일이 바뀌거나 오류가 발생하면 화면의 경고를 확인하고 다시 조사한다.

```bash
mkdir -p .local/model-catalog/surveys
survey_tmp=$(mktemp .local/model-catalog/surveys/.survey-XXXXXX)
survey_args=()
for model_dir in .model/*/; do
  [[ -d "$model_dir" && ! -L "${model_dir%/}" ]] || continue
  survey_args+=(--nested "$(basename "$model_dir")")
done
if python3 -m workflow.common.model_catalog_survey .model "${survey_args[@]}" > "$survey_tmp"; then
  mv -n "$survey_tmp" ".local/model-catalog/surveys/$(date +%F-%H%M%S-%N)-models.json"
else
  rm -f "$survey_tmp"
fi
```

이 조사는 숨김이 아닌 최상위 디렉터리의 직계 항목을 별도로 기록한다. 이전 관측은 현재 사용·삭제 가능 상태를 보증하지 않으며, 미완료 확장자 파일도 조사 당시의 이름과 할당 크기로만 분류한다.
2026-11-26 위 명령으로 조사 기록을 생성하고 카탈로그에서 34개 디렉터리와 MiniMax 이미지 미완료 확장자 파일 8개를 읽는 것을 확인했다.

모델 간 동일 내용 후보 조사는 별도로 실행한다. 최신 Samba 스냅샷 매니페스트에서 1 MiB 초과 파일의 해시와 크기가 다른 모델 경로에 반복되는 후보를 찾고, 해당 로컬 파일을 실제로 읽어 SHA-256을 비교하므로 후보 크기에 따라 시간이 걸린다. 실행 중인 파일의 변화를 감지하면 확인 불가로 남긴다. 결과는 로컬에 저장해 카탈로그에서 확인하며, 기존 결과는 새 조사가 성공한 경우에만 교체한다.

```bash
duplicate_tmp=$(mktemp .local/model-catalog/.duplicates-XXXXXX)
if python3 -m workflow.common.model_duplicate_survey > "$duplicate_tmp"; then
  mv "$duplicate_tmp" .local/model-catalog/duplicate-observations.json
else
  rm -f "$duplicate_tmp"
fi
```

해시 일치는 조사 시점의 파일 내용에 한정된다. 링크·공유 관계, 서비스 의존성 및 삭제 영향이 있어도 자동으로 정리하지 않으며 회수 가능 용량으로 환산하지 않는다.

오디오 모델을 복원한 뒤 현재 설치본과 최신 Samba 스냅샷을 읽기 전용으로 대조하려면 아래 명령을 사용한다. 서비스별 모든 구성 모델과 스냅샷을 전부 읽으므로 대용량 파일과 네트워크 사용량이 크다. 다른 다운로드·이관 작업이 진행 중이면 결과를 완료 판정에 사용하지 않는다.

```bash
python3 -m workflow.common.model_offline_audio_check sfx-dasheng-audiogen
python3 -m workflow.common.model_offline_audio_check music-heartmula
```

각 스냅샷의 현재 내용을 백업 당시 매니페스트 해시와 확인한 뒤 현재 설치본을 같은 스냅샷과 비교한다. 두 단계 사이 최신 스냅샷 ID가 바뀌거나 누락·불일치·미완료 확장자가 있으면 전체 결과는 실패다. 현재 고정 모델의 주요 설정·가중치와 HeartMuLa 샤드 목록도 최소 필수 파일로 확인한다. 이 검사는 백업 당시의 바이트 일치와 제한된 파일 존재만 확인하며 공급처 진본, 서비스 준비 기록 재생성, 전체 필수 구성 또는 GPU 로드·추론 성공을 보장하지 않는다. 파일을 변경하거나 준비 기록을 만들지 않는다.
진행 표시는 표준 오류에 모델·단계·현재 파일과 해당 파일의 처리 바이트를 약 5초 간격으로 출력한다. 최종 JSON은 표준 출력으로 분리되며 표시되는 바이트는 전체 작업 누적량이 아니다.

2026-11-26 실제 Samba의 Demucs 스냅샷 `cb4b4b0042924fe294349a819608fe9b`과 현재 설치본에 위 검사 함수를 적용해 파일 1개의 양쪽 SHA-256 일치와 미완료 파일 0개를 확인했다. 이는 Demucs 한 구성요소의 검사이며 서비스별 전체 명령을 실제 모델에서 실행한 결과가 아니다.
같은 날 HeartMuLa와 Dasheng의 여섯 구성요소에 대해 새 검사기의 최소 필수 파일 이름이 현재 로컬 경로와 최신 스냅샷 매니페스트에 모두 있는 것을 확인했다. 이 이름 대조는 파일 내용을 읽거나 해당 모델의 완전성을 확인한 것이 아니다.

## 목적과 현황

모델을 생성기 이름이나 디렉터리 이름만이 아니라 출처, 버전, 파일 구성, 사용 서비스와 백업 상태로 찾는다. 모델을 삭제하거나 이동하기 전에 어떤 서비스가 사용하는지와 복구 가능성을 확인한다. 사용자는 필요한 폴더 경로 조정을 승인했다. 이 문서는 이동 완료 기록이 아니며, 모델 삭제와 백업 제거를 포괄적으로 승인한 것으로 해석하지 않는다.

2026-11-24 로컬 조사에서 `.model`은 `du` 기준 약 644GiB였다. 생성기별 폴더, 공용 구성요소, Hugging Face 캐시, 잠금 파일과 준비 기록이 함께 있다. `animationgpt-author`는 `animationgpt`의 두 하위 폴더를 심볼릭 링크로 참조한다. 실제 사용 관계는 폴더 이름과 일대일이 아니다. Kimodo와 DWPose도 포즈 모델 경로를 공유한다. 크기는 조사 시점의 값이며 파일시스템 사용량과 논리 크기, 링크를 따라 복사한 백업의 크기는 다를 수 있다.

기존 `model_file_inventory.py`는 등록 서비스에서 사용하는 경로를 나열하고, `model_backup_metadata.py`는 일부 `manifest.json`을 정규화한다. 이 정보는 유용하지만 전체 모델의 고정 식별자·의존 관계·버전 이력을 포괄하는 카탈로그는 아니다. 일부 생성기는 기존 절대 또는 `.model` 상대 경로를 직접 사용하며, 준비 파일 형식도 `manifest.json`, `prepared.json` 등으로 다르다. 이들의 내용과 신뢰도는 각각 확인해야 한다.

사용자는 폴더 정리가 모두 끝나면 직접 백업을 다시 하기로 했다. 자동으로 새 백업을 시작하지 않는다. 기존 `rsync -rtL --partial` 작업과 관리 화면의 스냅샷은 서로 다른 백업이다. `-L`은 심볼릭 링크 대상을 따라 복사하므로 원본의 공유 관계가 백업에서 별도 복사본이 될 수 있다. 진행 중인 작업의 상태와 대상 파일 사용 여부를 확인한다. 기존 작업을 임의로 중단하거나 기존 백업을 제거하지 않는다.

## 권장 설계

물리 디렉터리 재배치보다 먼저 **논리 카탈로그**를 도입한다. 카탈로그가 현재 파일 위치와 서비스의 다대다 관계를 설명하고, 기존 생성기는 현재 경로를 계속 사용한다. 카탈로그와 실제 파일의 차이는 관측 결과로 보여주며 자동으로 경로를 바꾸거나 삭제하지 않는다.

관리 단위는 다음을 구분한다.

1. **모델 항목:** 사람이 찾는 이름과 고정 ID, 용도, 출처와 라이선스 링크, 관련 서비스 및 구성요소 관계.
2. **모델 버전:** 저장소 또는 공급처, 리비전, 형식·정밀도·변환 여부, 필요한 파일과 공급처가 제공한 해시의 출처. 미확인 값은 비워 둔다.
3. **설치본:** 실제 경로와 파일 상태, 파일별 크기, 준비 기록, 관측 시각. 같은 버전이 여러 위치에 있을 수 있고 캐시·임시 파일은 별도로 식별한다.
4. **백업본:** 공유 폴더 또는 완료 스냅샷의 위치·대상 버전·시각·검증 결과. 존재, 크기·시간 일치, SHA-256 일치, 복원 시험 성공은 서로 다른 상태다.
5. **서비스 의존성:** 서비스가 필수 또는 선택적으로 사용하는 설치본·공유 구성요소. 미확인 관계는 `unknown`으로 남기며 미사용으로 추정하지 않는다.

카탈로그의 선언 정보와 스캔한 사실을 분리한다. 사람이 유지하는 ID·출처·의존성은 Git 추적이 가능한 버전 관리 문서에 두고, 실제 위치·마운트·해시 관측·작업 이력 등 기기별 상태는 Git에서 제외한 로컬 저장소에 둔다. 대용량 파일의 SHA-256은 명시적 검증 작업에서 계산하고, 화면을 열 때 자동으로 전부 읽지 않는다. 선언 해시, 공급처 해시와 직접 계산한 해시의 출처 및 시각을 구분한다.

물리 구조는 조사 결과와 소비자 이관을 검증한 뒤 결정한다. 후보는 `models/`(버전별 모델), `shared/`(명시된 공유 구성요소), `cache/`(재생성 가능한 캐시), `staging/`(다운로드 중 파일)와 별도 상태 저장소다. 이는 목표 구조의 예시이며 지금 `.model` 아래에 디렉터리를 만들거나 기존 경로를 바꾸라는 지시가 아니다. Hugging Face 캐시의 내부 레이아웃, 하드링크·심볼릭 링크와 프레임워크의 기대 경로는 보존해야 한다.

## 단계와 완료 조건

### 1. 읽기 전용 실태 조사

- `.model`의 파일·크기·링크·매니페스트 형식과 서비스별 참조 경로를 수집하고, 잠금·진행 중 다운로드 및 백업 작업을 기록한다. 권한 오류, 끊어진 링크, 스캔 중 파일 변경은 확인 불가로 기록한다.
- 폴더별 논리 크기와 실제 사용량을 구분하고, 해시 없이 이름이나 크기만으로 중복을 확정하지 않는다. 대용량 해시 검사는 명시적으로 선택한다.
- 산출물은 모델/구성요소/서비스/설치 위치의 대응표와 미확인 항목이다. 원본 파일을 수정하지 않는 재실행 가능한 조사로 검증한다.

### 2. 카탈로그 스키마와 초기 등록

- 버전이 있는 스키마와 안정적인 모델·버전·구성요소 ID를 정의한다. 절대 경로와 사용자 인증 정보는 추적 파일에 넣지 않는다. 기존 매니페스트를 어댑터로 읽되 선언값과 관측값을 구별한다.
- FLUX, Kimodo/DWPose 공유 모델, Hugging Face 캐시, Samba에만 남은 모델을 대표 사례로 등록하고 누락·중복 ID·잘못된 경로·스키마 버전을 검사한다. 등록되지 않은 기존 파일은 삭제 대상이 아니라 미분류로 표시한다.
- 카탈로그가 없어도 기존 생성기와 다운로드가 동작하는지 확인한다. 기존 경로와 CLI·게이트웨이 계약을 유지한다.

### 3. 관리 화면과 조회 API

- 모델명·생성기·출처·버전·저장 위치로 검색하고 모델과 설치본을 구분해 표시한다. 공유 구성요소의 사용 서비스를 표시한다. 파일 상태, 최종 검증 시각과 백업 상태는 근거 및 확인 불가를 함께 표시한다.
- 선택한 모델에서 연결된 설치본과 백업 비교·검증 이력으로 이동한다. 디렉터리 이름이 곧 모델 ID라고 가정하지 않는다. 로컬과 백업-only 항목 및 다수 설치본을 다룬다.
- 실제 관리 화면에서 검색·선택·연결 실패·오래된 결과·좁은 화면·키보드 조작을 검증한다. 기존 백업과 사용자 작업은 취소하지 않는다.

### 4. 안전한 백업·복원 연결

- 카탈로그의 설치본과 기존 스냅샷 매니페스트를 연결하고, 백업 저장 위치 및 해시 출처를 기록한다. 기존 rsync 결과와 스냅샷을 혼동하거나 서로 덮어쓰지 않는다. 새로운 전체 백업은 폴더 정리가 완료된 뒤 진행한다.
- 검증 가능한 공급처 해시 또는 신뢰할 수 있는 고정 해시가 있는 파일만 백업 우선 복원한다. 부분 파일, 링크, 경로 탈출, 원본 변경 및 연결 해제를 처리하고 실패하면 기존 다운로드 경로를 유지한다.
- 작은 대표 모델을 별도 임시 위치에 복원해 해시와 소비 경로를 확인한다. SHA-256 일치만으로 공급처 진본이나 실제 추론 품질을 보장하지 않는다.

### 5. 정리 후보와 선택적 물리 이관

- 용량·중복 후보·서비스 의존성·실행 중 작업·백업 검증·복원 시험 결과를 한 화면에 표시한다. 자동 삭제 없이 후보와 절약 가능 용량을 미리 보여주고, 공유 파일과 미확인 항목은 안전한 삭제 대상으로 분류하지 않는다.
- 필요한 폴더 경로 조정은 사용자가 승인했다. 모델 한 개씩 새 위치와 소비자 지원을 준비하고, 충분한 공간과 기존 백업·복구 가능성을 확인한다. 이관 전 새 백업을 만들지는 않는다. 원본을 보존하는 이동·되돌리기 절차가 안전하게 확보되지 않으면 해당 항목은 보류한다. 관련 다운로드·추론·백업이 해당 파일을 사용 중이면 이관을 기다린다. 기존 링크와 공유 파일의 소유 관계를 조사하고 경로별 소비자와 백업·복원 매핑을 함께 갱신한다.
- 이동 전후 해시와 서비스 준비 상태를 검증하고 실패 시 기존 경로로 되돌릴 수 있어야 한다. 이관 과정에서 필요한 이름 변경과 경로 교체는 승인 범위에 포함한다. 중복으로 보이는 모델, 검증되지 않은 백업 및 불필요하다고 추정되는 파일의 삭제는 별도 범위다.
- 폴더 정리와 소비자 검증이 완료되면 사용자가 최종 경로를 기준으로 Samba 백업을 다시 수행한다. 백업 결과와 복구 가능성은 별도로 확인하며, 그전까지 기존 백업을 보존한다.

## 실행 계약과 최종 검증

- 조사 결과는 파일별 오류와 관측 시각을 보존하며, 미분류·확인 불가를 숨기지 않는다. 스캔 중 변경된 항목은 재검사 대상으로 둔다.
- 추적하는 카탈로그에는 스키마 버전과 유일한 ID를 두고, 관측 기록에는 카탈로그 ID·위치 유형·관측 시각·결과와 근거를 기록한다. 사용자별 실제 마운트 주소와 인증 정보는 추적하지 않는다.
- 각 이관의 사전 기록에 원본·대상·소비자·백업 상태·필요 공간·되돌리는 절차를 남긴다. 성공은 새 위치의 내용 검증과 관련 서비스 준비·다운로드·백업 우선 복원 경로 확인으로 판정하며, 실패는 미완료로 남기고 기존 사용 경로를 복구한다.
- 완료 전 실제 로컬·백업 목록과 카탈로그를 대조하고 누락·미확인 항목을 보고한다. GUI·CLI의 검색, 공유 의존성, 백업-only, 단절과 오래된 결과, 직접 복원 시험 및 해당 모델의 기존 준비 경로를 검증한다. 실제 추론이나 모든 가중치의 전체 해시를 수행하지 않은 경우 범위를 명시한다.

## 결정할 사항

- Git에서 유지할 카탈로그 형식과 관리 주체, 기존 매니페스트를 원본으로 취급할 범위.
- 한 서비스가 모델 여러 개를 쓰거나 한 모델을 여러 서비스가 공유할 때의 구성요소 식별 기준.
- 라이선스·접근 제한·출처 미확인 모델을 어떻게 표시할지와 재다운로드가 불가능한 모델의 보존 정책.
- 저장소 여유 공간과 네트워크 비용을 고려한 스냅샷 보존 기간 및 복원 시험 범위.
