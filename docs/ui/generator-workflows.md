# 생성기 사용 흐름

공통 흐름은 모델 준비 → 입력과 검증 → 생성 확인 → 진행 상태 → 이력과 결과다. 실행 중인 작업을 살펴보면서 새 입력을 작성할 수 있어야 하며, 이력 조회와 결과 선택은 생성 요청과 구분한다. 생성기별 기능·입력·제약의 사용설명은 해당 생성기 페이지에서 직접 제공한다.

- 입력의 필수 여부, 단위, 제약과 해결 가능한 오류를 해당 필드 가까이에 표시한다.
- 영상 입력은 선택 또는 복원한 실제 파일을 해당 입력 옆에서 재생해 확인할 수 있어야 한다. 파일명과 규격·검증 상태를 함께 표시하고, 브라우저 재생 실패는 명확히 알린다. 파일 교체·제거 시 이전 미리보기는 해제한다.
- 생성 전 확인은 입력을 보존하고, 취소는 요청을 접수하지 않는다. 중복 접수를 방지한다.
- 진행 상태는 현재 단계와 전체 예상치를 구분하고, 실제로 확인된 근거와 관측 범위만 표시한다. 마지막 조회를 한 번 표시하고 별도 관측 시각은 상세에 둔다.
- 이력 선택, 결과 조회, 복원, 삭제는 서로 구분하고 대상과 비활성 사유를 표시한다. 선택 결과는 해당 이력 안에 표시하고 닫을 때 해당 이력 항목으로 초점을 복원한다. 진행 작업이나 직접 주소의 결과도 작업 ID로 이력과 연결한다.
- 같은 역할은 공용 컴포넌트를 사용한다. 서비스별 검증과 결과 유형은 해당 서비스가 소유한다.

## 이력의 입력 확인과 적용

입력을 다시 사용하는 흐름은 **결과의 저장 입력 확인 → 입력 적용 → 입력 검토** 순서로 제공한다. 결과를 열면 저장 입력을 자동으로 조회해 같은 작업의 결과에 표시하며, 별도 조회 버튼을 눌러야 내용을 볼 수 있게 하지 않는다.

- 저장 입력의 주요 설정과 상세 요청은 긴 결과 영상·로그보다 앞에 표시한다. 조회 중과 조회 실패·재시도 방법을 표시하며 다른 작업의 응답을 잘못 연결하지 않는다. 조회는 현재 입력을 변경하지 않는다.
- 기존 `입력값 불러오기` 자리에 `입력 적용`을 제공한다. 한 번 누르면 해당 이력의 입력과 필요한 첨부를 확인한 뒤 적용하고, 별도의 확인·적용 버튼을 다시 요구하지 않는다.
- 지원하지 않거나 읽지 못한 필드·첨부가 있으면 현재 입력과 첨부를 보존하고 실패 사유와 재시도 방법을 알린다. 적용 자체는 생성 요청을 접수하지 않는다.
- 적용이 성공하면 입력 카드를 열고 입력 영역으로 이동해 초점을 둔다. 적용한 원본 작업을 밝히고 완료를 알린다. 이력 선택·결과와 검색 상태는 적용을 위해 불필요하게 초기화하지 않는다.
- 좁은 화면에서도 순서와 클릭 영역을 유지한다. 선택한 결과가 길거나 입력 카드가 접혀 있어도 입력 정보와 적용 동작을 찾을 수 있어야 한다.

이 절은 목표 계약이다. 공용 이력 컴포넌트의 변경과 각 생성기의 파일 복원·오류 처리·초점 이동은 별도로 검증하며 [적용 현황](adoption-status.md)에 기록한다.
