# 생성기 사용 흐름

공통 흐름은 모델 준비 → 입력과 검증 → 생성 확인 → 진행 상태 → 이력과 결과다. 실행 중인 작업을 살펴보면서 새 입력을 작성할 수 있어야 하며, 이력 조회와 결과 선택은 생성 요청과 구분한다. 생성기별 기능·입력·제약의 사용설명은 해당 생성기 페이지에서 직접 제공한다.

- 입력의 필수 여부, 단위, 제약과 해결 가능한 오류를 해당 필드 가까이에 표시한다.
- 영상 입력은 선택 또는 복원한 실제 파일을 해당 입력 옆에서 재생해 확인할 수 있어야 한다. 파일명과 규격·검증 상태를 함께 표시하고, 브라우저 재생 실패는 명확히 알린다. 파일 교체·제거 시 이전 미리보기는 해제한다.
- 생성 전 확인은 입력을 보존하고, 취소는 요청을 접수하지 않는다. 중복 접수를 방지한다.
- 진행 상태는 현재 단계와 전체 예상치를 구분하고, 실제로 확인된 근거와 관측 범위만 표시한다. 마지막 조회 시각은 한 번 표시한다. 관측이나 추정 정보가 조회 시각과 30초 넘게 차이 나거나 비교할 수 없을 때만 해당 정보 옆에 별도 갱신 시각을 표시한다.
- 이력 선택, 결과 조회, 복원, 삭제는 서로 구분하고 대상과 비활성 사유를 표시한다. 선택 결과는 해당 이력 안에 표시하고 닫을 때 해당 이력 항목으로 초점을 복원한다. 진행 작업이나 직접 주소의 결과도 작업 ID로 이력과 연결한다.
- 선택 이력의 행동 버튼은 같은 행에서 일관된 크기로 배치한다. 검수 전송 결과나 오류 같은 가변 길이 안내는 버튼 행 아래에 놓아 다른 버튼의 크기를 바꾸지 않는다. 좁은 화면에서는 버튼을 줄바꿈한다.
- 같은 역할은 공용 컴포넌트를 사용한다. 서비스별 검증과 결과 유형은 해당 서비스가 소유한다.

## 건물 배치 가이드 선택

건물 생성기의 배치 가이드는 이미지와 주요 속성을 함께 볼 수 있는 카드 갤러리로 제공한다. 검색과 페이지 이동으로 목록을 좁히고, 각 카드에 썸네일과 배치 크기·지붕·층수·입구 방향 등 선택에 필요한 정보를 표시한다. 선택 상태를 구분하고 선택한 가이드를 참조 이미지에 적용하는 동작은 별도로 제공한다. 같은 유형의 선택 화면은 공용 카드 갤러리를 사용한다.

MiniMax 건물 생성기는 별도의 한국어 번역 기능을 제공하지 않는다. 헤르메스에서 해당 스킬을 사용할 때 한국어로 번역해 생성하도록 한다.

## 입력폼과 이력 페이지

독립 생성기 화면은 생성 입력과 이력 조회를 구분한다. 입력폼에서 이력으로 이동하는 조작과 해당 생성기가 지원하는 검수 페이지 링크를 제공하고, 이력에서 입력폼으로 돌아갈 수 있어야 한다. 현재 페이지는 이동하지 않는 표시로 구분해 작성 중인 입력을 실수로 새로고침하지 않게 한다.

- 여러 입력폼이 같은 작업 서비스를 사용하면 이력 화면을 공유한다. 서로 다른 서비스의 이력을 한 화면에서 선택할 수 있어도 목록, 결과 조회, 작업 제어와 삭제는 선택 서비스의 저장소와 명령에 한정한다.
- 이력을 새 탭에서 열거나 이동 전 초안을 보존해 작성 중인 프롬프트·설정·첨부가 유지되도록 한다. 보존에 실패하거나 보존 중 입력이 변경되면 이동을 멈추고 이유를 안내한다. 저장 작업의 입력 복원과 미접수 초안 복원은 구분한다.
- 이력과 입력폼 사이에서 대화 세션을 유지한다. 독립 입력폼의 기존 `?job=` 작업 링크는 해당 서비스의 독립 이력에서 같은 작업과 결과를 연다. 서비스 변경 시 이전 서비스의 작업 선택을 이어받지 않는다.
- 형식이 잘못된 작업 ID로 이력에 진입하면 다른 작업을 임의로 열지 않고 오류와 재선택 방법을 표시한다. 안내를 닫으면 이력 검색으로 초점을 옮기고 검색이 비활성화된 동안에는 이력 제목으로 옮긴다.
- 대화에 내장된 폼은 제안·접수 상태와 기존 이력 흐름을 보존한다. 독립 화면의 페이지 이동을 내장 폼에 강제하지 않는다.
- 임시 건물 후보 전송을 지원하는 생성기는 완료된 이력에서 `검수로 보내기`를 제공한다. 임시 후보 저장 결과와 보존 기한을 알리고 건물 검수 화면으로 연결한다. 후보가 만료되면 유효한 후보로 취급하지 않으며, 다시 검수하려면 이력에서 다시 보낼 수 있게 한다. 후보 전송을 지원하지 않는 생성기는 검수 화면으로 이동하는 경로와 후보 전송 기능을 구분해 표시한다.

## 이력의 입력 확인과 적용

입력을 다시 사용하는 흐름은 **이력 선택 → 입력 보기 → 이 입력으로 생성하기 → 생성폼 검토** 순서로 제공한다. 입력 보기에서는 선택한 작업 아래에 프롬프트와 설정을 읽기 전용으로 표시하고 첨부 이미지·영상은 썸네일로 표시한다. 첨부를 불러올 수 없으면 그 상태를 알린다.

- 입력 보기는 현재 생성폼을 변경하지 않는다. 조회 중·실패·재시도와 선택 변경 시 늦은 응답 처리를 제공한다.
- 입력 보기를 열면 프롬프트, 미디어와 입력 설정 상세를 바로 표시한다. 상세 설정을 보기 위해 별도의 접기 조작을 요구하지 않는다.
- 이미지·영상 미리보기가 없거나 손상됐을 때는 해당 미디어의 이름과 실패 상태를 표시한다. 브라우저에서 영상 코덱을 표시하지 못하면 안전하게 확인한 저장 원본의 첫 프레임으로 대체할 수 있으며, 원본 파일을 바꾸지 않는다. 확인되지 않은 외부 미디어 주소는 불러오지 않는다.
- 확인 영역의 `이 입력으로 생성하기`는 저장된 입력과 필요한 첨부를 생성폼에 적용한다. 적용 후 사용자가 생성 요청을 검토하고 명시적으로 접수하며, 버튼 자체는 생성을 시작하지 않는다.
- 지원하지 않거나 읽지 못한 필드·첨부가 있으면 현재 입력을 보존하고 사유와 재시도 방법을 알린다. 적용에 성공하면 원본 작업과 적용 결과를 알린다.
- 좁은 화면에서도 입력과 미디어를 확인할 수 있어야 한다. 결과 보기와 입력 보기는 각각 독립된 동작이다.

이 절은 목표 계약이다. 공용 이력 컴포넌트의 변경과 각 생성기의 파일 복원·오류 처리·초점 이동은 별도로 검증하며 [적용 현황](adoption-status.md)에 기록한다.
