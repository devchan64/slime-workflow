# 헤르메스 기반 3D 전투 애니메이션 설계

상태: 구상 및 조사 단계 · 2026-11-22

## 목표

기본 캐릭터의 [8방향 참조](../baseline/player/default/default-eight-directions-v1.png)를 바탕으로 리깅된 3D 캐릭터를 만들고, 전투 모션과 무기 궤적을 생성한다. 헤르메스가 사용자의 텍스트 요청을 해석해 키프레임 편집기를 조작하고, 결과를 확인하며 수정한다. 최종 산출물은 같은 캐릭터의 외형을 유지하는 방향별 2D 게임 스프라이트다.

모션을 수동 보정할 인력이 없으므로 사람이 관절이나 키프레임을 직접 편집하는 것을 필수 단계로 두지 않는다. 사용자는 텍스트로 의도를 전달하고 결과를 확인할 수 있다. 자동 검사는 실패 후보를 걸러내지만 시각적 완성도를 보장하지 않는다.

## 전체 흐름

1. 8방향 시트와 생성 이력을 입력으로 사용한다. 시트를 개별 방향으로 분리하고 방향·크기·정렬을 기록한다. 기존 기준 기록에 표시된 방향 및 비율의 미검수 사항을 유지한다.
2. 상업적 사용 조건을 확인한 3D 생성기로 캐릭터 메시를 만들고 자동 리깅·스키닝한다. 관절 계층, 손과 무기 부착점, 내보내기 형식을 검증한다.
3. 초기 전투 모션을 생성하거나 사용 권한이 확인된 기존 모션을 불러온다. Kimodo와 AnimationGPT는 후보이며 특정 모델을 필수로 지정하지 않는다.
4. 무기의 손잡이와 칼끝을 정의하고 몸 모션에 맞는 무기 트랙을 생성한다. 헤르메스는 사용자의 요청과 현재 동작을 바탕으로 몸·무기·타이밍을 함께 수정한다.
5. 편집 결과를 여러 시점에서 렌더하고 연속 프레임, 무기 궤적과 자동 검사 결과를 헤르메스에 전달한다. 헤르메스는 결과를 해석하고 필요하면 수정·재검사한다.
6. 승인할 수 있는 결과를 고정 카메라로 8방향 렌더링하고, 캐릭터 외형 참조를 사용해 2D로 변환한 뒤 프레임과 기준점을 유지한 스프라이트를 만든다.

## 헤르메스와 편집기의 경계

헤르메스는 요청 해석, 도구 선택, 편집 지시와 결과 판단을 담당하는 조정자다. 3D 생성·리깅·IK·렌더는 각각의 도구가 수행한다. 텍스트의 모호한 방향은 캐릭터 기준 좌표와 카메라 기준 좌표를 구분하고, 해석한 설정을 기록한다.

편집기는 GUI와 함께 에이전트가 호출할 수 있는 구조화된 명령을 제공하도록 설계한다.

- 장면, 리그, 관절 계층, 무기와 프레임 범위 조회
- 특정 프레임 또는 구간의 관절·루트·무기 변환 및 키프레임 조회와 변경
- 무기 손잡이 목표에 대한 주 손 IK와 양손 무기의 보조 손 제약
- 키프레임 보간, 타이밍 변경, 변경 전후 비교와 되돌리기
- 프레임·연속 이미지·영상 및 다방향 렌더, 칼끝 궤적 시각화
- 자동 검사 실행과 측정 결과·실패 원인 반환

명령은 대상 장면과 버전, 좌표계, 단위, 프레임 또는 시간, 수정 범위를 명시한다. 편집 전 원본을 보존하고 변경 이력, 사용한 텍스트, 도구·모델 버전, 입력·출력 식별자를 기록한다. 잘못된 입력이나 검사 실패를 성공으로 취급하지 않는다.

## 무기와 모션 표현

무기는 손잡이와 칼끝의 로컬 좌표를 가진 별도 오브젝트로 다룬다. 무기 트랙은 시간별 위치와 회전을 저장하고 칼끝 경로는 이 변환으로부터 계산한다. 무기 종류, 파지 손, 손잡이 오프셋, 보조 손 위치, 공격 활성 구간을 기록한다. 손목 위치만으로 칼날 방향이 결정된다고 가정하지 않는다.

초기 궤적은 기존 손 동작에서 추정하거나 텍스트를 준비·휘두름·타격·회수의 목표로 해석해 생성할 수 있다. 헤르메스가 예를 들어 “베는 각도를 수평에 가깝게 하고 회수는 유지”라는 지시를 받으면 영향 구간과 좌표계를 정한 뒤 무기와 몸을 함께 수정한다. 손의 도달 범위, 양손 파지와 몸통 자세에 따라 무기 궤적 및 몸 모션을 함께 조정해야 한다.

게임 판정에 필요한 타격 활성 프레임과 궤적은 렌더 결과와 같은 시간 기준으로 내보낸다. 빠른 움직임은 프레임 사이의 칼날 이동도 고려한다. 판정의 구체적 형식은 게임 엔진과 별도로 합의한다.

## 자동 검증과 반복

다음 지표를 프레임별·구간별로 기록하고 실패 후보의 재생성 또는 수정을 시도한다. 임계값은 시험 결과로 정하며 미정 상태에서 품질 통과로 표시하지 않는다.

- 무기와 손잡이의 위치·방향 오차, 양손 파지 오차
- 무기·손·팔의 급격한 이동과 회전, 칼끝 속도 및 불연속
- 무기와 신체의 관통, 관절 도달 한계, 발 접지와 미끄러짐
- 8방향의 실루엣·가림, 타격 시점과 프레임 누락
- 2D 변환 후 얼굴·의상·무기 형태, 파지와 프레임 간 일관성

검사는 유효한 수치, 시각적 자연스러움, 텍스트 의도 충족을 별도로 다룬다. 자동 검사만으로 자연스러운 검술이나 최종 스프라이트 품질을 보장하지 않는다. 반복 횟수와 실패 사유를 기록하고, 성공 조건을 충족하지 못하면 실패로 보고한다.

## 현재 상태와 후보

- [헤르메스](../generators/hermes_agent/README.md)는 격리된 파일·터미널 도구와 기존 생성기 제안·조회 기능을 제공한다. 현재 3D 편집기, 무기 트랙 조작 및 위의 확인·수정 반복은 구현 또는 검증된 것으로 간주하지 않는다.
- [AnimationGPT 실험](../workflow/domains/animationgpt/README.md)은 22관절 좌표를 반환했지만 무기 형상·궤적이 없고 시각 품질과 서비스 연결은 미검증이다. Kimodo와 AnimationGPT는 모두 선택 가능한 초기 모션 후보이며 다른 도구도 평가한다.
- [관절 비율과 포즈 출력 실험](../workflow/domains/joint_proportions/README.md)은 GUI·게이트웨이에 연결되지 않았고 무기와 가림을 출력하지 않는다.
- [TRELLIS](https://github.com/microsoft/TRELLIS)는 다중 이미지 입력을 지원하고 [UniRig](https://github.com/VAST-AI-Research/UniRig)는 자동 리깅 후보다. 8방향 정확도, 손·스키닝, 실제 실행 환경 및 모든 의존성의 상업적 이용 조건은 미검증이다. 도구의 MIT 표기만으로 전체 파이프라인을 승인하지 않는다.
- [Quaternius 기본 캐릭터](https://quaternius.com/packs/universalbasecharacters.html)와 [전투 모션](https://quaternius.com/packs/universalanimationlibrary2.html)은 제작자가 CC0로 제공하는 비교 시험 후보다. 참조 이미지로 생성한 결과가 아니며 무기 트랙 포함 여부와 자동 적용 품질은 파일 검사 전 미확인이다.

## 단계별 검증

1. **3D 생성 가능성:** 8방향 기준으로 메시와 리그를 생성하고 각 방향의 체형·실루엣, 스키닝, 손 부착점을 확인한다. 생성기·가중치·의존성의 라이선스와 장비 지원을 기록한다.
2. **편집 반복 최소 시험:** 리깅된 캐릭터, 한손검, 가로 베기 한 동작으로 텍스트 요청 → 몸·무기 수정 → 다방향 렌더·검사 → 재수정 경로를 검증한다. 생성 캐릭터가 아직 준비되지 않으면 권리가 확인된 임시 캐릭터를 사용할 수 있으며 이는 3D 생성 성공을 뜻하지 않는다.
3. **2D 출력 시험:** 같은 동작을 8방향으로 렌더해 외형 변환을 수행하고 칼날·파지·접지·프레임 일관성을 확인한다.
4. **확장:** 대각 베기, 찌르기, 양손 무기와 콤보로 확대하고 다른 모션 생성기·무기를 비교한다.

각 단계는 실제 결과물과 검증 범위를 기록한다. 3D 출력 성공, 자동 리깅 성공, 자연스러운 전투 모션, 상업적 사용 가능 여부와 최종 스프라이트 품질은 서로 다른 판정이다.
