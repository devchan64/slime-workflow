# 생성기 구성 가이드

모든 현행·신규 생성기는 생성 기능, 해당 생성기 페이지, 생성기별 변경 기록 문서를 한 세트로 관리한다. 생성기를 추가하거나 기능·설정·모델·사용 방법을 변경할 때 페이지와 변경 기록도 함께 검토하고 필요한 내용을 같은 변경에 반영한다. 폐기된 생성기를 이 규칙 때문에 복원하지 않는다.

## 폴더 구조

신규 생성기는 안정적인 생성기 식별자별 폴더를 사용한다. 동일 모델을 공유하더라도 사용자에게 독립된 생성기로 제공되는 경우 각각 페이지와 변경 기록을 둔다.

```text
generators/<generator-id>/
  README.md                 목적·실행 방법·페이지와 의존성 안내
  CHANGELOG.md              해당 생성기의 변경 기록 원본
  page/                     해당 생성기 전용 페이지 구성과 표시 자원
  ...                       생성기 전용 실행 코드·설정
```




## 변경 기록과 페이지 표시

- `CHANGELOG.md`는 Git으로 관리하는 유일한 변경 기록 원본이다. 생성 결과·로그·작업별 생성 이력과 구분한다. 과거 이력을 추정해 채우지 않으며 확인 가능한 기록부터 시작한다.
- 최신 항목을 위에 두고 날짜(`YYYY-MM-DD`)와 변경 내용을 한국어로 기록한다. 사용자에게 영향을 주는 기능·기본값·모델·호환성·제한사항을 구체적으로 적고, 필요한 경우 관련 문서나 변경 근거를 연결한다. 비밀값·개인 경로·내부 로그는 기록하지 않는다.
- 해당 생성기 페이지에 `변경 기록` 영역을 제공하고 해당 문서의 내용을 직접 표시한다. 페이지마다 복사한 문자열이 아니라 원본 문서를 읽는 공용 표시 기능을 사용한다. 페이지에서 내용을 확인할 수 있어야 하므로 파일 링크만으로 대체하지 않는다.
- 문서가 없거나 읽을 수 없으면 빈 기록처럼 보이지 않도록 오류와 조치 방법을 표시한다. 파일 경로는 생성기별 명시적 등록 또는 고정 경로로 제한하며 사용자 입력을 파일 경로로 사용하지 않는다. Markdown을 표시할 때 스크립트 등 실행 가능한 내용은 허용하지 않는다.

## 적용 및 검증

신규 생성기는 세 구성요소를 함께 구현하고 관리 메뉴에서 페이지로 접근할 수 있어야 한다. 기존 생성기는 실제 페이지·문서·연결 상태를 확인해 빠진 부분을 전환한다. 변경 기록을 새로 만들 때 확인 가능한 최초 기록과 이후 변경을 적는다.

각 생성기에 대해 페이지에서 올바른 문서의 전체 내용을 읽을 수 있는지, 문서 변경이 복제 없이 표시되는지, 누락 시 안내가 나오는지 확인한다. 공용 표시 기능은 여러 생성기의 문서 분리와 허용되지 않은 경로 거절도 검증한다. 관리도구에 합성된 실제 페이지에서 표시를 확인하고, 기존 URL·CLI·생성 및 이력 계약이 유지되는지 영향 범위에 맞게 검증한다. 문서 규칙, 공용 기능, 개별 생성기 적용 여부와 브라우저 검증 여부는 각각 구분해 보고한다.
