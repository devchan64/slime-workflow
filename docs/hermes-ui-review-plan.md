# 헤르메스 운영 대화 UI 검수와 개선 계획

2026-11-21 로컬 운영 화면을 Chrome 임시 프로필로 열어 새 대화, 기존 세션 선택, 도구 패널 열기, 대기열 열기, 좁은 화면에서 세션 접기를 확인했다. 개선 순서는 대화 공간 확보 → 요청 작성 간소화 → 결과의 다음 단계 연결이다. 실행·검증 계약은 [워크플로우 설계](hermes-generator-workflow-design.md)를 따른다.

## 관찰 결과

| 검수 장면 | 관찰 | 사용자에게 미치는 영향 |
|---|---|---|
| 기존 세션, 1366×813 | 대화 영역 높이가 641px였다. 대기열을 열면 7개 필터가 나타나고 대화 영역이 329px로 줄었다. 작성창은 계속 보였다. | 대기열을 참고하면서 앞선 대화를 읽을 공간이 절반 가까이 줄어든다. |
| 같은 세션, 390×844 | 가로 넘침은 없었다. 상단 도구 영역이 197px였다. 세션 목록을 접으면 대화 높이가 432px에서 567px로 늘지만 상단 높이는 같았다. | 목록 접기와 별도로 상단 동작을 줄여야 대화를 더 읽을 수 있다. |
| 새 대화에서 도구 탐색 | 검색창으로 포커스가 이동했다. 기본 패널에 검색 모드 전환과 도구 선택을 포함해 버튼 39개가 있었다. | 도구를 모르는 사용자가 첫 요청을 쓰기 전에 많은 선택지를 훑게 된다. |
| 기존 생성 이력 응답 | 대화 안에서 결과 표 1개를 확인했다. 코드상 구조화된 이력은 공통 표를 쓰고 요약만 있는 이력은 텍스트로 표시한다. | 표를 유지하면서 결과의 출처와 다음 작업에서 쓸 수 있는 항목을 드러내는 편이 좋다. |

기존 세션과 결과를 읽어 확인했다. 요청 전송, 폼 저장·복사, 우선순위 변경, 작업 실행과 결과 체인 완주는 이번 실측 범위 밖이다.

## 구현 순서와 완료 기준

1. **대화와 대기열을 함께 읽기.** [대화 셸](../gui/app.jsx)에서 좁은 화면의 상단을 세션 전환·제목·도구 메뉴 한 줄 중심으로 정리한다. [대기열](../gui/QueuePanel.jsx)은 상태와 최근 작업을 먼저 보여주고 날짜·작업 ID 등 상세 필터는 펼쳐서 사용한다. 완료 기준은 같은 세션의 390×844 화면에서 상단 높이 100px 이하, 1366×813에서 대기열 기본 보기와 대화를 함께 열 때 대화 영역 480px 이상이다. 세션 접기·너비 조절, 작성창, 상세 필터는 키보드로 접근할 수 있어야 한다.
2. **도구 선택부터 폼 초안까지 이어 쓰기.** 작성창 옆에 도구 검색 진입점을 두고 생성기와 조회·검수 도구를 이름이나 기능으로 함께 찾게 한다. 도구를 고르면 선택 이름과 제거 동작을 표시하고 작성 중인 문장을 보존한다. [폼 목록](../gui/FormLibrary.jsx)에서 기존 입력을 복사해 같은 세션의 초안으로 편집한다. 완료 기준은 빈 대화에서 마우스 없이 도구 선택·해제 후 처음 입력한 문장이 유지되고, 복사본을 수정한 뒤 원본 값과 버전을 다시 확인할 수 있는 것이다. 초안 편집 중 작업 접수는 0건이어야 한다.
3. **결과에서 다음 단계 정의하기.** [워크플로우 결과](../gui/WorkflowResults.jsx)에서 선택한 결과 항목에 호환되는 다음 단계 입력을 표시한다. 등록된 입출력 계약을 사용해 원본 실행·단계·결과 항목과 대상 입력을 폼에 함께 보여준다. 대기열에서는 의존 대기, 실행 가능, 실패 원인을 구별한다. 완료 기준은 격리된 번역→이미지 예제에서 번역 결과를 다음 프롬프트에 재입력 없이 연결하고, 새로고침 후에도 연결이 유지되며, 선행 실패 시 후속 생성 접수가 0건인 것이다.

각 패치에서 같은 세션 데이터와 두 화면 크기로 다시 측정한다. 검색은 생성기와 관리 도구 각각 한 건, 결과는 정상·빈 결과·조회 실패를 포함한다. 접수와 우선순위 변경은 격리 데이터로 검증하고 운영 화면에서는 조회와 이전 대화 복귀를 확인한다.
