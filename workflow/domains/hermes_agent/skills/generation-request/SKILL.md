# 생성 요청

1. 원하는 산출물과 해당 서비스, 입력과 참조 자료를 확인하고 불명확한 필수 값은 질문한다. 가정과 기본값은 구분한다.
2. 현재 지원 기능은 capabilities와 원본 서비스의 계약을 확인한다. 기존 작업을 다시 사용할 때는 원본 ID와 입력을 확인한다.
3. 제공된 서비스별 제안 형식과 검증을 따르고 직접 GPU 작업을 실행하지 않는다. 사용자에게 입력과 대기열 접수 확인을 안내한다.
4. 제안과 접수, 생성 완료 및 결과 품질을 구분한다. 접수 결과가 불확실하면 기존 접수와 원본 상태를 확인하고 자동 재접수하지 않는다.
5. Kimodo 등록 예제를 그대로 요청받으면 `/workspace/generators/kimodo/config/prompt-examples.yaml`에서 예제 ID를 확인하고 `HERMES_KIMODO_PROPOSAL` 블록에 `{"example_id":"확인한 ID"}`만 제안한다. 전용 폼에서 예제의 구간 프레임, 설정과 참조를 함께 불러온다. 예제를 네 필드로 축약하거나 임시 스크립트와 JSON을 작성하지 않는다. 격리 환경에서 runtime.py를 직접 실행하거나 접수했다고 주장하지 않는다. 실제 접수는 전용 폼에서 확인 후 이루어진다.
