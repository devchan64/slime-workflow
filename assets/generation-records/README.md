# 생성 에셋 관리기록

재현을 위한 관리 원본이다. `index.yaml`에서 관리번호별 최신 이력으로 연결한다. 최종 이미지 원본은 프론트엔드, 생성 이력·재현 증거는 워크플로우가 소유한다. 후보 보존은 에셋 채택을 뜻하지 않는다.

## 식별과 이력

- `managementId`는 프론트엔드 `image-assets.yaml`의 동일 에셋 `managementId`와 **완전히 같아야 한다**. 전송·파일 이동 시 새 번호를 발급하지 않는다. animationId/frameId/실행 날짜/해시는 관리번호를 대신하지 않는다.
- 기존 프론트엔드 번호는 그대로 사용한다. 새 후보에는 먼저 번호를 부여하고 채택된 동일 파일에 그 번호를 전달한다. 아직 미전달이면 `frontend: null`이다.
- 같은 논리 에셋 수정은 같은 관리번호에 `revision-0002`처럼 새 이력을 추가한다. 이전 기록·해시를 덮어쓰지 않는다. 별도 보관하는 독립 버전·해상도·포맷에는 새 관리번호를 부여하고 원본 번호·이력으로 연결한다.
- 재패킹된 통합 시트는 입력 프레임·기존 시트와 별도 산출물이므로 새 번호를 부여한다. 걷기 4×4 두 장 각각에 번호가 필요하다. 프레임 원본과 시트의 번호를 공유하지 않고 구성 관계로 연결한다.

## 보존 계약

각 이력은 관리번호·이력 버전·시간·상태·이전 이력·생성 실행 연결, 모델/revision·라이브러리 버전·도구 소스, 기준/옵션 프롬프트 버전·해시·순서, 입력 이미지 원본 또는 불변 자산과 크롭/변환, 실제 출력·해시, 후처리 배율·이동·앵커·패킹, 검수·채택 판단을 기록한다. 원본 result.json 등 도구 산출물은 재현 증거로 유지한다.

비공개 프롬프트 원문은 비공개 저장소에 보관하고 기록에는 저장소·경로·버전·해시·치환값을 남긴다. 해시만 남기고 원문을 지우면 안 된다. 변경 시 과거 버전도 유지한다. 민감한 지시를 공개 기록에 복사하지 않는다.

입력·출력·로그·실행 소스 보존이 필요한 실험은 이 디렉터리의 이력별 `artifacts/`로 승격한다. 재사용 자산 또는 최종 프론트엔드 에셋을 불변 해시로 찾을 수 있으면 참조를 사용한다. 재현에 필요한 시점 스냅샷은 단순 중복 에셋 등록과 구분한다. `.tmp` 정리 전 접근·해시 검증을 완료한다. 모델 가중치는 `.model`에만 둔다.

## 프론트엔드 전달 검증

1. 후보 검수와 선택을 완료하고 해당 이력의 산출물 해시를 고정한다.
2. 프론트엔드 이미지 목록에 같은 관리번호와 전달 경로를 등록한다.
3. 관리번호의 정확한 일치, 대상 파일 해시, 경로와 파일 존재를 확인한다. 누락·중복·불일치는 전달 완료 처리하지 않는다.
4. 워크플로우 새 이력에 전달 경로·해시·상태를 남기고 인덱스를 갱신한다. 재생 메타데이터와 시트 구성은 별도 검증한다.

현재 5개 기존 프론트엔드 에셋과 Qwen 후보 3개를 등록했다. 기존 에셋은 소급 연결이며 수집되지 않은 생성 정보 때문에 `partial`로 표시한다. Qwen 후보는 입력·설정·실행 소스·출력을 보존했다. 관리번호 존재만으로 재현 완료를 의미하지 않는다. 이미지젠의 모델/seed 미노출은 명시하고 미확인값을 추정하지 않는다. 목표는 제작 절차의 재실행 가능성이지 모든 생성기의 픽셀 동일성 보장이 아니다.
