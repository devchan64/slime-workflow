# 공통 프롬프트 관리

화풍과 캐릭터 외관의 재사용 원문을 YAML로 관리한다. 이 문서는 선택·조합·버전 관리 기준이며 생성기가 자동으로 적용하는 설정은 아니다. 실행 시 선택한 버전과 실제 전달 원문을 기록한다.

## 조합 방법

1. 과제에서 가장 중요한 조건을 먼저 쓴다. 비율 실험이면 5등신 등 비율 조건을 먼저 둔다.
2. 캐릭터 외관 공통 원문과 캐릭터별 외형·복장을 지정한다.
3. 화풍 공통 원문을 한 번 추가한다.
4. 동작·카메라·방향 수·배치·배경·해상도를 짧게 지정한다.

완성형 과거 프롬프트에 두 블록을 무조건 추가하지 않는다. 중복·충돌을 확인한다. 이미지 무참조 요청은 텍스트만 전달하며 참조 목록을 비운다. 원문 키는 두 YAML 모두 `prompt`이다. 표시된 단어 수는 개별 블록 기준이며 최종 입력은 모든 치환·조합 이후 다시 센다.

## 버전 관리

- `prompt_id`는 역할 식별자, `version`은 의미 버전이다. 최초 원본은 `*-v1.yaml`이다.
- 원문을 바꾸면 새 파일로 저장한다. 예: `art-style-v1.1.0.yaml`. 기존 파일을 덮어써 과거 실행을 바꾸지 않는다.
- 방향성·역할 변경은 주 버전, 표현·규칙 추가는 부 버전, 의미 없는 오탈자 수정은 패치 버전을 올린다. 새 버전의 상태는 검증 전부터 시작한다.
- 새 버전에는 원문·공백 기준 단어 수·UTF-8 원문의 SHA-256·변경 이유를 기록하고 이 색인과 변경 이력을 갱신한다.
- 실행 기록에는 사용한 공통 버전·참조 이미지 역할·실제 최종 프롬프트·단어 수·해시를 남긴다. 이미지별 YAML은 이미지와 함께 보존한다.
- 생성 완료와 채택을 구분한다. 사용자가 승인하기 전에는 기본 버전으로 자동 승격하지 않는다.
- 원본은 Git 추적 대상이다. 버전 파일 작성과 Git 커밋은 별개이며 커밋은 요청 시 수행한다.

기존 [art-style.yaml](../art-style.yaml)은 대상·출력별 종합 기준 및 기존 소비자의 연결 원본으로 보존한다. 이 분리 문서를 추가한 것만으로 기존 소비 코드를 전환하지 않는다.
