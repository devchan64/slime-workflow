# 캐릭터 스탠딩 시트 제작 절차

Codex 내장 `image_gen`으로 승인된 **4방향 2×2 베이스라인 시트 전체를 참조하여 방향별 4×1 제자리 스탠딩 시트 총 4장**를 생성한다. 출력은 4방향×방향당 4프레임이다. 생성 후보 검수와 기존 런타임 에셋 교체는 구분한다.

## 입력 기준

- 현재 참조 원본: `slime-frontend/src/assets/characters/default/baseline/character-default-white-shirt-four-directions-v2.png`.
- 같은 이름의 sidecar YAML에서 실제 크기·셀 좌표·출처를 확인하고 실행 시 파일 해시를 기록한다.
- 베이스라인 시트 전체를 하나의 참조 이미지로 전달한다. 단일 방향을 잘라 유일한 외형 참조로 사용하거나 기존 스탠딩 결과를 연쇄 참조하지 않는다.
- 외형·복장·렌더링 스타일과 신체 비율은 승인된 베이스라인을 기준으로 유지한다. 사용자가 채택한 명시적 5등신 표현을 유지한다. 추가 체형 보정 문구를 임의로 누적하지 않는다.

## 입력과 출력의 방향 대응

매 호출마다 같은 2×2 전체 베이스라인을 전달하되 한 방향만 생성한다. 총 4회 호출하여 4장을 만든다. 각 시트는 4열×1행이며 왼쪽부터 중립·들숨·최대 들숨·날숨 순서다.

| 방향 | 참조 셀 | 출력 파일 |
|---|---|---|
| down_left | 좌하, 앞면·측면 | standing-down-left.png |
| down_right | 우하, 앞면·측면 | standing-down-right.png |
| up_left | 좌상, 뒷면·측면 | standing-up-left.png |
| up_right | 우상, 뒷면·측면 | standing-up-right.png |

한 시트 안에서는 몸·얼굴 방향과 카메라를 고정한다. 양발 접지선·가로 기준점은 유지하고 호흡만 바꾼다. 프레임당 400ms, 주기 1.6초로 검수한다. 첫 프레임과 마지막 프레임의 인물·복장·비율이 이어지는지 확인한다.

## 실행 프롬프트

관리 원본은 `prompts/character-default-standing-v4.yaml`이다. 2×2 전체 참조와 짧은 프롬프트에 명시적 5등신 표현을 사용하는 방식을 채택했다. 사용자 요청에 따라 이 제작 프롬프트를 워크플로우에서 관리한다. 공통 화풍 블록이나 장문의 금지사항을 자동 결합하지 않는다. 프롬프트 채택은 실험 이미지 채택과 별개이며, 최근 결과의 행 순서·행 내부 방향 혼합은 미해결 검수 항목이다.

## 생성과 실행 기록

1. 한국 시간 `.tmp/YYYY-MM-DD_HH-mm-ss/`에 참조 사본·실험 프롬프트·실행 기록을 준비한다. 관리 원본의 `prompt_template`에 선택한 `directions[directionId].direction_instruction`을 치환한다. 정의된 네 방향만 허용하고 누락·미지원 방향은 실패시킨다. 치환된 프롬프트와 버전·해시를 기록한다. 변형 프롬프트는 해당 실행 폴더에서만 수정한다.
2. 참조 이미지를 확인한 뒤 내장 `image_gen`에 2×2 시트 전체와 실행 프롬프트를 전달하여 방향마다 4×1 시트 한 장씩 총 네 장을 생성한다. 다른 방향 결과를 외형 참조로 연쇄 사용하지 않는다. 걷기용 MoMask 포즈 맵이나 Qwen 단일 프레임 실행기를 필수 입력으로 사용하지 않는다.
3. 전신이 각 셀 안에 들어가고 프레임 간 외형·카메라·크기·발 기준 위치가 일관되도록 요청한다. 바닥·배경 광채·문자·테두리를 넣지 않는다.
4. 생성 원본을 실행 폴더에 복사한다. 도구·참조 경로와 해시·프롬프트 원문과 해시·요청 크기·실제 크기·셀 순서·원본 출력 경로를 기록한다. 도구의 내부 모델명은 추측하지 않는다.
5. 생성 프롬프트와 별도로 납품 목표 기록에 셀 크기·행열 수·몸체 높이·anchor를 명시하고 `시트 너비=셀 너비×열 수`, `시트 높이=셀 높이×행 수`로 납품 크기를 계산한다. 납품 목표는 512×512 셀, 방향별 4×1 배열, 2048×512 PNG 4장, 몸체 높이 384px, 셀 로컬 접지 anchor (256,448)이다. 현재 단축 프롬프트에는 픽셀 수치·anchor를 추가하지 않는다. 원본 생성 크기와 후처리 납품 목표를 혼동하지 않는다.
6. 실제 크기를 검사한다. 내장 도구에는 별도 크기 인자가 없으므로 프롬프트 요청만으로 크기가 보장되지 않는다. 1254×1254 등 계약과 다른 결과는 원본 후보로 기록하고 그대로 정식 시트로 전달하지 않는다. 실제 인물 영역을 확인하여 비율을 유지하는 균일 배율과 평행이동으로 정수 셀에 재배치한 뒤 검수한다. 해상도 부족·셀 침범·잘린 신체는 기록하며 단순 확대를 고해상도 생성으로 간주하지 않는다. 실험 프롬프트는 `.tmp`에 둔다.

## 검수와 등록

- 각 파일에 같은 방향의 전신 4개가 있는지, 네 파일 전체가 4방향·16프레임인지 확인한다. 파일 사이의 캐릭터 외형·크기·카메라 차이도 검수한다.
- 네 방향 모두 베이스라인과 비교하여 얼굴·머리·복장·체형의 일관성을 확인한다.
- 같은 방향 참조와 결과를 전신 높이가 같도록 균일 배율로 겹쳐 머리/전신, 어깨폭/전신, 몸통/전신, 다리/전신 비율을 확인한다. 셀에 맞추기 위한 머리 확대·다리 단축·비균일 스케일을 허용하지 않는다. 프레임마다 키를 자동 정규화하면 호흡까지 상쇄되므로 방향별 고정 배율과 공통 접지점을 사용한다.
- 방향별 0→1→2→3→0 루프에서 발 미끄러짐·불필요한 이동·크기 변화·팔다리 깨짐을 확인한다. 대기 동작이 걷기로 변하지 않아야 한다.
- 알파 채널 존재뿐 아니라 배경에 불필요한 반투명 색이나 광채가 남았는지 확인한다.
- 사용자 채택 후에만 새 버전으로 프론트엔드에 등록한다. 실제 이미지 크기로 셀 좌표·방향별 프레임·발 anchor·재생 시간을 기록하고 런타임 채택은 별도로 처리한다.

현재 채택본은 `slime-frontend/src/assets/characters/default/standing-v4/`의 방향별 PNG 네 장이다. 생성 출처는 `2026-09-20_21-53-32`, 앵커 검수 출처는 `2026-09-20_22-22-51`이다. 기존 standing-v3 시트는 폐기했다. 실제 2172×724 원본과 543×724 셀을 유지하는 사용자 채택 예외이며, 2048×512 납품 목표로 비균일 축소하지 않는다. 방향마다 4개 고유 프레임을 재생한다.

## 양발 앵커 검수 도구

```bash
python3 generators/animation/review_standing_anchors.py --sheets-dir .tmp/2026-09-20_21-53-32
```

Pillow가 필요하다. 이미지 생성·추론이 아닌 기존 PNG의 좌표 분석 도구다. 새 `.tmp/한국시간` 폴더에 원본 사본, 공통 애니메이션 메타데이터, 시트 해시·접지점 기록, `contacts.json`, `anchor-overview.png`, `preview.html`, 단계별 로그를 만든다. 네 방향 입력은 같은 크기의 RGBA PNG여야 하며 너비가 4로 나누어져야 한다.

밝은 무채색 신발 두 영역의 앞꿈치·뒤꿈치를 잇는 중심을 각 발의 기준점으로 추정하여 `anchor.x=(left.x+right.x)/2`, `anchor.y=(left.y+right.y)/2`로 지정한다. 화면 좌우 기준이며 해부학적 좌우 발 구분과 무관하다. 앞꿈치·뒤꿈치 후보는 신발 하단 외곽선 양끝에서 너비 12% 안쪽 점이며 반드시 육안 검수한다. 밑창 최하단이 아닌 앞뒤 중심을 사용한다. 신발 둘을 분리할 수 없으면 임의 셀 중앙으로 대체하지 않고 실패한다. 자동 검출은 현재 흰 운동화용이며 다른 색·형태에는 검수 좌표를 지정한다.

검수 페이지는 방향·프레임 선택, 400ms 반복 재생, 앵커 정렬 전후 비교, 접지점·중간점 표시를 제공한다. 일시정지하고 화면 좌/우 발의 앞꿈치/뒤꿈치를 선택한 뒤 클릭하여 끝점을 수정하고 JSON을 저장한다. 저장한 파일을 `--contacts-file /경로/contacts.json`으로 전달해 새 검수 폴더와 메타데이터를 만든다. 전체 16프레임의 네 끝점·좌표 범위·중복 키를 검증한다.

정식 전달 시 PNG 네 장과 `idle-v4.animation.json`, `source.json`을 함께 전달한다. 런타임은 direction→texture 매핑 후 해당 방향 클립을 선택한다. rect는 각 시트의 로컬 좌표이며 서로 다른 방향의 이미지를 같은 텍스처로 취급하지 않는다. 기본 캐릭터 크기는 모든 프레임의 불투명 몸체 높이 평균을 기준으로 한 고정 배율을 사용한다. 각 프레임의 키를 별도로 정규화하지 않는다.

## 로컬 검증 서버

```bash
python3 tools/review/serve.py --root .tmp/2026-09-20_22-22-51 --port 8765
```

`http://127.0.0.1:8765/`에서 앵커 검수 페이지를 연다. 선택한 개별 검수 폴더만 읽기 전용으로 제공하며 디렉터리 목록·상위 경로·숨김 파일·프롬프트·로그·모델 캐시는 제공하지 않는다. 외부 접속용 바인딩은 지원하지 않는다. 실행 로그는 별도 `.tmp/한국시간/review-server.log`에 남기며 5초마다 요청 수와 로그 크기를 출력한다. 종료는 실행 터미널에서 Ctrl+C다. 포트가 사용 중이면 자동으로 다른 포트를 선택하지 않고 실패한다.

### 프레임별 정수 좌표 편집·저장

이전/다음 프레임 버튼과 슬라이더로 이동하면 자동 일시정지한다. 각 프레임의 앵커는 독립적이며 수정값을 다른 프레임으로 자동 전파하지 않는다. 선택한 점 또는 최종 앵커를 X/Y ±1px 버튼으로 이동할 수 있다. 최종 앵커 이동은 해당 프레임의 두 발 기준점을 함께 평행이동한다. 좌표와 평균 앵커는 0.5 올림으로 정수 반올림한다.

저장은 `character-default-standing-v4-anchor-review.json`이다. schemaVersion, artifactType, 설명, 좌표 모드, 애니메이션 ID·버전, 시트 파일·방향·SHA-256, 프레임별 셀 영역·점·앵커를 포함한다. 셀 왼쪽 위 (0,0), x 오른쪽·y 아래 원본 픽셀 단위다. `toe-heel`은 발별 앞꿈치/뒤꿈치 네 점, `foot-centers`는 사용자 지정 두 발 중심이다. 서로 자동 변환하거나 끝점을 임의 복원하지 않는다.

```bash
python3 generators/animation/review_standing_anchors.py --sheets-dir .tmp/2026-09-20_21-53-32 --contacts-file /경로/character-default-standing-v4-anchor-review.json --coordinate-mode foot-centers
```

기본 입력은 설명 포함 review 형식이며 스키마·중복 키·16프레임·정수 좌표·셀 영역·앵커 계산·원본 해시를 검증한다. 이전 좌표만 있는 파일은 명시적인 `--contacts-format legacy`로만 읽는다. 현재 채택 좌표는 `contacts (1).json`의 프레임별 네 끝점을 정수화한 결과다. 이전 방향별 보정량 전파 결과를 대체하며 프레임별 값을 독립 적용한다. 원본 입력과 설명 포함 좌표 산출물은 `.tmp/2026-09-20_22-22-51/`에 보존한다.
