# 캐릭터 스탠딩 시트 제작 절차

Codex 내장 `image_gen`으로 승인된 **4방향 2×2 베이스라인 시트 전체를 참조하여 4×4 제자리 스탠딩 시트**를 생성한다. 출력은 4방향×방향당 4프레임이다. 생성 후보 검수와 기존 런타임 에셋 교체는 구분한다.

## 입력 기준

- 현재 참조 원본: `slime-frontend/src/assets/characters/default/baseline/character-default-white-shirt-four-directions-v2.png`.
- 같은 이름의 sidecar YAML에서 실제 크기·셀 좌표·출처를 확인하고 실행 시 파일 해시를 기록한다.
- 베이스라인 시트 전체를 하나의 참조 이미지로 전달한다. 단일 방향을 잘라 유일한 외형 참조로 사용하거나 기존 스탠딩 결과를 연쇄 참조하지 않는다.
- 외형·복장·렌더링 스타일과 신체 비율은 승인된 베이스라인을 기준으로 유지한다. 사용자가 채택한 명시적 5등신 표현을 유지한다. 추가 체형 보정 문구를 임의로 누적하지 않는다.

## 입력과 출력의 방향 대응

베이스라인은 좌상부터 행 우선으로 `up_left`, `up_right`, `down_left`, `down_right`다. 출력은 기존 standing-v2의 행 순서를 유지한다.

| 출력 행 | 방향 | 참조 베이스라인 셀 | 출력 열 |
|---|---|---|---|
| 1 | `down_left` | 좌하 | 프레임 0, 1, 2, 3 |
| 2 | `down_right` | 우하 | 프레임 0, 1, 2, 3 |
| 3 | `up_left` | 좌상 | 프레임 0, 1, 2, 3 |
| 4 | `up_right` | 우상 | 프레임 0, 1, 2, 3 |

방향은 화면 기준이다. 입력의 2×2 위치를 출력 4×4에 그대로 반복 배치하지 않는다. 각 행은 한 방향의 시간 순서이며 마지막 열에서 첫 열로 이어지는 제자리 대기 루프다.

양발은 같은 접지 위치를 유지하고 걷기·발 내딛기·몸 방향 전환 없이 작은 호흡 동작만 표현한다. 같은 행의 네 프레임은 같은 방향과 카메라를 유지한다. 검수 재생은 기존 스탠딩과 같은 프레임당 400ms, 한 주기 1.6초로 시작한다.

## 실행 프롬프트

관리 원본은 `prompts/character-default-standing-v3.yaml`이다. 2×2 전체 참조와 짧은 프롬프트에 명시적 5등신 표현을 사용하는 방식을 채택했다. 사용자 요청에 따라 이 제작 프롬프트를 워크플로우에서 관리한다. 공통 화풍 블록이나 장문의 금지사항을 자동 결합하지 않는다. 프롬프트 채택은 실험 이미지 채택과 별개이며, 최근 결과의 행 순서·행 내부 방향 혼합은 미해결 검수 항목이다.

## 생성과 실행 기록

1. 한국 시간 `.tmp/YYYY-MM-DD_HH-mm-ss/`에 참조 사본·실험 프롬프트·실행 기록을 준비한다. 관리 원본의 `prompt`를 복사하고 버전·해시를 기록한다. 변형 프롬프트는 해당 실행 폴더에서만 수정한다.
2. 참조 이미지를 확인한 뒤 내장 `image_gen`에 2×2 시트 전체와 실행 프롬프트를 전달하여 4×4 시트 한 장을 생성한다. 걷기용 MoMask 포즈 맵이나 Qwen 단일 프레임 실행기를 필수 입력으로 사용하지 않는다.
3. 전신이 각 셀 안에 들어가고 프레임 간 외형·카메라·크기·발 기준 위치가 일관되도록 요청한다. 바닥·배경 광채·문자·테두리를 넣지 않는다.
4. 생성 원본을 실행 폴더에 복사한다. 도구·참조 경로와 해시·프롬프트 원문과 해시·요청 크기·실제 크기·셀 순서·원본 출력 경로를 기록한다. 도구의 내부 모델명은 추측하지 않는다.
5. 생성 프롬프트와 별도로 납품 목표 기록에 셀 크기·행열 수·몸체 높이·anchor를 명시하고 `시트 너비=셀 너비×열 수`, `시트 높이=셀 높이×행 수`로 납품 크기를 계산한다. 납품 목표는 512×512 셀, 4×4 배열, 2048×2048 PNG, 몸체 높이 384px, 셀 로컬 접지 anchor (256,448)이다. 현재 단축 프롬프트에는 픽셀 수치·anchor를 추가하지 않는다. 원본 생성 크기와 후처리 납품 목표를 혼동하지 않는다.
6. 실제 크기를 검사한다. 내장 도구에는 별도 크기 인자가 없으므로 프롬프트 요청만으로 크기가 보장되지 않는다. 1254×1254 등 계약과 다른 결과는 원본 후보로 기록하고 그대로 정식 시트로 전달하지 않는다. 실제 인물 영역을 확인하여 비율을 유지하는 균일 배율과 평행이동으로 정수 셀에 재배치한 뒤 검수한다. 해상도 부족·셀 침범·잘린 신체는 기록하며 단순 확대를 고해상도 생성으로 간주하지 않는다. 실험 프롬프트는 `.tmp`에 둔다.

## 검수와 등록

- 정확히 16개 전신 프레임인지, 행별 방향이 참조 셀과 일치하는지 확인한다.
- 네 방향 모두 베이스라인과 비교하여 얼굴·머리·복장·체형의 일관성을 확인한다.
- 같은 방향 참조와 결과를 전신 높이가 같도록 균일 배율로 겹쳐 머리/전신, 어깨폭/전신, 몸통/전신, 다리/전신 비율을 확인한다. 셀에 맞추기 위한 머리 확대·다리 단축·비균일 스케일을 허용하지 않는다. 프레임마다 키를 자동 정규화하면 호흡까지 상쇄되므로 방향별 고정 배율과 공통 접지점을 사용한다.
- 방향별 0→1→2→3→0 루프에서 발 미끄러짐·불필요한 이동·크기 변화·팔다리 깨짐을 확인한다. 대기 동작이 걷기로 변하지 않아야 한다.
- 알파 채널 존재뿐 아니라 배경에 불필요한 반투명 색이나 광채가 남았는지 확인한다.
- 사용자 채택 후에만 새 버전으로 프론트엔드에 등록한다. 실제 이미지 크기로 셀 좌표·방향별 프레임·발 anchor·재생 시간을 기록하고 런타임 채택은 별도로 처리한다.

사용자 채택으로 `slime-frontend/src/assets/characters/default/standing-v3/`에 2026-09-20_21-32-33 결과를 등록하고 기존 standing-v2는 폐기했다. 채택본은 1254×1254 원본을 유지하는 해상도 예외이며, 방향 혼합은 sidecar 셀 선택으로 보정한다. 좌하 3개 고유 프레임은 1→2→3→2로 재생한다. 향후 규격 시트 채택 시 이 예외를 종료한다. 이후 재생성 결과는 아직 `.tmp` 후보이며 런타임 교체 대상이 아니다. 생성 방식은 워크플로우, 정식 이미지 원본은 프론트엔드에서 관리한다.
