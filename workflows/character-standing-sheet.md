# 캐릭터 스탠딩 시트 제작 절차

Codex 내장 `image_gen`으로 승인된 **4방향 2×2 베이스라인 시트 전체를 참조하여 4×4 스탠딩 시트**를 생성한다. 출력은 4방향×방향당 4프레임이다. 이 문서는 제작 실행 계약이며 이번 정리는 이미지 생성이나 기존 에셋 교체를 의미하지 않는다.

## 입력 기준

- 현재 참조 원본: `slime-frontend/src/assets/characters/baseline/character-default-white-shirt-four-directions-v2.png`.
- 같은 이름의 sidecar YAML에서 실제 크기·셀 좌표·출처를 확인하고 실행 시 파일 해시를 기록한다.
- 베이스라인 시트 전체를 하나의 참조 이미지로 전달한다. 단일 방향을 잘라 유일한 외형 참조로 사용하거나 기존 스탠딩 결과를 연쇄 참조하지 않는다.
- 외형·복장·렌더링 스타일과 신체 비율은 승인된 베이스라인을 기준으로 유지한다. 별도의 등신 수치나 체형 보정 문구를 자동 추가하지 않는다.

## 입력과 출력의 방향 대응

베이스라인은 좌상부터 행 우선으로 `up_left`, `up_right`, `down_left`, `down_right`다. 출력은 기존 standing-v2의 행 순서를 유지한다.

| 출력 행 | 방향 | 참조 베이스라인 셀 | 출력 열 |
|---|---|---|---|
| 1 | `down_left` | 좌하 | 프레임 0, 1, 2, 3 |
| 2 | `down_right` | 우하 | 프레임 0, 1, 2, 3 |
| 3 | `up_left` | 좌상 | 프레임 0, 1, 2, 3 |
| 4 | `up_right` | 우상 | 프레임 0, 1, 2, 3 |

방향은 화면 기준이다. 입력의 2×2 위치를 출력 4×4에 그대로 반복 배치하지 않는다. 각 행은 한 방향의 시간 순서이며 마지막 열에서 첫 열로 이어지는 제자리 대기 루프다.

## 생성과 실행 기록

1. 한국 시간 `.tmp/YYYY-MM-DD_HH-mm-ss/`에 참조 사본·실험 프롬프트·실행 기록을 준비한다. 프롬프트는 참조 역할, 위 방향 대응, 방향당 4프레임의 작은 호흡·대기 동작, 투명 배경을 명시한다.
2. 참조 이미지를 확인한 뒤 내장 `image_gen`에 2×2 시트 전체와 실행 프롬프트를 전달하여 4×4 시트 한 장을 생성한다. 걷기용 MoMask 포즈 맵이나 Qwen 단일 프레임 실행기를 필수 입력으로 사용하지 않는다.
3. 전신이 각 셀 안에 들어가고 프레임 간 외형·카메라·크기·발 기준 위치가 일관되도록 요청한다. 바닥·배경 광채·문자·테두리를 넣지 않는다.
4. 생성 원본을 실행 폴더에 복사한다. 도구·참조 경로와 해시·프롬프트 원문과 해시·요청 크기·실제 크기·셀 순서·원본 출력 경로를 기록한다. 도구의 내부 모델명은 추측하지 않는다.
5. 크기는 실행 전에 정하고 실제 출력값을 별도로 확인한다. 기존 standing-v2의 크기를 새 결과의 실제 크기로 가정하지 않는다. 실험 프롬프트는 `.tmp`에 두고 정식 채택 프롬프트는 기존 보관 정책에 따라 관리한다.

## 검수와 등록

- 정확히 16개 전신 프레임인지, 행별 방향이 참조 셀과 일치하는지 확인한다.
- 네 방향 모두 베이스라인과 비교하여 얼굴·머리·복장·체형의 일관성을 확인한다.
- 방향별 0→1→2→3→0 루프에서 발 미끄러짐·불필요한 이동·크기 변화·팔다리 깨짐을 확인한다. 대기 동작이 걷기로 변하지 않아야 한다.
- 알파 채널 존재뿐 아니라 배경에 불필요한 반투명 색이나 광채가 남았는지 확인한다.
- 사용자 채택 후에만 새 버전으로 프론트엔드에 등록한다. 실제 이미지 크기로 셀 좌표·방향별 프레임·발 anchor·재생 시간을 기록하고 런타임 채택은 별도로 처리한다.

기존 `character-default-white-shirt-standing-v2`는 그대로 유지하며 이 새 참조 절차로 생성된 결과라고 소급 기록하지 않는다. 생성 방식은 워크플로우, 정식 이미지 원본은 프론트엔드에서 관리한다.
