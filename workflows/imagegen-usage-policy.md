# 이미지젠 최소 사용 정책

## 목적과 적용 범위

Codex 내장 image_gen은 호출 비용이 높은 최종 외형 도구다. 캐릭터·몹·컷인 등 워크플로우가 만드는 모든 래스터 에셋 후보에 이 정책을 적용한다. 이 정책은 품질 검수나 사용자 채택을 생략하는 근거가 아니며, 모델 비용을 줄이면서 재현 가능한 제작 순서를 정한다.

## 기본 원칙

- 이미지젠은 기본 포즈 생성기나 반복 실험 도구가 아니다. MoMask 리그, Qwen 포즈 적용, 이미지 비교, 투명 배경 처리, 균일 배율·정렬, 앵커 검수, 시트 패킹은 이미지젠 없이 수행한다.
- 새 캐릭터의 승인 2×2 베이스라인을 만들 때와, 포즈·방향 검수를 통과한 후보의 외형을 최종 복구할 때만 이미지젠을 사용한다.
- Qwen 결과가 포즈·방향·다리 연결 검수를 통과하지 못하면 이미지젠을 호출하지 않는다. 먼저 리그·참조 순서·기준 프롬프트·Qwen 파라미터 중 한 조건만 바꾼 비교를 수행한다.
- 정상 프레임은 다시 생성하지 않는다. 오류 프레임만 선택하고, 검수 시트·리그·기존 프레임을 함께 기록한 뒤 그 프레임만 처리한다.
- 이미지젠으로 최종 시트·연속 루프·검수용 비교 이미지·앵커 좌표를 만들지 않는다. 승인된 개별 프레임을 결정적 도구로 정렬·패킹한다.

## 호출 허용 조건

호출 전 실행 폴더에 다음 항목을 기록한다.

1. 호출 목적: `baseline`, `identity-recovery`, `approved-final-asset` 중 하나.
2. 대상 에셋·방향·프레임 ID와 현재 오류 또는 검수 통과 근거.
3. Qwen·리그 검수 결과와 참조 입력의 역할·순서·해시.
4. 이번 호출에서 확인할 가설 하나와, 결과를 채택·보류·폐기할 판정 기준.

위 기록 없이 하는 스타일 비교, 프롬프트 길이 비교, 여러 변형의 동시 생성, 이미 오류로 판정된 포즈의 외형 복구는 허용하지 않는다. 사용자가 특정 이미지젠 실험을 명시적으로 요청한 경우에도 실험 결과는 `.tmp/` 후보로만 보관하며 정식 에셋에 자동 반영하지 않는다.

## 호출 단위와 재시도

- 애니메이션은 검수된 프레임만 호출한다. 여러 프레임을 한 호출에 넣는 경우에도 최대 4프레임이며, 같은 방향·같은 외형·같은 검수 조건이어야 한다.
- 새 베이스라인은 2×2 한 장을 하나의 후보 단위로 본다. 같은 외형·방향 범위에서 추가 베이스라인 호출은 사용자가 새 후보 생성을 지시했을 때만 허용한다.
- 개별 오류 프레임은 한 번의 이미지젠 후보를 기본으로 한다. 결과가 기준을 충족하지 않으면 같은 프레임을 즉시 반복 호출하지 않고 실패 사유를 기록해 Qwen·리그 단계로 돌아간다.
- 동일 프레임의 추가 이미지젠 호출은 입력 참조, 포즈 결과, 방향 지시 중 적어도 하나의 검증 가능한 변경과 새 가설이 있을 때만 허용한다. 이전 후보를 그대로 다시 요청하는 재시도는 금지한다.
- 한 실행에서 이미지젠 호출 예산은 실행 시작 전에 선언한다. 예산 확대는 이미 생성한 후보의 검수 결과와 확대 사유를 같은 실행 기록에 남긴다. 도구가 비용·토큰을 노출하지 않으면 `null`과 미제공 사유를 기록하며 추정값으로 대체하지 않는다.

## 단계별 기본 경로

| 단계 | 기본 도구 | 이미지젠 사용 |
| --- | --- | --- |
| 모션·방향·발 교대 | MoMask·리그·Qwen | 사용 안 함 |
| 포즈 오류 분석 | 리그 대조·Qwen 단일 조건 비교 | 사용 안 함 |
| 외형 기준 생성 | 이미지젠 | 승인 베이스라인에 한해 사용 |
| 포즈 통과 프레임의 외형 복구 | Qwen 결과 + 승인 베이스라인 | 필요한 선택 프레임에만 사용 |
| 정렬·알파·앵커·루프·시트 | 결정적 이미지 처리·검수 도구 | 사용 안 함 |

## 기록과 검토

`generation-records`에는 이미지젠 호출 수, 대상 프레임 수, 채택 수, 폐기 수, 재시도 횟수, 알려진 실행 시간·비용을 남긴다. 호출 수가 늘어난 실행은 어떤 검수 실패가 원인이었는지 기록한다. 최종 에셋에 반영되는 후보는 사용자 채택과 프론트엔드 전달 전 검증을 거쳐야 한다.

이 정책은 이미지젠을 사용할 수 없게 만드는 제한이 아니다. 최종 외형 품질에 실제로 필요한 호출만 남기고, 모델 호출로 해결할 수 없는 정렬·검수·패킹 작업을 로컬 워크플로우가 맡도록 하는 기준이다.
