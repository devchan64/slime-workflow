# 캐릭터 애니메이션 소스와 최종 시트 패킹

## 생성과 전달 분리

이미지젠 소스는 호출당 최대 4프레임으로 생성한다. 걷기는 방향마다 1–4번·5–8번의 2×2 소스 두 장, 스탠딩은 방향마다 4×1 소스 한 장을 유지한다. 오류 프레임은 개별 생성·보정한다. 최종 배열을 만들기 위해 통합 시트를 이미지젠으로 다시 그리지 않는다.

프론트엔드 전달 시트는 **최소 3열×3행**을 사용한다. 방향별 파일 수를 고정하지 않고 전체 방향의 프레임 수를 합산하여 패킹한다. 이 하한은 최종 애니메이션 텍스처에 적용하며 2×2 베이스라인·생성 소스·4×2 리그/OpenPose 참조 시트에는 적용하지 않는다.

## 최종 배치

행 우선으로 배치한다. 아래 프레임 번호는 사용자 표기 1부터 시작하며 기존 frameId는 보존한다.

| 애니메이션 | 전체 프레임 | 최종 배열 | 시트 내부 배치 |
| --- | --- | --- | --- |
| 걷기 | 4방향×8 = 32 | **4×4 두 장** | 1장: down_left 1–8, down_right 1–8 / 2장: up_left 1–8, up_right 1–8 |
| 스탠딩 | 4방향×4 = 16 | **4×4 한 장** | 행별 down_left, down_right, up_left, up_right; 각 행 1–4 |

걷기 각 시트의 1–2행은 첫 방향, 3–4행은 두 번째 방향이다. 방향 클립은 다른 방향으로 이어 재생하지 않는다. 걷기는 방향당 150ms×8, 스탠딩은 400ms×4를 유지한다. 다른 프레임 수는 열·행 모두 3 이상인 배열을 명시하고 남는 셀을 완전 투명하게 둔다. 빈 셀은 재생 목록에서 제외하며 프레임 복제로 채우지 않는다.

## 크기·메타데이터·검수

- 현재 게임용 셀은 384×384, 4×4 시트는 1536×1536 RGBA8이다. 생성 원본은 별도 보존하고 정렬·균일 축소한 게임용 셀을 패킹한다. 생성 도구의 최소 출력 크기를 게임 셀 크기로 사용하지 않는다.
- 생성 원본은 보존한다. 셀 보정이 필요하면 균일 배율·평행이동·투명 여백을 사용하고 배율과 이동을 기록한다. 비균등 변형은 금지한다.
- 각 방향·프레임 ID를 실제 시트 파일/텍스처와 정수 rect에 연결한다. 셀 위치만 이동할 때 셀 로컬 anchor·접지 좌표·재생 시간은 그대로 보존한다. 보정한 경우 좌표도 같은 변환으로 갱신한다.
- 기존 direction→texture 매핑은 여러 방향이 같은 텍스처를 참조할 수 있어야 한다. 소비자와 검수기는 프레임 메타데이터를 사용하며 파일 하나=방향 하나, 전체 셀 수=재생 프레임 수로 추정하지 않는다.
- 원본 셀과 패킹 셀의 RGBA 일치, 총 32/16개 프레임의 누락·중복 부재, rect 범위·중첩, 시트 해시, 방향별 루프·앵커를 확인한다. 빈 셀은 알파 0인지 확인한다. PNG와 애니메이션 메타데이터·출처를 함께 전달한다.
- 기존 4×2/4×1 전용 도구에는 통합 시트를 그대로 입력하지 않는다. 패커와 검수·소비 경로의 다방향 텍스처/rect 지원을 확인하거나 수정한 후 export한다. 이 문서 갱신은 자동 패킹 도구 구현 또는 현재 에셋 전환 완료를 뜻하지 않는다.

## 적용 시점과 비용

2026-09-21 이후 새 최종 export부터 적용한다. 현재 등록된 방향별 시트는 다음 명시적 재패킹·채택 때 교체하며 이번 문서 수정으로 자동 변경하지 않는다. 소스 후보와 패킹 후보는 `.tmp/한국시간/`, 선택된 최종 에셋은 프론트엔드에서 관리한다.

384 셀 기준 RGBA8 기본 레벨은 4×4 장당 9MiB로 걷기 18MiB, 스탠딩 9MiB다. 동일 셀 크기에서 빈 칸 없는 기존 배열과 총 픽셀 수는 같다. 두 방향이 한 텍스처를 공유하므로 방향 하나만 로드할 때의 로딩 단위는 커질 수 있다. 실제 압축 파일 크기·텍스처 제한을 전달 전에 확인한다. 배포·API·DB 구조 변경은 없다.

## 관리번호 전달

최종 시트마다 워크플로우 [생성 관리기록](../assets/generation-records/README.md)의 managementId를 프론트엔드 이미지 목록에 동일하게 등록한다. 전달 경로·SHA-256을 함께 확인하고 불일치 시 완료로 처리하지 않는다. 입력 프레임과 패킹 시트는 각자의 번호를 가지며 이력에서 구성 관계로 연결한다.

## 현재 게임용 export 실행 (2026-09-21)

현재 전달 계약은 RGBA8(채널당 8비트), **384×384 셀·1536×1536 걷기 시트 두 장**이다. 기존 512/640 셀 예시는 과거 크기의 재패킹 설명이다. 생성 원본 캔버스의 최소 크기와 게임용 패킹 크기를 혼동하지 않는다. 제작 정렬본의 전신 최대 384px는 512px 셀에 보존하고, 게임용 셀은 동일 배율 3/4로 축소한다. 인덱스 컬러 변환을 하지 않는다.

```bash
.venv/bin/python generators/animation/pack_walk_sheets.py \
  --normalized-dir .tmp/실행폴더/game-cells \
  --output-dir .tmp/실행폴더/packed
```

입력은 `frameId.png` 32개와 `frames.json`이다. 각 셀은 투명 RGBA 384px이며 해시·정수 앵커·클립 목록·정렬 출처를 포함한다. 패커는 `frameId → texture + rect` 메타데이터를 생성하고 모든 정렬 셀의 RGBA 바이트가 패킹 후 동일함을 확인한다. 방향별 원본에서 게임용으로 정렬·축소하는 단계와 픽셀 보존 패킹 단계를 구분한다. 후보는 프론트에 자동 등록하지 않는다.

## 기준 버전과 소유권

현재 실행 계약의 기준 ID는 `ui.character-sprite`, 버전은 `1.1`이다. 설계 원본은 비공개 `slime-backend/docs/design/frontend/character-sprite-pixel-guide.md`에서 관리하며 이 문서는 실행·입출력 검증만 설명한다. 비공개 문서를 런타임에 읽거나 공개 저장소에 복제하지 않는다. 계약 변경 시 패커·메타데이터·검수기를 함께 확인하고 과거 생성 기록을 덮어쓰지 않는다.
