# Qwen 맵 타일 생성 워크플로우

## 목적과 도구 선택

맵 타일은 반복 배치되는 환경 에셋이며, 캐릭터의 얼굴·신체처럼 고비용 외형 일관성이 필요한 항목이 아니다. 따라서 맵 타일의 기본 생성 도구는 **Qwen**으로 고정하고 Codex 내장 image_gen은 사용하지 않는다. 이 결정은 이미지젠 호출 비용을 캐릭터 베이스라인과 검수 통과 프레임의 최종 외형에 남기기 위한 것이다.

이 문서는 타일 생성·검수·전달의 실행 계약이다. 생성기는 `Qwen/Qwen-Image-Edit-2511` revision `6f3ccc0b56e431dc6a0c2b2039706d7d26f22cb9`만 사용한다. 사용자 입력이나 실행 프롬프트가 모델을 선택하게 하지 않는다.

## 입력 티켓

타일마다 `.tmp/YYYY-MM-DD_HH-mm-ss/` 실행 폴더에 YAML 티켓을 만든다. 후보 프롬프트와 생성 결과도 같은 폴더에 보관하며 정식 채택 전에는 프론트엔드 에셋 경로에 두지 않는다.

티켓에는 다음 필드를 둔다.

| 필드 | 내용 |
| --- | --- |
| `asset_id` | 타일의 안정적인 관리 식별자 |
| `tile_role` | ground, edge, wall, connector, decoration 중 하나 |
| `tile_size` | 최종 타일의 정수 폭·높이 |
| `generation_size` | 실험용 Qwen 생성 폭·높이. 256~1024px, 16의 배수 |
| `tileability` | repeat-x, repeat-y, repeat-both, none 중 하나 |
| `tile_variants` | `ground`, `wall-front`, `wall-side` 중 생성할 역할 |
| `style_reference` | 승인된 화풍·팔레트·참조 에셋의 ID와 해시 |
| `material_reference` | 선택: 절벽의 돌·흙 표면만 담긴 반복 재질 참조 ID와 해시 |
| `prompt` | 타일 표면과 경계만 설명하는 짧은 생성 지시 |
| `acceptance` | 이음새·가독성·알파·타일 경계의 검수 기준 |

캐릭터·인물·텍스트·UI 요소를 타일 프롬프트에 넣지 않는다. 랜덤한 풍경 장면이나 완성된 맵 스크린샷을 타일 출력으로 채택하지 않는다.

현재 생성기는 불투명 바닥·벽 타일만 지원하므로 `acceptance.transparent_background`는 `false`여야 한다. 투명 장식 타일은 별도 생성기로 다룬다.

## 생성 순서

1. 타일 역할, 최종 크기, 반복 방향, 승인 화풍 참조를 티켓에 고정한다.
2. GPU와 고정 Qwen 모델 캐시를 샌드박스 밖에서 확인한다. CUDA를 사용할 수 없거나 모델·revision이 준비되지 않았으면 즉시 실패한다. CPU 대체 생성은 하지 않는다.
3. Qwen으로 바닥 및 선택한 전면·측면 벽 후보를 각각 생성한다. 고도 벽은 독립 오브젝트가 아닌 정사각형의 평면·무원근·양방향 반복 표면 패턴으로 생성한다. `generation_size`는 실험 변수이며 결과 기록에 반드시 남긴다. 출력·모델 ID·revision·파라미터·입력 해시·프롬프트 해시·로그를 실행 폴더에 기록한다.
4. 결정적 이미지 처리로 최종 타일 크기·RGBA·투명도·색상 형식을 맞춘다. 비반복 타일을 반복 가능하도록 추정 보정하지 않으며, 이음새 오류는 새 Qwen 후보의 검수 사유로 기록한다.
5. 바닥 반복과 `elevations` 전면·측면 절벽 면을 높이 단계만큼 배치한 미리보기로 지면과 높이 변화의 연결을 검수한다. 타일 역할과 다른 실루엣, 경계 광원 차이, 텍스트·워터마크·인물·잘린 오브젝트는 실패다.
6. 사용자가 채택한 타일만 프론트엔드 에셋으로 전달하고 이미지 관리번호·경로·해시를 워크플로우 생성 기록과 동일하게 맞춘다.

## 품질과 비용 경계

맵 타일은 캐릭터 수준의 얼굴·의상·포즈 정확도를 목표로 하지 않는다. 그러나 반복 이음새, 지형 역할의 가독성, 투명도, 최종 크기와 색상 형식은 반드시 검수한다. 품질 부족을 이유로 image_gen으로 자동 승격하지 않는다. Qwen 후보가 기준을 충족하지 않으면 실패 원인을 기록하고 티켓의 역할·참조·프롬프트 중 하나를 바꾼 새 Qwen 실행으로 비교한다.

최종 아틀라스 구성, 해시 파일명, 프론트엔드 등록, CDN 전달은 Qwen 생성과 분리한다. 타일을 다시 그려 아틀라스를 만들지 않고 검수된 타일을 결정적으로 패킹한다. 생성 실행·중간 결과는 워크플로우, 최종 전달 타일은 프론트엔드가 소유한다.

## 실행기와 실험 크기

생성기는 Qwen이 처리 가능한 16의 배수 범위 안에서 `generation_size`를 티켓으로 실험한다. 이 값은 최종 게임 타일 크기와 다르며, 후보 검수 시 실제 품질·이음새·용량을 비교해 다음 실행의 값을 결정한다. 특정 크기를 기본 품질 기준으로 고정하지 않는다.

```bash
.venv/bin/python generators/terrain/generate_qwen_tile.py \
  --ticket .tmp/실행폴더/tile-ticket.yaml \
  --style-reference /승인된/지면-스타일-참조.png \
  --material-reference /승인된/돌-흙-재질-참조.webp \
  --output-dir .tmp/새-실행폴더
```

출력은 역할별 원본 후보, 최종 크기 타일, 역할별 프롬프트, `height-preview.png`, `ticket.yaml`, `result.json`, `execution.log`이다. 명령은 프론트엔드 에셋을 변경하지 않는다.

## 구현 계약

Qwen 타일 생성기는 다음 계약을 구현해야 한다.

- 모델·revision·허용 입력·출력 형식을 코드에 고정하고 엄격히 검증한다.
- `.model/`에는 모델 캐시만 두며, 후보·실행 기록·검수 결과는 `.tmp/` 또는 승인된 `assets/`에 보관한다.
- 단계별 로그와 5초 heartbeat, 실패 traceback·로그 tail을 남긴다.
- 후보 생성, 이음새 검수, 아틀라스 패킹, 프론트엔드 export를 독립 명령으로 제공한다. 한 명령이 사용자 채택 없이 프론트엔드 에셋을 바꾸지 않는다.

이 워크플로우는 이미지젠 비용을 줄이는 도구 선택 기준이며, Qwen 결과의 자동 승인을 뜻하지 않는다.
