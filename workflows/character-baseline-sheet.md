# 캐릭터 생성과 4방향 베이스라인 통합 절차

신규 캐릭터는 Codex 내장 `image_gen`의 **한 번의 생성으로 4방향 2×2 베이스라인 시트**를 만든다. 단일 베이스라인을 먼저 생성한 뒤 2×2로 변환하던 두 단계를 통합한다. 사용자는 변환 과정의 비율 변화 때문에 직접 생성을 선택했다. 시트 내부의 일관성은 생성 후 별도로 검수한다.

## 입력과 실행 준비

1. 승인된 캐릭터 정의에서 외형·복장·화풍 등 필요한 내용만 가져와 새 `.tmp/YYYY-MM-DD_HH-mm-ss/`에 실행 프롬프트를 작성한다. 기획 원본은 비공개 저장소에서 관리한다.
2. 신규 생성은 캐릭터 정의를 입력으로 하며 중간 단일 원화를 필수 입력으로 만들지 않는다. 이미 존재하는 캐릭터의 변경 작업은 별도 편집이며 승인된 2×2 시트를 직접 참조한다.
3. 프롬프트는 캐릭터 정의, 같은 캐릭터의 전신 네 방향, 2×2 배치, 투명 배경, 가능한 최대 출력 크기를 간결하게 지정한다. 추가 체형 보정이나 측정 비율을 임의로 주입하지 않는다.
4. `prompts/character-baseline-four-directions-v1.yaml`은 기존 단일 원화→시트 생성 이력이다. 신규 생성의 기본 프롬프트로 실행하지 않으며 기존 이미지의 출처 기록으로 보존한다.

## 한 번에 생성

- 한 시트의 좌상/우상/좌하/우하는 각각 `up_left`, `up_right`, `down_left`, `down_right`다. 위 행은 후면 쿼터뷰, 아래 행은 전면 쿼터뷰다.
- 같은 캐릭터의 얼굴·머리·복장·체형·렌더링 스타일을 네 셀에서 유지한다. 머리부터 신발까지 셀 안에 담고 문자·테두리·추가 물체를 넣지 않는다.
- **현재 내장 도구가 지원하는 최대 크기의 정사각형 투명 PNG**를 요청한다. 과거 요청값 2160×2160이나 실제 결과 1254×1254를 고정 기본값 또는 최대치로 재사용하지 않는다.
- 내장 도구에 크기 선택 인자가 없으면 프롬프트에 최대 크기를 요청한다. 검증 가능한 최대치가 제공되지 않으면 임의의 수치를 최대치로 단정하지 않는다. 실행 기록에는 `requested_size_policy: maximum_supported_square`, 실제 가로·세로 크기, 최대치 확인 여부를 구분해 남긴다.
- 작은 결과를 사후 업스케일해 최대 해상도에서 생성했다고 기록하지 않는다. 최대치 충족 여부를 확인할 수 없으면 미확인으로 보고한다. 다른 모델/API로 자동 전환하지 않는다.
- 내장 출력 원본을 보존하고 실행 폴더에 복사한다. 도구·프롬프트와 해시·참조 사용 여부·요청 정책·실제 크기·파일 해시·원본 경로를 기록한다. 내부 모델 이름은 추측하지 않는다.

## 검수와 승인

네 방향의 얼굴·머리·몸통·팔다리 비율, 복장과 화풍을 함께 비교한다. 단일 이미지를 다시 생성해 비교 원형으로 삼지 않는다. 필요하면 시트 셀을 크롭하고 균등 배율의 비교 가이드를 만들되 원본은 변형하지 않는다. 원근·자세 차이와 수동 측정 오차를 기록한다.

투명 배경은 알파 채널뿐 아니라 잔여 배경색·광채까지 확인한다. 최종 채택은 사용자 지시로 결정하며 직접 생성 방식으로 일관성이 자동 보장된다고 간주하지 않는다.

## 전달과 후속 생성

승인된 2×2 PNG를 캐릭터의 외형 관리 원본으로 프론트엔드 `src/assets/characters/baseline/`에 버전 등록한다. 레지스트리와 sidecar에는 실제 크기·셀 좌표·생성 출처·해시를 기록한다. 기존 단일 원화는 폐기했다. 현재 승인된 직접 생성 원본은 2×2 v2다. 이전 v1은 이력으로만 유지하며 직접 생성 방식의 결과로 소급 기록하지 않는다.

- 스탠딩: 승인된 **2×2 시트 전체**를 참조하여 [4방향×4프레임 시트](character-standing-sheet.md)를 생성한다.
- 방향별 걷기: 승인된 **2×2 시트 전체**를 외형 참조로 사용하고 해당 방향 셀을 프롬프트에서 지정한다. 같은 방향의 8프레임 리그 시트를 동작 참조로 전달하여 최종 이미지는 내장 image_gen으로 생성한다. [걷기 제작 절차](character-animation.md)를 따른다.
- 휴식 등 다른 제작은 승인된 2×2 원본의 해당 실행 계약을 따른다. 생성 결과를 다음 외형 원본으로 연쇄 참조하지 않는다.

후보·프롬프트·비교 자료는 `.tmp`에 보관한다. 정식 이미지 관리 원본은 프론트엔드, 생성 방식은 워크플로우, 기획·설계는 비공개 백엔드에서 관리한다. 베이스라인 등록과 게임 런타임 채택은 별도이며 AWS 배포 구조에는 변경이 없다.
