# 공통 에셋 웹 검수

웹 검수 서버는 `tools/review/serve.py`에서 관리한다. 기존 애니메이션 전용 `generators/animation/serve_asset_review.py`는 이 경로로 이전했다. 생성기는 HTML·이미지·좌표 산출물만 만들고 웹서버 구현을 복제하지 않는다.

```bash
# 스탠딩 앵커 검수
python3 tools/review/serve.py --root .tmp/2026-09-20_22-22-51 --port 8765
# 리그·OpenPose·Depth 검수
python3 tools/review/serve.py --root .tmp/2026-09-20_21-01-21 --port 8766
# 다른 이름의 오버레이 검수 페이지
python3 tools/review/serve.py --root .tmp/2026-09-20_19-32-12 --entry overlay-review.html --port 8767
```

저장소 루트에서 실행한다. 기본 진입 페이지는 `preview.html`이며 `--entry`는 검수 폴더 기준 상대 HTML 경로다. 실행 시 출력되는 `http://127.0.0.1:포트/`를 연다. 페이지 파일이 없거나 포트가 사용 중이면 즉시 실패한다. 서로 다른 검수 폴더를 동시에 열 때 포트를 구분한다. 종료는 Ctrl+C다.

검수 대상은 워크플로우 `.tmp/`, 기존 `.result/`, 정식 제작 자산 `assets/` 아래 개별 폴더다. 상위 루트 전체 공개·디렉터리 목록·숨김 파일·경로 이탈·외부 심볼릭 링크는 허용하지 않는다. HTML·이미지·JSON·JS·CSS·MP4만 제공하고 로그·프롬프트·모델 파일은 제공하지 않는다. 진입 HTML이 없는 자산은 검수 페이지와 참조 사본을 `.tmp/한국시간/`에 준비한다.

서버는 로컬 읽기 전용이며 저장 버튼은 브라우저 다운로드를 사용한다. 좌표의 정식 적용은 입력 검증 후 별도로 수행한다. 서버 로그는 새 `.tmp/YYYY-MM-DD_HH-mm-ss/review-server.log`에 저장하며 제작 자산 폴더를 변경하지 않는다. 5초마다 요청 수와 로그 크기를 기록하고 실패 시 traceback과 로그 마지막 부분을 출력한다. 응답 캐시는 비활성화한다.

프론트엔드 개발용 Vite와 백엔드 API 서버는 각 제품 저장소의 기능으로 유지한다. 최종 프론트엔드 에셋은 검수에 필요한 파일만 워크플로우 실행 폴더로 복사하며 서버가 다른 저장소를 런타임 의존성으로 사용하지 않는다.

## 걷기 비교 UI

`python3 tools/review/build_walk_review.py --root .tmp/실행폴더`로 공통 걷기 페이지를 만든다. 입력은 `result.json`의 4방향 outputs와 각 결과 PNG, `rig-방향.png`다. 이후 공통 서버로 연다. 템플릿은 `tools/review/walk-sheet.html`에서 관리한다.

방향 탭, 8개 프레임 썸네일, 이전·다음, 속도 선택, 캐릭터·리그 동기 비교, 발 확대, 반투명 겹치기를 지원한다. 시작은 좌하 3번 프레임에서 정지하며 방향·프레임 선택 시 정지한다. 방향 전환 시 프레임 번호를 유지한다. 발 확대는 두 이미지의 동일한 셀 하단 영역을 보여준다. 겹치기는 셀 비율을 맞춘 시각 비교이며 관절 정합이나 앵커 보정을 의미하지 않는다.

## 애니메이션별 앵커 좌표 검수

스탠딩은 기존 양발 중심/앞뒤 끝점 모드를 유지한다. 걷기 등 생성 시트는 공통 진입점으로 수동 지면 앵커를 편집한다.

```bash
python3 tools/review/build_animation_anchors.py --root .tmp/실행폴더 --animation-id character.default.white-shirt.walk --animation-version candidate-2026-09-20
```

`result.json`의 layout(열·행), frame_duration_ms, 4방향 outputs(image·size)를 읽어 `anchors.html`을 만든다. 같은 서버의 `/anchors.html`에서 열거나 `--entry anchors.html`로 시작한다. 프레임 수는 레이아웃에서 결정하므로 4×2 걷기는 방향당 8개, 총 32개다. 시트 크기가 열·행으로 나누어떨어지지 않으면 경계를 정수 내림 분할하여 443/444px 같은 셀을 명시하며 픽셀을 리사이즈하지 않는다.

초기 좌표는 셀 하단 중앙의 수동 편집 시작점이며 자동 검출·승인 좌표가 아니다. 공중 발과 접지 발의 평균으로 지면 앵커를 추정하지 않는다. 각 프레임의 지면 기준점을 클릭 또는 1px 버튼으로 지정한다. 저장 파일 `character-animation-anchor-review.json`에는 설명, 애니메이션 ID·버전, 시트 해시, 방향·프레임·정수 셀 영역·앵커가 포함된다. 좌표 모드는 anchor이며 points는 앵커 한 점이다. 저장해도 게임에 자동 적용되지 않는다.

동일 명령에 `--coordinates /경로/character-animation-anchor-review.json`을 추가하면 편집값을 다시 읽는다. 스키마·중복 키·대상 ID/버전·시트 해시·프레임 수·셀 영역·정수 범위를 검증하며 불일치 시 실패한다. 스탠딩 전용 JSON과 공통 JSON은 구분한다.

## 워크프레임 관리도구

공통 메뉴바에서 걷기 비교·걷기 앵커·스탠딩 앵커를 전환한다. 기능별 페이지를 유지한 채 표시만 전환하므로 좌표 편집 상태가 메뉴 이동으로 초기화되지 않는다. 새로고침·종료 전 JSON 저장이 필요하다. 좌표 편집 후 페이지를 떠날 때 브라우저 확인을 표시한다.

```bash
# 생성 후 즉시 관리도구 실행
python3 tools/review/serve.py --walking .tmp/걷기실행폴더 --standing .tmp/스탠딩검수폴더 --port 8770
# 기존 관리도구 재실행
python3 tools/review/serve.py --root .tmp/생성된관리도구폴더 --port 8770
```

걷기 입력은 preview.html과 anchors.html, 스탠딩 입력은 preview.html이 필요하다. 필요한 페이지와 이미지 사본을 새 한국시간 실행 폴더에 모으며 원본 프롬프트와 로그는 복사하지 않는다. 메뉴 경로는 `/#walk-review`, `/#walk-anchors`, `/#standing-anchors`다. 통합 화면은 실행 시점의 스냅샷이며 후속 생성 결과는 명시적으로 다시 묶는다. 원본 실행 정보는 manager-source.json에 기록한다.

화면의 색상·간격·입력·버튼·포커스 스타일은 `tools/review/review-ui.css`에서 관리한다. 각 생성기는 공통 스타일을 HTML에 삽입하므로 결과 페이지를 별도로 열어도 같은 UI를 사용한다. 통합 생성기는 입력 페이지의 좌표·이미지 메타데이터를 현재 템플릿에 적용한다. 기존 입력 파일은 변경하지 않는다. 앵커 편집은 미리보기와 방향·프레임/좌표 조정/저장 패널로 구성하며 좁은 화면에서는 세로로 배치한다.

`serve.py`는 `--walking`과 `--standing`을 함께 받으면 통합 생성기를 호출하고 반환된 폴더를 바로 제공한다. 이 모드에서는 생성 폴더에 `frame-manager.log`와 `review-server.log`를 함께 기록한다. `--root`와 입력 폴더 옵션은 상호 배타적이며 관리도구 생성 모드의 진입 페이지는 `preview.html`로 고정된다. 생성 실패 시 서버를 시작하지 않는다. 생성만 필요한 경우 `build_frame_manager.py`를 직접 사용할 수 있다.

## 프론트엔드 저장소 자동 탐색

기본 실행은 옵션 없는 `python3 tools/review/serve.py`다. 인접한 `slime-frontend`와 포트 8770을 기본값으로 사용한다. 다른 위치는 `--frontend-repo`로 지정한다. 지정 저장소의 `src/assets/**/*.animation.json`을 탐색해 각 애니메이션·버전의 검수 메뉴를 만든다. 단일 시트는 메타데이터와 같은 이름의 PNG, 방향별 시트는 같은 폴더 `source.json`의 `sheets`를 사용한다. 메타데이터 없는 이미지는 자동으로 프레임을 추정하지 않는다. 현재 프론트엔드의 캐릭터 스탠딩·휴식 및 몬스터 시트를 지원하며 미등록 걷기 후보는 이미 생성된 웹 검수 HTML이 있으면 통합 목록에서, 없으면 기존 생성·명시적 입력 모드에서 검수한다.

현재 검수 UI가 지원하는 계약은 네 방향의 순차 프레임 ID, 동일한 방향별 프레임 수·고정 재생 시간, 독립 반복 클립이다. 계약과 다른 입력은 원인을 표시하고 실패한다. 정수 셀 영역과 원본 소수 앵커를 검증·유지한다. 전체 원본 파일을 제공하지 않고 검수용 이미지 사본과 생성 HTML만 워크플로우 실행 폴더에서 제공하므로 프론트엔드 코드를 런타임에 로드하지 않는다. 저장 JSON은 별도 검수 산출물이며 자동 반영하지 않는다. `frontend-review.log`, `review-server.log`, 출처와 해시를 담은 `manager-source.json`이 생성 폴더에 남는다. 에셋 변경 후에는 명령을 다시 실행해 새 스냅샷을 만든다.

## 검색과 기존 웹 검수 통합

기본 관리도구 생성 시 `.tmp/실행폴더/*.html`, `.result/실행폴더/*.html`, `assets/` 하위 HTML을 수집한다. `manager-source.json`이 있는 이전 관리도구와 현재 출력 폴더는 제외한다. 같은 실행 폴더의 페이지들은 이미지·CSS·JS·JSON·MP4 사본을 공유하며 하위 상대 경로를 유지한다. 숨김 파일·심볼릭 링크·로그·텍스트 프롬프트·모델 파일은 복사하지 않는다. 알려진 앵커 페이지는 기존 데이터를 보존한 채 현재 공통 UI로 갱신한다. 일반 리그·Depth·오버레이 HTML은 원래 기능을 유지한다.

선택 목록은 한국어 이름·ID·검수 종류·실행 날짜 검색과 분류 필터를 제공한다. 공백으로 구분한 검색어는 모두 일치해야 하며 대소문자를 구분하지 않는다. Enter는 첫 결과를 열고 Escape는 검색어만 초기화한다. 검색·분류 변경은 현재 편집 화면을 자동 전환하지 않는다. 페이지는 처음 선택할 때 로드하고 이후에는 인스턴스를 유지한다.

앵커 미리보기에는 기본 240×120px 가상 마름모 타일과 접지 그림자를 표시한다. 원본 픽셀 기준이며 게임 스케일 재현을 의미하지 않는다. 너비를 32–600px의 짝수로 조절하며 높이는 2:1 비율로 자동 계산한다. 그림자 너비와 높이는 타일의 각각 50%다. 큰 타일은 기준선·이미지를 함께 올려 캔버스 안에 표시하며 원본 좌표를 바꾸지 않는다. 타일과 그림자의 표시는 각각 끌 수 있다. 잘못된 크기는 메시지를 표시하며 마지막 유효한 크기를 유지한다. 좌표 내보내기에는 표시 설정이 포함되지 않는다.

## 네비게이션

검색 영역과 현재 검수 위치 표시줄을 분리한다. 현재 항목명·분류는 검색 필터와 무관하게 유지하고 원본 경로·ID는 접이식 원본 정보에 표시한다. 이전·다음은 현재 검색 결과를 순서대로 이동하며 순환하지 않는다. 현재 항목이 결과 밖이면 이동 버튼을 비활성화하고 현재 항목 찾기로 검색 조건을 초기화한다.

사용자 선택은 브라우저 방문 기록에 추가한다. 뒤로·앞으로 이동 시 항목과 해당 기록의 검색어·분류를 복원하며 기존 iframe 인스턴스를 재사용한다. 초기 진입은 기록을 교체해 불필요한 뒤로 이동 단계를 만들지 않는다. 검색 영역을 접어도 현재 위치·이동·별도 탭 열기는 유지한다.

검수 대상은 왼쪽 검색 목록에서 선택합니다. 선택된 항목은 강조되며, 검색·분류를 바꿔도 현재 작업은 유지됩니다. 검색창에서 Enter를 누르면 첫 결과가 열립니다. `검색·목록 접기`로 작업 공간을 넓힐 수 있고, 좁은 화면에서는 목록 아래에 미리보기와 편집 도구가 순서대로 표시됩니다.

좌표 편집 화면 상단에서 변경 프레임 수와 다운로드 필요 여부를 확인합니다. 실행 취소·다시 실행은 편집한 방향과 프레임으로 이동하며, `현재 프레임 원본 복원`도 이력에 남습니다. 방향을 바꿔도 프레임 번호는 유지됩니다. 앵커 편집 화면에서 다른 검수 대상으로 이동하면 재생은 일시정지됩니다.

`좌표 JSON 다운로드` 후 브라우저에서 파일을 확인하세요. 요청 시점 이후 좌표가 달라지면 다운로드 필요 표시가 다시 나타납니다. 페이지 종료 경고는 미다운로드 변경이 있을 때 표시됩니다. 목록 전환은 편집 이력을 유지하지만 새로고침은 유지하지 않습니다. 입력란 밖에서 Ctrl/Cmd+Z와 Ctrl/Cmd+Shift+Z로 실행 취소·다시 실행할 수 있습니다.
