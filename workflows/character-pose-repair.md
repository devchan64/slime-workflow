# Qwen 포즈 변경 → 이미지젠 아이덴티티 복원 → 시트 교체

Qwen에 리그 렌더를 참조시켜 개별 걷기 포즈를 적용하고 이미지젠으로 외형을 복원하는 제작 절차다. [이미지젠 최소 사용 정책](imagegen-usage-policy.md)에 따라 Qwen·리그 포즈 검수를 통과한 오류 프레임만 이 절차에 진입한다. 최초 방향별 4프레임 분할 생성 규칙은 유지한다. 과거 좌하 5번의 채택 사례는 OpenPose 비교 경로이며 리그 경로의 성공 증거로 간주하지 않는다. 다른 프레임·방향의 성공을 보증하지 않는다.

## 1. 참조 준비

새 `.tmp/YYYY-MM-DD_HH-mm-ss/`에 참조·프롬프트·결과·로그·출처를 보관한다. 폴더 시각은 Asia/Seoul이다.

- 승인된 2×2 베이스라인에서 대상 방향 셀을 크롭한다. 좌상/우상/좌하/우하 = up_left/up_right/down_left/down_right다. 크롭 rect·원본 해시를 기록한다.
- Qwen용 캐릭터 크롭을 균일 배율로 512×512에 맞추고 투명 부분을 흰 배경에 합성하여 `standing-reference.png`로 저장한다.
- `assets/rig-sheets/five-head-walk-8f/v1/`에서 같은 방향·번호의 512×512 셀을 추출해 `rig-reference.png`로 저장한다. 4열×2행, 행 우선 순서다. 해당 manifest의 자산·모션 출처와 해시를 확인한다.
- OpenPose는 MoMask 관절의 승인 리그 투영 결과다. 이미지에서 검출한 관절이나 임의 포즈로 교체하지 않는다. OpenPose는 명시적 비교 실험에서만 사용하며 폐기한 다리 컬러 가이드는 사용하지 않는다.

## 2. Qwen 단일 포즈 변경

입력 순서는 **이미지 1: 방향별 캐릭터 크롭, 이미지 2: 목표 리그 렌더**이다. 짧은 영어 프롬프트로 대상 캐릭터와 목표 골격의 역할을 명시한다. 비공개 기준 프로필의 rig 템플릿과 옵션을 분리해 사용한다. 과거 OpenPose 성공 프롬프트로 자동 대체하지 않는다. 장문 좌우 설명을 자동 추가하지 않는다.

고정 Qwen/Qwen-Image-Edit-2511, 512×512, 10스텝, seed 10107, true_cfg_scale 4.0, guidance_scale 1.0, Lightning LoRA 없음. 참조 VAE 512×512·조건 인코딩 384×384, diffusers 0.37.0 계약을 유지한다. CUDA 확인·모델 로딩·추론은 샌드박스 밖에서 실행한다.

```bash
.venv/bin/python generators/animation/generate_qwen_frame.py \
  --output-dir .tmp/실행폴더 \
  --prompt-profile /전달받은/기준-프롬프트.yaml \
  --pose-kind rig --steps 10 --reference-order standing-first
```

`result.png`와 `result.json`에서 입력 순서·해시·크기·설정을 확인한다. 포즈가 변경됐는지, 골반→무릎→발목 연결과 지지발·이동발이 적절한지 검수한다. 방향·외형이 바뀐 Qwen 결과를 최종 캐릭터 에셋으로 바로 채택하지 않는다. 포즈 자체가 잘못됐다면 다음 단계로 넘기지 않는다.

## 3. 이미지젠 외형·얼굴 방향 정리

**이미지 1: 확인한 Qwen 결과(포즈 전용), 이미지 2: 승인된 2×2 베이스라인 전체(캐릭터 아이덴티티)**를 전달한다. 베이스라인의 대상 방향 셀을 명시하고 얼굴·머리·복장·5등신 비율·화풍을 유지하도록 한다. 몸·다리 연결과 겹침은 Qwen 포즈를 유지하고 얼굴 방향은 선택한 베이스라인 방향으로 맞춘다. Qwen 결과 하나만 외형 기준으로 사용하지 않는다.

내장 image_gen으로 1프레임·전신·투명 배경을 생성한다. 현재 도구에는 출력 size/width/height 및 seed 인자가 없으므로 프롬프트의 요청 해상도를 실제 생성 설정으로 기록하지 않는다. 실측 크기와 요청 크기를 따로 기록한다. 내부 모델명은 추측하지 않는다.

## 4. 사용자 채택 후 실제 시트 교체

1. 사용자가 채택한 원본을 프론트엔드 `walk-v1/approved-frames/` 같은 정식 원본 경로에 등록하고 해시·승인 상태·출처를 남긴다. 원본 등록만으로 시트 적용 완료로 처리하지 않는다.
2. **리사이징 금지 원칙은 폐기했다.** 생성 원본은 보존하고 시트용 사본을 균일 축소·확대할 수 있다. 기존 프레임의 머리·몸통 배율을 기준으로 맞추고 투명 여백·평행이동으로 대상 rect에 배치한다. 비균등 변형과 신체 잘림은 허용하지 않는다.
3. 기존 시트의 해당 셀을 RGBA 교체 셀로 완전히 대체한다. 정상 프레임을 재생성하거나 리사이즈하지 않는다. 변경 전후 시트 크기 및 교체 영역 밖 **모든 RGBA 바이트**의 일치를 검증한다.
4. 시트 해시·프레임별 rect/anchor·개별 원본의 sheetIntegrated·통합 출처를 갱신한다. 기존 임시 앵커를 승인된 지면 좌표로 표시하지 않는다. runtimeAdopted는 실제 런타임 연결 여부와 별도로 관리한다.
5. 비교·앵커 검수 페이지의 시트와 메타데이터를 함께 갱신한다. 개별 5번뿐 아니라 4→5→6 및 8→1 루프, 배율·접지 흔들림을 확인한다. 정식 파일 경로·이미지 목록 검증도 수행한다.

최종 전달 배열은 [패킹 계약](character-animation-export.md)을 따른다. 걷기 32프레임은 4×4 두 장으로 전달하며 대상은 방향·프레임 ID에서 시트 파일·rect로 조회한다. 기존 시트의 셀 교체와 전체 재패킹은 별도 단계다. 재패킹 검증은 각 셀의 RGBA 보존으로 수행한다. 아래 사례의 rect는 당시 방향별 4×2 배열의 역사 기록이다.

통합 사례의 균일 배율은 0.5288135593, 이동은 (-1, 6), 시트 rect는 (0, 640, 640, 640)이다. 이 값은 해당 이미지에만 해당하며 다음 생성물에 복사하지 않는다. 앵커 (320, 608)는 여전히 검수 시작 좌표다. 범용 자동 교체 CLI는 아직 제공하지 않으며 실행별 통합 기록과 검증을 남긴다.

## AnyPose 적용 기준 (2026-09-21)

현재 보정 경로는 AnyPose Base/Helper **0.7/0.7**, Lightning 없음, 10스텝·true CFG 4.0이다. 모델 카드 기반 포즈 문구는 유지하고 캐릭터 방향은 별도 보조 프롬프트로 제공한다. 우상은 뒤쪽 3/4 시점·화면 오른쪽 위, 좌하는 앞쪽 3/4 시점·화면 왼쪽 아래다. 실제 문구·기준/보조 구분·해시는 실행별 `.tmp`에 보관한다.

우상 결과에서 얼굴이 정면으로 돌아가는 현상은 올바른 뒷모습 참조를 주어도 발생했다. Qwen 결과의 외형/얼굴 방향은 통과로 가정하지 않고 2×2 베이스라인을 사용한 이미지젠 복원 및 검수로 이어간다. 최종 패킹 계약은 게임용 384px 셀·RGBA8이며, 스탠딩과 동일 게임 배율의 비교 페이지에서 확인한다.
