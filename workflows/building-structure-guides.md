# 건물 구조 가이드 50종 제작 명세

## 범위와 상태

빌보드 가이드의 `건물` 분류를 바닥·벽·지붕·문이 확정된 구조 가이드 50종으로 대체한다. 최신 허용 범위는 각 변 2~5칸이다. 이전 4×4 상한은 이 가이드 카탈로그에 한해 대체한다. 기존 도시의 점유 크기는 자동 변경하지 않는다. 주택과 시설은 별도 분류하지 않는다.

신규 50종의 구조 PNG·검수 PNG·SVG·좌표 기록을 생성하고 건물 분류를 교체했다. 기존 가이드 파일과 선택 참조를 제거했다. 25개 구조 × 출입구 2방향 = 50개이며, 층수를 다시 조합해 수를 늘리지 않는다.

## 고정 좌표와 높이

- 타일은 80×40px, 직교투영은 `screenX = 40*(column-row)`, `screenY = 20*(column+row)-height`로 계산한다. 원근 수렴을 사용하지 않는다.
- 점유는 `(0,0)~(width,depth)`의 직사각형이다. 가시 접지점은 `(0,depth)`, `(width,depth)`, `(width,0)`이며 바닥선 기울기는 ±0.5다.
- 1층 높이는 80px, 2층 벽 상단은 160px다. 지붕 높이는 벽 상단에서 추가하며 층 높이에 포함하지 않는다.
- 문 높이는 64px로 고정한다. 문턱은 지면 높이 0이며 계단·포치로 바닥 윤곽을 확장하지 않는다.
- 남쪽 문은 `row=depth`인 왼쪽 가시 벽, 동쪽 문은 `column=width`인 오른쪽 가시 벽에 둔다. 월드 방향과 화면 좌우를 함께 표시한다.
- 문은 해당 벽 중앙에 배치한다. 문이 있는 변이 2~3칸이면 폭 1칸, 4~5칸이면 폭 2칸이다. 남쪽은 width, 동쪽은 depth로 문 폭을 결정한다. 이는 신규 소형 규격까지 확장한 제작 규칙이다.
- 남쪽 문 범위는 `column=(width-doorWidth)/2 .. (width+doorWidth)/2`; 동쪽은 같은 식에서 column을 row, width를 depth로 바꾼다. 문 상단과 하단은 각각 높이 64, 0이다.

## 지붕 구조

모든 구조는 벽면을 채운 불투명 단순 모형으로 제작한다. 바닥 그리드만 있는 상자 가이드를 재사용하지 않는다.

- 박공: 용마루는 긴 축 중앙에 놓는다. 정방형은 row 축을 따른다. 양 지붕면은 동일 경사이며 양 끝 박공벽을 막는다.
- 우진각: 네 면이 닫힌 지붕이다. 정방형은 중앙 꼭짓점, 장방형은 긴 축을 따라 짧은 중앙 용마루를 둔다. 장방형 용마루의 평면 길이는 긴 변과 짧은 변의 차이다.
- 우진각 상승량은 짧은 변 칸 수 × 32px로 정한다. 직교 카메라에서 뒤쪽 면이 가느다란 띠처럼 노출되는 낮은 경사를 피하고, 네 면을 좌표로 보존하되 카메라 반대쪽 두 면은 숨긴다. 정방형은 삼각면 4개, 장방형은 삼각면 2개와 사각면 2개다.
- 외쪽: 남쪽 벽 상단을 낮은 처마로 두고 북쪽으로 높아지는 단일 지붕면이다. 출입구를 동쪽으로 바꾸어도 지붕 축은 바꾸지 않는다.
- 처마는 각 방향으로 0.1타일만 돌출한다. 표의 지붕 상승량은 월드 수직 px이며, 처마·기와 장식 두께로 벽 높이를 줄이지 않는다.
- 굴뚝·종탑·도머·창문·간판은 초기 구조에서 제외한다. 재질 단계에서 추가하더라도 바닥과 주요 지붕선을 바꾸지 않는다.

## 제작 파일과 생성 입력

원본은 `generators/image/config/building-structures/`에 YAML 명세와 좌표로 생성한 SVG·PNG를 관리한다. YAML에는 카탈로그 버전과 ID, 점유, 층수, 문 방향·폭·높이, 지붕 종류·상승량을 저장한다. 지붕 축·처마·투영 규칙은 공용 제작 코드에 고정하고 좌표 기록에 실제 지붕면과 용마루를 보존한다. 알 수 없는 필드와 지원하지 않는 값은 거절한다.

구조 이미지는 도형 코드로 생성하고 이미지젠으로 설계하지 않는다. 이미지젠은 검증된 구조에 재질을 입히는 단계에서 사용한다. 구조 참조와 디자인 참조의 역할을 구분한다.

각 ID에 같은 좌표를 사용하는 두 PNG를 제공한다. 하나는 선·문·접지점을 표시한 검수용, 다른 하나는 글자와 그리드 없는 불투명 구조 참조용이다. 두 파일은 카탈로그에서 한 종으로 취급한다. 생성 참조에는 문 개구부와 닫힌 지붕을 실제 형상으로 표현한다.

50종 모두 동일한 2배 표시 배율로 1024×1024 캔버스에 중앙 배치한다. 실제 타일 80×40·층 높이 80px는 가이드에서 160×80·160px로 표시된다. 객체별 자동 확대를 하지 않는다. 검수용 이미지에는 바닥 격자를 겹쳐 표시한다. 입력 좌표와 캔버스 이동량을 기록한다. 투명 여백을 크롭할 경우 이동량·접지점도 함께 변환한다.

## 검수 기준

1. 구조 좌표에서 바닥 변 길이와 ±0.5 기울기, 수직 벽, 문 높이 64px, 층당 80px를 수치 검증한다.
2. 지붕은 닫힌 면으로 구성되고 벽 상단에 접한다. 박공의 중앙 용마루와 동일 경사를 검증한다.
3. 이미지젠 결과는 3개 접지점을 구조와 겹쳐 비교한다. 평행이동과 동일 배율만 허용하며 가로·세로 독립 변형으로 합격시키지 않는다.
4. 생성 후보의 허용 오차는 긴 바닥 대각선을 400px로 정규화했을 때 접지점당 2px 이하, 양쪽 접지선 각도 차이는 각각 1도 이하로 제안한다. 수치 통과와 사용자 시각 승인을 구분한다.
5. 지붕·문이 무너지거나 배경 잔상이 남은 후보는 등록하지 않는다. 생성 완료를 가이드 일치 완료로 표현하지 않는다.

## 기존 가이드 교체 절차

신규 50종을 검증한 뒤 한 번의 전환으로 카탈로그를 교체한다. 기존 `building-layouts`의 건물 프리셋 전체와 4×4 내부 배치 영역 가이드를 폐기 대상으로 한다. 자연물·소품 등 다른 빌보드 가이드는 유지한다.

신규 YAML·SVG·PNG를 Git 추적하고 새 로더, 건물 분류 검색, 생성 참조 전달, 프롬프트 조합, GUI·CLI 검증을 함께 반영한다. 기존 독립 층수 선택은 제거하고 각 가이드에 정해진 값을 표시한다. 폐기 ID 요청은 명확한 오류로 거절하며 다른 규격으로 자동 치환하지 않는다.

메뉴가 새 파일을 참조하는 것을 확인한 뒤 기존 건물 가이드 이미지와 소비 참조를 삭제한다. 과거 생성 작업의 입력 사본과 결과, 등록된 건물 에셋, 도시 배치 데이터는 가이드 폐기 대상이 아니다.

실제 관리도구 문서에서 건물 분류 50개, 검색·선택·미리보기·참조 전달을 확인한다. 검증 목적으로 GPU 작업을 접수하지 않는다. 문서 작성과 실제 교체 완료를 분리해 보고한다.
