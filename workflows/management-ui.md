# 관리도구 UI 가이드

관리도구의 새 페이지를 만들거나 기존 화면을 수정할 때 적용하는 UI·UX 기준이다. 공용 색상, 설정과 검수 화면의 배치, 생성 상태, 로그, 이력, 재생 동작을 일관되게 관리한다. 서비스별 명령·저장 경로·CLI 계약은 [관리도구 클라이언트 가이드](management-clients.md)를 따른다.

이 문서의 규칙은 신규·수정 UI의 기준이다. 기존 모든 페이지가 같은 컴포넌트로 전환되었다는 뜻은 아니다. 기존 구현과 차이가 있으면 해당 기능을 수정하는 범위에서 공용 구현으로 통합하고 검증한다.

## 1. 페이지 구성과 탐색

- 제목에는 도구의 목적을 표시하고, 바로 아래에 입력과 결과를 한 문장으로 설명한다.
- 데스크톱은 왼쪽에 입력·설정, 오른쪽에 미리보기·상태·결과를 배치한다. 생성 이력은 아래쪽 전체 너비를 사용한다.
- 생성 전에 확인할 수 있는 원본 에셋은 오른쪽 상단에서 검수한다. 생성 결과와 원본 에셋의 제목·컨트롤을 구분한다.
- 설정 영역에는 사용자가 선택에 필요한 참조만 표시한다. 캐릭터 애니메이션의 왼쪽에는 캐릭터 레퍼런스만 표시하고 첫 포즈 프레임을 중복 배치하지 않는다.
- 좁은 화면에서는 입력과 검수 영역을 세로로 배치한다. 긴 ID·경로·프롬프트는 줄바꿈하고 페이지 전체의 가로 스크롤을 만들지 않는다.
- 속성이 많은 편집기는 관련 속성을 그룹화한다. 속성 패널 높이를 미리보기와 맞추고 패널 안에서 스크롤한다. ‘기준값 복원’ 같은 전체 동작은 스크롤 영역 밖에 둔다.
- 페이지 등록과 메뉴는 기존 관리도구 구성을 따른다. 애니메이션 페이지는 [build_animation_tools.py](../tools/review/build_animation_tools.py)에서 관리한다. 폐기된 페이지의 메뉴나 우회 진입점을 다시 추가하지 않는다.

## 2. 공용 색상과 스타일

[management.css](../tools/review/ui/shared/management.css)의 CSS 변수를 기준으로 사용한다. 페이지별 스타일은 기능에 필요한 배치만 추가하며 공용 색상·버튼·로그·이력 스타일을 복사하지 않는다.

| 토큰 | 기본값 | 용도 |
| --- | --- | --- |
| `--page` | `#10151f` | 페이지 배경 |
| `--panel` | `#192230` | 설정·검수 패널 |
| `--line` | `#314055` | 경계선 |
| `--muted` | `#a7b5c8` | 보조 설명 |
| `--accent` | `#a7c8ff` | 주요 동작·강조 |
| `--danger` | `#ffc2bf` | 취소·초기화 안내 |

공용 클래스는 `.studio-grid`, `.studio-panel`, `.setting-field`, `.generation-actions`, `.result-canvas`, `.playback-controls` 등의 기존 사용처를 확인해 활용한다. 클래스가 페이지에만 정의되어 있다면 공용 제공으로 가정하지 않는다. 여러 페이지에 같은 배치가 필요할 때 공용 CSS로 추출한다.

상태는 색상과 텍스트를 함께 사용한다. 선택·실행·완료·실패를 색상만으로 구분하지 않는다. 모션·속성 이름과 조작 안내는 한국어를 우선하고 모델명·에셋 ID는 원문을 유지한다.

### 전역 스타일 적용 계약

- 시각 기준은 MoMask 생성기다. 정식 원본은 `tools/review/ui/shared/management.css`, 웹 공용 주소는 `/management/style.css`다. 생성기·작가 에이전트는 이 주소를 직접 연결한다.
- 색상 토큰 → 기본 타이포그래피·입력·버튼 → 패널·로그·상태·이력·탐색 컴포넌트를 전역 CSS에서 관리한다. 페이지별 CSS는 열 개수·미리보기 크기·스크롤 영역 같은 도메인 배치를 맡는다.
- 주요 버튼에는 `primary`, 위험 동작에는 `danger`, 패널에는 `studio-panel`을 사용한다. 키보드 포커스·hover·disabled·선택 상태도 공용 규칙을 따른다.
- 기존 `generation-studio.css`와 서비스별 `studio.css` 주소는 호환 연결로만 남긴다. 새 색상이나 컴포넌트를 이 파일에 추가하지 않는다.
- 검수 페이지와 관리 셸은 `read_review_shared_styles()`로 전역 CSS와 `review-ui.css` 배치를 함께 삽입한다. 생성된 HTML을 단독으로 열어도 색상이 유지된다. 과거 산출물은 재빌드해야 반영된다.
- 게임 캔버스·타일·이미지의 색과 투명도 검수용 배경은 UI 색상과 구분한다. 전역 테마 때문에 실제 산출물 색을 바꾸지 않는다.
- 변경 시 MoMask·ANNY·캐릭터 애니메이션·Qwen 두 페이지·작가 에이전트·관리 셸에서 로딩, 공통 색상, 좁은 화면 넘침을 확인한다. 실제 생성·취소는 스타일 검증에 사용하지 않는다.

## 3. 입력과 고정 설정

- 입력마다 보이는 라벨을 둔다. placeholder만으로 용도를 설명하지 않는다.
- 모션·캐릭터 레퍼런스·포즈 입력·생성 방향처럼 의미가 다른 설정을 별도 항목으로 표시한다.
- 방향은 전체 선택과 개별 선택을 지원한다. 화면에는 ‘전방 좌측·전방 우측·후방 좌측·후방 우측’처럼 사람이 이해할 수 있는 명칭을 사용한다.
- 고정 프롬프트는 기본·보조로 나누어 항상 표시하고 수정 가능한 입력처럼 보이지 않게 한다. 방향별 보조 프롬프트는 선택한 방향에 실제 적용할 내용을 표시한다. 서버에서도 프롬프트 변경 요청을 거절한다. 프롬프트를 출력하는 모든 화면은 아래 단어 수 표시 규칙을 따른다.
- 잠금 속성에는 잠금 표시와 기준값을 보여주고 조작을 비활성화한다. 기준값 복원도 잠금 규칙을 따른다.
- 타겟 FPS는 원본 시간축에서 초당 생성할 장수와 결과의 기본 재생 FPS를 결정한다. 원본 FPS를 초과하는 값은 보간 지원 전까지 거절한다. 검수 재생 속도 변경은 생성 장수를 바꾸지 않는다.
- 생성 장수는 원본 프레임 수·간격·선택 방향을 기준으로 계산해 표시한다. 예: 대기 16프레임·원본 4 FPS, 타겟 2 FPS, 네 방향 → 방향당 8장·4초, 총 32장.

모델·실행기 경로 등 구현 세부사항은 사용자의 선택이나 문제 해결에 필요할 때 표시한다. 용도를 알 수 없는 상태 태그·빈 버튼·중복 설명을 넣지 않는다.

## 4. 생성 버튼과 실행 상태

| 상태 | 주요 버튼 | 필수 안내 |
| --- | --- | --- |
| 초기 조회 | 생성 비활성화 | 생성 가능 여부를 확인 중임을 표시 |
| 입력 부족 | 생성 비활성화 | 부족한 입력과 해결 방법 표시 |
| 생성 가능 | 생성 활성화 | 생성 가능 상태 표시 |
| 요청 전송 | ‘생성 시작 중…’ 비활성화 | 접수 중임을 표시하고 중복 제출 방지 |
| 실행 중 | ‘생성 진행 중’ 비활성화, 취소 제공 | 작업 ID·진행률·비활성 사유·로그 이동 제공 |
| 취소 요청 | 취소 중 안내 | 서버가 취소를 확정할 때까지 실행 상태 추적 |
| 완료·실패·취소 | 유효한 입력이면 생성 활성화 | 최종 상태와 결과 또는 오류·로그 표시 |
| 조회 실패 | 오류·재조회 안내 | 통신 오류를 작업 완료나 취소로 취급하지 않음 |

비활성 버튼 옆에는 **왜 사용할 수 없는지와 어떻게 해소되는지**를 표시한다. 툴팁에만 사유를 숨기지 않는다. 관련 안내는 `aria-describedby`로 버튼과 연결한다.

완료 이미지 수(장), 원본 프레임 번호(번), 현재 방향의 생성 순서(번째), 현재 이미지의 추론 스텝을 구분한다. 전체 장수와 설정 요약은 실행 요청에 저장된 값을 기준으로 표시한다. 완료 이미지 비율을 전체 진행률로 사용하고 추론 스텝 비율을 전체 작업 비율로 표시하지 않는다. 생성 간격으로 원본 번호가 불연속이어도 결과 재생 순번과 혼동하지 않게 한다.

진행 상태와 로그는 자동 갱신한다. 프레임 작업은 완료 수/전체 수를 표시하고, 진행률을 알 수 없는 모델 준비 단계에서는 불확정 진행 표시를 사용한다. 실제 완료 전 100% 또는 ‘완료’를 표시하지 않는다.

페이지 재진입 시 서비스의 실행 상태를 조회해 현재 작업에 연결한다. 브라우저 메모리만으로 실행 여부를 판단하지 않는다. 생성 중에도 입력을 검토할 수 있으나 변경한 입력은 이미 접수된 작업에 적용하지 않는다. 작업 ID와 실행 당시 설정은 결과·이력에서 확인할 수 있어야 한다.

## 5. 로그

접이식 로그의 기준 구현은 [management_log_viewer.py](../tools/review/common/management_log_viewer.py)의 `ManagementLogViewer.attach(details, output)`이다.

- 펼칠 때 마지막 줄로 이동한다.
- 펼쳐진 상태에서 로그가 갱신되면 마지막 줄을 따라간다.
- 로그 영역 자체를 스크롤하며 페이지 전체를 강제로 이동시키지 않는다.
- 페이지의 현재 작업 로그와 이력에서 선택한 작업 로그를 구분한다.
- 로그는 실행 파일에 누적 보관한다. 화면에서 일부만 표시하더라도 원본 파일을 잘라 저장하지 않는다.
- 실행 실패 시 실패 상태와 원인을 표시하고 해당 로그에 접근할 수 있게 한다.

이력 공용 UI에는 같은 마지막 줄 따라가기 동작이 구현되어 있다. 새 페이지에서 별도의 로그 스크롤 구현을 복제하지 않는다.

## 6. 생성 이력

기준 시나리오는 MoMask의 목록·결과 재생 흐름이며, 이미지 생성기의 참조 복원·결과 조회 장점도 기능에 맞게 사용한다. 공용 이력 구현은 [generation-history.js](../tools/review/ui/shared/generation-history.js)이다.

- 이력은 서버에 누적 저장하고 새로고침·서버 재시작 이후 다시 조회한다.
- 드롭다운 대신 최신순 목록과 페이지네이션을 사용한다. 현재 공용 UI는 페이지당 8건이다.
- 이력 카드는 상태·생성 시각 → ID·설정 요약 → 결과·로그 동작 → 기록 폴더 → 접이식 입력 내용 순서로 구성한다. 상태·날짜를 상세 제목에 반복하지 않는다. 결과 재생은 주요 버튼으로 강조하고 목록 초기화는 상단 관리 동작으로 분리한다. 선택한 로그에는 작업 ID를 표시한다.
- 카드 스타일은 `management.css`에서 관리하며 공용 이력 JavaScript가 별도 스타일을 주입하지 않는다.
- 공용 생성 이력의 각 항목에는 기록 폴더의 절대 경로·경로 복사·기록 폴더 열기를 제공한다. 폴더 열기는 관리 서버 컴퓨터의 파일 관리자를 호출하며, GUI 환경이 없으면 실패 사유와 경로 복사 안내를 표시한다. 서버는 생성기·ID로 등록 저장소 안의 기록을 확인하며 클라이언트가 임의 파일 경로를 실행할 수 없게 한다.
- 완료된 결과는 생성 당시 데이터로 열거나 재생한다. 현재 입력을 바꿔도 과거 결과의 모션·방향·프레임 해석이 바뀌지 않는다.
- 입력 복원은 해당 생성기가 지원할 때 제공한다. 결과 조회가 입력을 자동으로 덮어쓰지 않게 한다.
- 선택한 이력, 현재 페이지, 펼친 상세는 자동 갱신으로 불필요하게 초기화하지 않는다.
- 초기화는 사용자의 명시적 수동 동작으로 수행한다. 확인 문구에 **목록만 초기화하고 원본 결과 파일은 유지한다**는 범위를 명시한다.
- 초기화한 이력은 진행 중인 작업이 종료되어도 다시 생성하지 않는다. 결과 파일 삭제는 별도 범위의 동작이다.

공용 이력 연결 시 `#generation-history`와 `data-route`를 제공한다. 애니메이션 결과는 `playable`과 `window.playGenerationRecord` 연결을, ANNY 입력 복원은 기존 `restoreGenerationRecord` 연결을 확인한다. 서비스별 응답을 확인하지 않고 공용 UI를 복사해 사용하지 않는다.

## 7. 에셋·결과 재생

- 방향 선택, 재생, 중지, 이전·다음 한 프레임, 위치 슬라이더, 현재/전체 프레임 번호를 제공한다.
- 재생 속도는 4·8·12·16 FPS를 선택할 수 있게 한다. 기본은 4 FPS이며 재생 중 변경할 수 있다. 검수 속도 변경은 원본이나 생성 메타데이터를 수정하지 않는다.
- 원본 OpenPose와 ANNY는 나란히 표시하고 같은 프레임으로 동기 재생한다. 두 이미지가 모두 준비된 뒤 화면을 갱신한다.
- 검수 방향은 생성 방향 선택과 독립적으로 바꿀 수 있다. 원본 검수는 타겟 FPS에 관계없이 전체 프레임을 사용한다.
- 모션·방향을 바꾸면 이전 재생과 진행 중 이미지 요청의 영향을 차단하고 새 프레임으로 전환한다. 늦게 도착한 응답이 새 선택을 덮어쓰지 않도록 한다.
- 긴 모션은 제한된 수의 프레임을 캐시하고 필요한 프레임을 미리 읽는다. 전체 모션을 무조건 메모리에 적재하지 않는다.
- 파일 누락·로딩 실패는 검수 영역에 표시한다. 오래된 이미지를 새 결과처럼 표시하지 않는다.

현재 원본 에셋 재생 구현은 [character-animation-assets.js](../tools/review/ui/character_animation/character-animation-assets.js), 생성 결과 재생은 [character-animation.js](../tools/review/ui/character_animation/character-animation.js)를 참고한다. 아직 독립된 범용 플레이어로 통합된 상태는 아니다. 다른 페이지에서 같은 기능이 필요하면 공용 플레이어로 추출해 함께 사용한다.

`generation-progress.js`는 기존 이미지 생성기의 DOM·응답 형식에 의존한다. 다른 생성기에 그대로 연결하지 말고 계약을 확인해 필요한 공용 동작을 추출한다. GUI는 공용 게이트웨이로 명령을 전달하고, 파일·이미지 조회는 정적 조회 경로를 사용한다. 별도 웹 전용 실행 서비스나 이력 저장소를 만들지 않는다.

공통 동작 변경은 공용 파일에서 수행한다. 모든 생성기에 영향을 주는 수정은 각 사용처의 계약과 주요 동작을 함께 확인한다.

## 9. 접근성과 검증

기본 HTML의 `button`, `label`, `select`, `details`, `progress`를 활용한다. 모든 컨트롤은 키보드로 조작할 수 있게 하고 포커스 표시를 유지한다. 상태 안내에는 `role="status"`, 슬라이더·캔버스에는 의미 있는 접근성 이름을 사용한다. 고빈도 로그 전체를 스크린리더에 계속 읽히게 만들지 않는다.

변경 범위에 맞게 다음을 검증한다.

1. 데스크톱·좁은 화면에서 입력, 결과, 이력이 잘리지 않고 읽히는가?
2. 생성 버튼의 비활성 이유가 보이며 입력 충족·작업 종료 후 활성화되는가?
3. 재진입 시 실행 작업을 찾고, 조회 오류·취소 요청·완료 상태를 구분하는가?
4. 로그 펼침과 자동 갱신이 마지막 줄을 표시하는가?
5. 과거 결과 선택, 페이지 이동, ID 복사, 수동 초기화 범위가 올바른가?
6. 모션·방향·FPS 변경, 중지, 한 프레임 이동이 의도대로 동작하는가?
7. GUI·CLI가 같은 요청과 이력을 사용하며 수정 불가 설정을 서버에서도 검증하는가?

브라우저 콘솔 오류, 잘못된 파일 요청, 자바스크립트 문법과 관련 계약 테스트를 확인한다. 생성·취소 테스트에는 모의 응답이나 별도 테스트 기록을 사용해 사용자의 실행 작업을 건드리지 않는다. 실제 GPU 생성 품질 검증과 UI 모의 검증을 구분해 보고한다. 단순 문구·스타일 수정에 구현을 그대로 반복하는 테스트를 추가하지 않는다.

## 공용 작업 영역 탐색

[management-workflow.js](../tools/review/ui/shared/management-workflow.js)는 `data-workflow-label`이 지정된 영역으로 이동하는 공용 메뉴를 만든다. `data-help-title` 영역은 접이식 도움말로 표시한다. 이동은 생성·취소·입력 변경을 실행하지 않는다. 캐릭터 애니메이션, MoMask, ANNY, Qwen 두 화면에 적용하며 키보드 포커스와 모션 감소 설정을 반영한다. 공용 이력 UI는 ID·입력 검색과 상태 필터를 제공하고, 필터 변경 시 첫 페이지로 이동한다. MoMask의 기존 전용 이력은 아직 이 검색 필터로 통합되지 않았다.



## 생성 예상 시간 표시 규칙

신규·수정 생성 UI는 생성 시작부터 예상 남은 시간과 예상 완료 시각을 표시한다. 이 규칙은 이미지·모션·렌더 등 시간이 걸리는 생성 작업에 공통 적용한다.

- 실행 상태 가까이에 ‘예상 남은 시간’과 ‘예상 완료 시각’을 각각 배치한다. 시간 단위와 완료 날짜·시각을 함께 표시해 자정을 넘는 작업도 구분한다.
- 실측 근거가 생기기 전에는 ‘계산 중’과 계산이 가능한 조건을 안내한다. 근거 없는 숫자나 `0분`, `NaN`을 출력하지 않는다.
- 같은 작업의 완료 단위 처리 시간을 우선 사용한다. 기존 이력으로 시작 시 추정할 경우 모델·스텝·입력 크기·작업 종류 등 비교 조건을 맞추고 이력 기반 추정임을 표시한다.
- 추정 근거와 표본 수를 표시하고 완료 단위가 추가되면 갱신한다. GPU 대기·모델 준비·추론 시간이 추정에 포함되는 범위를 명확히 한다.
- 평균 처리 시간을 초과하면 지연 안내 후 재계산한다. 음수 시간이나 확정적인 완료 시각을 표시하지 않는다.
- 완료·실패·취소 시 예상 시간 갱신을 종료하고 최종 상태를 표시한다. 과거 이력 조회 때문에 실행 중인 작업의 예상 시간을 덮어쓰지 않는다.
- 화면 안내는 ‘약’·‘예상’ 표현을 사용하고 GPU 부하 등에 따라 달라질 수 있음을 설명한다.

현재 캐릭터 애니메이션 구현은 같은 작업의 최근 완료 이미지 최대 5장의 처리 시간을 사용한다. 첫 이미지 완료 전에는 계산 중으로 표시한다. 이는 현재 구현 사례이며 다른 모든 생성기에 이미 적용되었다는 뜻은 아니다.

## 프롬프트 단어 수 표시 규칙

기본·보조·방향별·최종 프롬프트 등 프롬프트 원문을 표시하는 UI는 해당 원문 옆에 단어 수를 함께 표시한다. 읽기 전용·편집 가능 여부와 관계없이 적용한다.

- 공백 기준으로 앞뒤 공백을 제거하고 연속된 공백·줄바꿈으로 나눠 센다. 빈 문자열은 0단어다. 단어 수를 모델 토큰 수로 표시하지 않는다.
- 기본과 보조의 개별 단어 수, 실제 모델에 전달하는 최종 결합 프롬프트의 합계를 구분한다.
- 방향·변수 치환과 추가 지시를 모두 적용한 최종 문자열을 기준으로 센다. 여러 방향은 각각 별도 입력이므로 전체 방향의 단어 수를 하나의 입력 합계로 더하지 않는다.
- 편집·방향 선택·기본 프롬프트 사용 여부 등이 바뀌면 원문과 단어 수를 함께 갱신한다.
- 이력의 프롬프트와 단어 수는 실행 당시 기록을 기준으로 표시한다. 현재 설정으로 과거 값을 재해석하지 않는다.
- 모델별 단어 수 제한이 있으면 적용 범위와 한도를 함께 안내한다. UI와 실행기의 계산 기준을 일치시키고 최종 원문·단어 수·해시는 실행 기록에 보존한다.

검증 시 빈 프롬프트·연속 공백·줄바꿈·방향 치환과 최종 합계를 확인한다. 예상 시간은 실측 없음·정상 진행·지연·종료 상태를 확인한다.

### 캐릭터 애니메이션 생성 배속

배속은 생성 설정이다. 기본 4 FPS·1배이며 1·1.5·2·4배를 제공한다. 생성 장수는 `ceil(원본 프레임 수 × 타겟 FPS / 원본 FPS / 배속)`이다. 타겟 FPS는 유지하며 생성 결과의 동작 시간이 짧아진다. 예: 16프레임·4 FPS 원본에서 2배·4 FPS로 생성하면 8장·2초다. 재생기에 별도의 배속 옵션을 표시하지 않는다. 원본 프레임 번호·배속·타겟 FPS를 이력에 기록하며 결과는 기록된 FPS로 재생한다.
