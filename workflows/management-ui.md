# 관리도구 UI 가이드

관리도구의 새 페이지를 만들거나 기존 화면을 수정할 때 적용하는 UI·UX 기준이다. 공용 색상, 설정과 검수 화면의 배치, 생성 상태, 로그, 이력, 재생 동작을 일관되게 관리한다. 서비스별 명령·저장 경로·CLI 계약은 [관리도구 클라이언트 가이드](management-clients.md)를 따른다.

이 문서의 규칙은 신규·수정 UI의 기준이다. 기존 모든 페이지가 같은 컴포넌트로 전환되었다는 뜻은 아니다. 기존 구현과 차이가 있으면 해당 기능을 수정하는 범위에서 공용 구현으로 통합하고 검증한다.

## 게임 UI 검수의 렌더링 기준

- 게임 UI 검수는 프론트엔드가 사용하는 렌더링 라이브러리와 컴포넌트를 재사용한다. 같은 엔진만 도입하고 투영·타일 배치·고도 측면·캐릭터 표시를 관리도구에서 다시 구현하는 방식은 공용화로 보지 않는다.
- 공용 렌더러는 맵 데이터·에셋 URL·표시 설정을 입력받고 화면을 그린다. 관리도구는 입력 선택·검수 조작·상태 표시를 담당하며 게임 로그인·서비스 초기화에 의존하지 않는다.
- 저장소 경계를 지키기 위해 렌더러는 명시적인 버전과 공개 인터페이스가 있는 라이브러리로 제공한다. 관리도구 실행 중 인접 프론트엔드 소스를 읽거나 전체 프론트엔드를 빌드하여 복사하는 경로는 단계적으로 축소한다. 라이브러리 자체의 배포 빌드와 게임 전체 빌드는 구분한다.
- 맵·타일·스프라이트 변경은 원본 API와 등록부의 버전·해시를 통해 로딩한다. 에셋 내용만 바뀌었을 때 프론트엔드 빌드·관리도구 재시작·렌더러 재배포를 요구하지 않는다. 렌더러 코드 변경은 별도 라이브러리 버전 갱신으로 적용한다.
- 맵·타일·고도 측면을 우선 전환하고 캐릭터·전투 표시로 확대한다. 각 전환에서 게임과 검수의 투영·크기·겹침 순서·동일 에셋 해시를 확인한 뒤 해당 중복 구현과 기존 빌드 경로를 제거한다.
- 필드맵은 `@slime/field-renderer`의 동일 Phaser 구현으로 지면·절벽·계단·결계탑·오러를 그린다. 공용 `field-surface`가 고도·투영을 계산하며 검수는 에셋과 카메라·메시 표시 옵션을 전달한다. 캐릭터 재생·전투 표시·마을 건물과 다른 게임 UI는 별도 구현이 남아 있다. 부분 전환을 전체 UI 전환 완료로 보고하지 않는다.

## 1. 페이지 구성과 탐색

- 제목에는 도구의 목적을 표시하고, 바로 아래에 입력과 결과를 한 문장으로 설명한다.
- 데스크톱은 왼쪽에 입력·설정, 오른쪽에 미리보기·상태·결과를 배치한다. 생성 이력은 아래쪽 전체 너비를 사용한다.
- 생성 전에 확인할 수 있는 원본 에셋은 오른쪽 상단에서 검수한다. 생성 결과와 원본 에셋의 제목·컨트롤을 구분한다.
- 설정 영역에는 사용자가 선택에 필요한 참조만 표시한다. 캐릭터 애니메이션의 왼쪽에는 캐릭터 레퍼런스만 표시하고 첫 포즈 프레임을 중복 배치하지 않는다.
- 좁은 화면에서는 입력과 검수 영역을 세로로 배치한다. 긴 ID·경로·프롬프트는 줄바꿈하고 페이지 전체의 가로 스크롤을 만들지 않는다.
- 속성이 많은 편집기는 관련 속성을 그룹화한다. 속성 패널 높이를 미리보기와 맞추고 패널 안에서 스크롤한다. ‘기준값 복원’ 같은 전체 동작은 스크롤 영역 밖에 둔다.
- 페이지 등록과 메뉴는 기존 관리도구 구성을 따른다. 애니메이션 페이지는 [build_animation_tools.py](../tools/review/build_animation_tools.py)에서 관리한다. 폐기된 페이지의 메뉴나 우회 진입점을 다시 추가하지 않는다.

### Gradio 표준 정렬 목표 · 2026-10-06

현재 정렬 작업은 이 절의 기존 커스텀 스타일 기준보다 다음 기준을 우선한다. Gradio 기본 테마를 사용하며 옵션 CSS·테마 덮어쓰기·별도 색상·간격·크기 스타일을 폐기한다. 정렬은 `Row`·`Column`·`Group`·`Accordion`과 컴포넌트의 공개 파라미터로 구성한다. CSS를 제거한 빈자리를 새 CSS로 보완하지 않는다.

- 적용 범위: 공용 참조 이미지·시드·생성 ID·이력·로그·실행 버튼을 소비하는 Gradio 도구. MoMask를 먼저 확인한 뒤 Qwen 계열·심리스·바닥 타일·캐릭터 애니메이션·복장 분리 도구에 적용한다.

- 중복 통합: 같은 역할의 입력·참조 첨부·시드·생성 ID·이력 선택·로그·실행 버튼은 공용 빌더로 통합한다. 도구는 라벨·허용 값·기본값·콜백을 전달하며 페이지별 마크업·스타일 복제와 별도 이벤트 구현을 추가하지 않는다.

- 범위 구분: HTML을 Gradio 안에 삽입한 기존 편집기·정적 검수·맵·3D 화면은 독립 전환 대상으로 기록한다. 기능용 캔버스 및 재생 렌더링을 일반 입력 컴포넌트 스타일과 혼동해 삭제하지 않는다.

### 선택·입력 컴포넌트 대비

- `select`, `input`, `textarea`와 그 라벨은 페이지 배경·패널 배경과 구분되는 배경색, 전경색, 테두리를 함께 지정한다. 브라우저 기본 밝은 선택 상자가 다크 테마에 섞이지 않게 한다.
- HTML 선택란은 `management.css`의 공통 `review-select-control` 래퍼와 `review-select-arrow`를 사용한다. 네이티브 `select`의 ID·label 연결·키보드 동작을 유지하고, 우측 화살표는 `aria-hidden="true"`와 `pointer-events:none`으로 표시한다. 페이지별 배경 이미지 화살표를 중복 구현하지 않는다. Gradio 선택란은 프레임워크 기본 드롭다운을 유지한다.
- 선택 상자의 현재 값, placeholder, 비활성 값, 펼친 `option` 목록을 각각 확인한다. 현재 값만 보이고 드롭다운 항목이 읽히지 않는 구현은 허용하지 않는다.
- 비활성 상태는 낮은 대비가 아니라 읽을 수 있는 보조 전경색과 구분 가능한 배경·테두리로 표현한다. 비활성 사유는 가까운 안내로 제공한다.
- 포커스는 색상 대비가 충분한 외곽선으로 표시하며, 키보드 포커스와 마우스 선택의 시각 상태를 동일하게 확인한다.
- 단독 검수 HTML은 공용 스타일을 연결한 뒤에도 브라우저 기본 폼 스타일에 의존하지 않는다. 도메인 CSS에는 필요한 폼 상태만 보완하고, 공용 토큰을 임의의 하드코드 색으로 대체하지 않는다.

### 전역 스타일 적용 계약

- 시각 기준은 MoMask 생성기다. 정식 원본은 `tools/review/ui/shared/management.css`, 웹 공용 주소는 `/management/style.css`다. 생성기·작가 에이전트는 이 주소를 직접 연결한다.
- 색상 토큰 → 기본 타이포그래피·입력·버튼 → 패널·로그·상태·이력·탐색 컴포넌트를 전역 CSS에서 관리한다. 페이지별 CSS는 열 개수·미리보기 크기·스크롤 영역 같은 도메인 배치를 맡는다.
- 주요 버튼에는 `primary`, 위험 동작에는 `danger`, 패널에는 `studio-panel`을 사용한다. 키보드 포커스·hover·disabled·선택 상태도 공용 규칙을 따른다.
- 폼 컴포넌트 변경 시 밝은·다크 시스템 색상 모드와 데스크톱·좁은 화면에서 `select`의 현재 값·옵션·disabled·focus 대비를 확인한다.
- 기존 `generation-studio.css`와 서비스별 `studio.css` 주소는 호환 연결로만 남긴다. 새 색상이나 컴포넌트를 이 파일에 추가하지 않는다.
- 검수 페이지와 관리 셸은 `read_review_shared_styles()`로 전역 CSS와 `review-ui.css` 배치를 함께 삽입한다. 생성된 HTML을 단독으로 열어도 색상이 유지된다. 과거 산출물은 재빌드해야 반영된다.
- 게임 캔버스·타일·이미지의 색과 투명도 검수용 배경은 UI 색상과 구분한다. 전역 테마 때문에 실제 산출물 색을 바꾸지 않는다.
- 변경 시 MoMask·ANNY·캐릭터 애니메이션·Qwen 두 페이지·작가 에이전트·관리 셸에서 로딩, 공통 색상, 좁은 화면 넘침을 확인한다. 실제 생성·취소는 스타일 검증에 사용하지 않는다.

## 3. 입력과 고정 설정

- 입력마다 보이는 라벨을 둔다. placeholder만으로 용도를 설명하지 않는다.
- 모션·캐릭터 레퍼런스·포즈 입력·생성 방향처럼 의미가 다른 설정을 별도 항목으로 표시한다.
- 방향은 전체 선택과 개별 선택을 지원한다. 화면에는 ‘전방 좌측·전방 우측·후방 좌측·후방 우측’처럼 사람이 이해할 수 있는 명칭을 사용한다.
- 고정 프롬프트는 기본·보조로 나누어 항상 표시하고 수정 가능한 입력처럼 보이지 않게 한다. 방향별 보조 프롬프트는 선택한 방향에 실제 적용할 내용을 표시한다. 서버에서도 프롬프트 변경 요청을 거절한다. 프롬프트를 출력하는 모든 화면은 아래 단어 수 표시 규칙을 따른다.
- 잠금 속성에는 잠금 표시와 기준값을 보여주고 조작을 비활성화한다. 기준값 복원도 잠금 규칙을 따른다.
- Seed처럼 재현성에 사용하는 정수 입력에는 현재 값을 직접 편집할 수 있는 입력과 **무작위 생성** 버튼을 함께 둔다. 무작위 생성은 서비스가 허용하는 전체 범위의 정수만 설정하며, 생성 요청과 이력에 최종 Seed를 그대로 보존한다.
- 타겟 FPS는 원본 시간축에서 초당 생성할 장수와 결과의 기본 재생 FPS를 결정한다. 원본 FPS를 초과하는 값은 보간 지원 전까지 거절한다. 검수 재생 속도 변경은 생성 장수를 바꾸지 않는다.
- 생성 장수는 원본 프레임 수·간격·선택 방향을 기준으로 계산해 표시한다. 예: 대기 16프레임·원본 4 FPS, 타겟 2 FPS, 네 방향 → 방향당 8장·4초, 총 32장.

모델·실행기 경로 등 구현 세부사항은 사용자의 선택이나 문제 해결에 필요할 때 표시한다. 용도를 알 수 없는 상태 태그·빈 버튼·중복 설명을 넣지 않는다.

### 참조 이미지 첨부 컴포넌트

참조 이미지 첨부기는 생성 결과 미리보기나 생성 이력 썸네일과 구분되는 공용 입력 컴포넌트다. 페이지마다 입력 방식이나 슬롯 동작을 새로 정의하지 않는다.

- **입력 경로:** 파일 드롭, 클릭 업로드, **클립보드 이미지 붙여넣기**를 기본으로 제공한다. 세 경로는 같은 슬롯·검증·저장 계약을 사용하며, 클립보드 입력을 페이지별 선택 기능으로 빼거나 별도 전환 화면을 요구하지 않는다.
- **슬롯 구성:** 여러 이미지를 받으면 최대 개수와 `참조 이미지 1`처럼 순번을 표시한다. 넓은 화면에서는 가능한 슬롯을 같은 행에 균등 배치하고, 폭이 부족하면 다음 행 또는 한 열로 자연스럽게 전환한다. 페이지·패널·접이식 영역에 가로 스크롤을 만들지 않는다.
- **빈 상태:** 각 슬롯 전체를 드롭·클릭 가능한 영역으로 사용하고 `이미지를 여기에 드롭 또는 클릭하여 업로드` 안내를 읽을 수 있게 표시한다. 업로드와 클립보드 동작은 아이콘만 두지 않고 `파일 업로드`, `클립보드 붙여넣기`처럼 텍스트를 함께 표시한다. 아이콘은 충분한 크기·대비와 접근성 이름을 가져야 한다. 카메라처럼 작업에 필요하지 않은 입력 원본은 기본으로 노출하지 않는다.
- **선택 상태:** 선택한 이미지는 슬롯 안에서 원본 비율을 유지해 미리보기로 표시하고, 교체·제거 동작을 제공한다. 선택 전 안내·버튼·아이콘이 이미지를 가리거나 슬롯 밖으로 넘치지 않게 한다.
- **검증과 기록:** 허용 파일 형식·용량·개수 제한과 실패 사유를 해당 슬롯 가까이에 표시한다. 실제 요청에는 슬롯 순서대로 이미지를 전달하고, 참조 이미지의 출처·순서·해시는 실행 요청과 생성 이력에 보존한다.
- **검수 범위:** 빈 슬롯, 파일 드롭, 파일 선택, 클립보드 붙여넣기, 이미지 교체·제거, 최대 개수, 긴 파일명, 좁은 화면을 확인한다. 시각 검수에서는 사용자 파일을 업로드하거나 실행 중인 생성을 덮어쓰지 않는다.

## 4. 생성 버튼과 실행 상태

| 상태 | 주요 버튼 | 필수 안내 |
| --- | --- | --- |
| 초기 조회 | 생성 비활성화 | 생성 가능 여부를 확인 중임을 표시 |
| 입력 부족 | 생성 비활성화 | 부족한 입력과 해결 방법 표시 |
| 생성 가능 | 생성 활성화 | 생성 가능 상태 표시 |
| 요청 전송 | ‘생성 시작 중…’ 비활성화 | 접수 중임을 표시하고 중복 제출 방지 |
| 실행·대기 중 | 새 생성은 활성화, 생성 이력에서 작업 중지 제공 | 새 요청은 확인 후 대기열에 추가하고 작업 ID·순서·진행률·로그 이동 제공 |
| 취소 요청 | 취소 중 안내 | 서버가 취소를 확정할 때까지 실행 상태 추적 |
| 완료·실패·취소 | 유효한 입력이면 생성 활성화 | 최종 상태와 결과 또는 오류·로그 표시 |
| 조회 실패 | 오류·재조회 안내 | 통신 오류를 작업 완료나 취소로 취급하지 않음 |

비활성 버튼 옆에는 **왜 사용할 수 없는지와 어떻게 해소되는지**를 표시한다. 툴팁에만 사유를 숨기지 않는다. 관련 안내는 `aria-describedby`로 버튼과 연결한다.

완료 이미지 수(장), 원본 프레임 번호(번), 현재 방향의 생성 순서(번째), 현재 이미지의 추론 스텝을 구분한다. 전체 장수와 설정 요약은 실행 요청에 저장된 값을 기준으로 표시한다. 완료 이미지 비율을 전체 진행률로 사용하고 추론 스텝 비율을 전체 작업 비율로 표시하지 않는다. 생성 간격으로 원본 번호가 불연속이어도 결과 재생 순번과 혼동하지 않게 한다.

진행 상태와 로그는 자동 갱신한다. 프레임 작업은 완료 수/전체 수를 표시하고, 진행률을 알 수 없는 모델 준비 단계에서는 불확정 진행 표시를 사용한다. 실제 완료 전 100% 또는 ‘완료’를 표시하지 않는다.

페이지 재진입 시 서비스의 실행 상태를 조회해 현재 작업에 연결한다. 브라우저 메모리만으로 실행 여부를 판단하지 않는다. 생성 중에도 입력을 검토할 수 있으나 변경한 입력은 이미 접수된 작업에 적용하지 않는다. 작업 ID와 실행 당시 설정은 결과·이력에서 확인할 수 있어야 한다.

## 5. 로그

Gradio 접이식 로그의 기준 구현은 [gradio_logs.py](../tools/review/common/gradio_logs.py)의 `build_execution_logs`와 `bind_execution_log_updates`다. 기존 독립 HTML은 `management_log_viewer.py`를 사용한다.

- Gradio의 ‘최신 줄 따라가기’ 옵션은 폐기한다. 자동 갱신과 수동 ‘마지막 줄로 이동’을 제공한다.
- 자동 갱신을 끄면 현재 표시 내용을 유지한다. 갱신 시 강제로 마지막 줄로 이동하지 않는다.
- 로그 영역 자체를 스크롤하며 페이지 전체를 강제로 이동시키지 않는다.
- 페이지의 현재 작업 로그와 이력에서 선택한 작업 로그를 구분한다.
- 로그는 실행 파일에 누적 보관한다. 화면에서 일부만 표시하더라도 원본 파일을 잘라 저장하지 않는다.
- 실행 실패 시 실패 상태와 원인을 표시하고 해당 로그에 접근할 수 있게 한다.

이력 공용 UI는 공용 로그 컴포넌트의 조회·갱신·수동 스크롤 동작을 사용한다. 새 페이지에서 별도의 구현을 복제하지 않는다.

## 6. 생성 이력

기준 시나리오는 MoMask의 목록·결과 재생 흐름이며, 이미지 생성기의 참조 복원·결과 조회 장점도 기능에 맞게 사용한다. Gradio 공용 이력 구현은 [gradio_history.py](../tools/review/common/gradio_history.py)이며, 기존 HTML 화면은 [generation-history.js](../tools/review/ui/shared/generation-history.js)를 사용한다.

- 선택 전 안내는 한 번만 표시한다. 결과 조회 전에는 빈 결과 공간을 만들지 않으며, 이력 0건은 생성 시작 안내를 표시한다.
- 이력은 서버에 누적 저장하고 새로고침·서버 재시작 이후 다시 조회한다.
- 이력 카드 목록은 최초 진입·수동 새로고침·페이지 이동에서 갱신한다. 주기적으로 목록 전체를 재렌더링하지 않는다. 선택 작업의 상태·실행 로그 갱신은 별도로 유지한다.
- Gradio 공용 이력은 기본 `Dropdown`으로 선택하고 `Dataframe`으로 상태·시각·설정·진행·ID를 비교한다. 결과 썸네일은 기본 `Gallery`로 표시한다. 페이지당 8건이며 아래 카드 세부 규칙은 미전환 HTML 화면에만 적용한다.
- 카드는 **상단: 작업명·상태·생성 시각 / 본문: 설정 이름과 값 / 하단: 생성 ID·선택 상태**로 구분한다. 메타데이터를 긴 한 문장으로 이어 붙이지 않는다. 상태는 `생성 중`, `GPU 대기 중`, `완료`, `중지됨`, `실패`로 표기하고 생성 시각은 초 단위까지만 표시한다. 색상만으로 상태를 구분하지 않는다.
- 목록 요약은 긴 원문 배열·JSON을 그대로 출력하지 않는다. 예를 들어 방향은 `방향 4개`로 축약하고, 프레임 생성은 `프레임 1–120`, 모션 생성은 모션명, 이미지 생성은 해상도·스텝처럼 작업 판단에 필요한 값만 표시한다. 전체 요청·프롬프트·경로는 선택 후 상세에서 조회한다.
- 생성 결과를 같은 종류 안에서 구분해야 하는 도구는 선택형 **생성 이력 태그** 입력을 제공한다. 태그는 짧은 사람용 이름(줄바꿈 없이 최대 80자)으로 요청·이력에 보존하고 목록 요약의 앞부분에 `태그 <값>`으로 표시한다. 태그는 모델 프롬프트·시드·생성 파라미터를 변경하지 않으며, 입력값 불러오기에서 함께 복원한다. 태그를 비워도 생성·이력 조회는 동일하게 동작한다.
- 목록 도구 모음은 새로고침·페이지·전체 건수를 먼저 배치하고, 썸네일은 해당 이력 카드 내부에 표시하며 목록 위에 별도 갤러리를 두지 않는다. 이력을 선택하면 상태·ID·핵심 설정 요약과 결과 조회·입력 복원 동작을 함께 갱신한다.
- 결과 조회 진입점은 선택 이력 카드의 `결과 조회` 하나로 통일한다. 생성 ID를 다시 입력하는 별도 결과 조회 폼·접이식 패널을 만들지 않으며, 현재 생성 ID는 실행 상태 확인과 복사 용도로만 표시한다.
- 선택 이력이 없으면 선택 요약과 행동 버튼 영역을 숨긴다. 카드를 선택하면 해당 카드 바로 아래에 표시하며, 초기화·개별 삭제·페이지 이동으로 선택이 사라지면 다시 숨긴다. 다른 카드를 선택하면 행동 영역도 함께 이동하고 자동 갱신은 유효한 선택을 유지한다.
- 선택 행동은 **선택한 카드 바로 아래**에 동일 너비 **6열**로 배치한다. 순서는 `결과 조회` → `입력값 불러오기` → `생성 재개` → `우선 실행` → `작업 중지` → `선택 이력 삭제`다. Gradio 표준 Row를 사용하며 결과 조회만 기본 강조한다. 삭제 시 대상 ID와 범위를 확인한다.
- `우선 실행`은 모든 생성기의 공통 기본 기능이다. GPU 대기(`queued`) 작업만 공용 게이트웨이 `prioritize`로 대기열 맨 앞으로 이동한다. 실행 중 작업의 선점·취소·예약 변경은 하지 않으며 VRAM 확보 전 즉시 실행을 보장하지 않는다. 비활성 버튼은 대기 작업 선택을 안내한다. 실행 예약과 같은 잠금으로 상태를 재검증하며 GUI·CLI·대기열 조회는 동일한 순서를 사용한다.
- 공용 생성 이력에서 `작업 중지`를 제공하는 화면은 설정·미리보기·결과 영역에 별도의 `생성 취소` 버튼을 중복 배치하지 않는다. 대기·실행 작업을 이력에서 선택한 뒤 중지하며, 선택한 작업 ID를 대상으로 취소 요청을 전달한다. 재생 컨트롤의 `중지`는 영상 재생만 멈추는 별도 기능으로 유지한다.
- **조회한 생성 ID와 복사 기능은 결과 상태·재생 영역 위의 접이식 영역 밖에 표시**한다. 기록 폴더 경로·폴더 열기·저장 입력은 그 아래 `기록 위치 · 저장 입력` 접이식 상세에 모으며 기본으로 접는다. ID와 경로는 각각 전체 폭을 사용한다. 빈 ID·경로 입력란이나 ID 직접 결과 조회 폼을 목록 앞에 배치하지 않는다.
- 전체 순서는 **생성 이력 제목 → 건수·새로고침·이전/페이지/다음 → 카드 목록(선택 카드 바로 아래에 선택 요약·행동) → 조회한 생성 ID·복사 → 결과 상태 → 이미지·재생기 → 접이식 기록·로그 → 수동 초기화**다. 단일 화면에 불필요한 탭 제목을 반복하지 않는다. 초기화는 탐색·결과 조회와 떨어진 마지막 접이식 영역에 배치한다.
- Gradio 이력은 `common/gradio_history.py`, 결과 갤러리는 `common/gradio_results.py`에서 관리한다. 기본 테마와 `Row`·`Column`을 사용하며 CSS를 주입하지 않는다. 기존 HTML 이력만 `management.css`를 사용한다. 페이지별 이력 구현을 복제하지 않는다.
- 공용 생성 이력의 각 항목에는 기록 폴더의 절대 경로·경로 복사·기록 폴더 열기를 제공한다. 폴더 열기는 관리 서버 컴퓨터의 파일 관리자를 호출하며, GUI 환경이 없으면 실패 사유와 경로 복사 안내를 표시한다. 서버는 생성기·ID로 등록 저장소 안의 기록을 확인하며 클라이언트가 임의 파일 경로를 실행할 수 없게 한다.
- 완료된 결과는 생성 당시 데이터로 열거나 재생한다. 현재 입력을 바꿔도 과거 결과의 모션·방향·프레임 해석이 바뀌지 않는다.
- 생성이력에는 **입력값 조회**와 **입력값 불러오기**를 별도 동작으로 제공한다. 조회는 저장된 요청과 실행 당시 프롬프트를 표시하며 현재 설정을 바꾸지 않는다. 불러오기는 사용자가 명시적으로 누를 때 지원하는 입력란만 복원하고 생성을 시작하지 않는다. 결과 조회가 입력을 자동으로 덮어쓰지 않게 한다.
- 고정 설정·폐기된 옵션 등 복원할 수 없는 입력은 원문 조회를 유지하고 제한을 설명한다. 고정 프롬프트가 현재 설정과 다르면 차이를 안내하며 과거 입력을 현재 설정으로 재해석하지 않는다. Gradio의 별도 이력 화면은 `common/gradio_history.py`의 `build_history_input_controls`를 재사용한다.
- 선택한 이력, 현재 페이지, 펼친 상세는 자동 갱신으로 불필요하게 초기화하지 않는다.
- **생성이력 전체 초기화는 이력 목록과 해당 생성기의 결과·실행 기록을 함께 삭제하는 동작**이다. 사용자의 명시적 수동 동작으로만 수행하며, 확인 문구에 `.tmp` 작업 폴더의 입력·참조 사본·중간 산출물·최종 결과·상태·로그까지 삭제됨을 명시한다. 이전에 목록에서만 제거된 작업 폴더도 삭제 범위에 포함한다.
- 삭제 범위는 해당 생성기가 소유한 작업 폴더와 이력 저장소로 한정한다. 다른 생성기의 기록, 정식 등록 에셋·재사용 제작 자산, 모델 캐시, 사용자가 첨부한 원본 파일은 삭제하지 않는다. 실행·대기 중이거나 종료 여부를 확인할 수 없는 작업이 있으면 삭제 전에 거절하고 사유와 해결 방법을 안내한다.
- GUI와 CLI는 같은 공용 명령 게이트웨이·작업 서비스에서 동일한 삭제 범위를 적용한다. 초기화한 이력·결과 기록은 자동 복원하지 않는다. 목록만 제거하는 기능은 `이력 목록만 비우기`처럼 별도 이름과 파일 보존 안내를 사용하며 `전체 초기화`로 표시하지 않는다.

기존 HTML 공용 이력 연결 시 `#generation-history`와 `data-route`를 제공한다. 애니메이션 결과는 `playable`과 `window.playGenerationRecord` 연결을, ANNY 입력 복원은 기존 `restoreGenerationRecord` 연결을 확인한다. 서비스별 응답을 확인하지 않고 공용 UI를 복사해 사용하지 않는다.

## 7. 에셋·결과 재생

- 방향 선택, 재생, 중지, 이전·다음 한 프레임, 위치 슬라이더, 현재/전체 프레임 번호를 제공한다.
- 재생 속도는 4·8·12·16 FPS를 선택할 수 있게 한다. 기본은 4 FPS이며 재생 중 변경할 수 있다. 검수 속도 변경은 원본이나 생성 메타데이터를 수정하지 않는다.
- 원본 OpenPose와 ANNY는 나란히 표시하고 같은 프레임으로 동기 재생한다. 두 이미지가 모두 준비된 뒤 화면을 갱신한다.
- 검수 방향은 생성 방향 선택과 독립적으로 바꿀 수 있다. 원본 검수는 타겟 FPS에 관계없이 전체 프레임을 사용한다.
- 모션·방향을 바꾸면 이전 재생과 진행 중 이미지 요청의 영향을 차단하고 새 프레임으로 전환한다. 늦게 도착한 응답이 새 선택을 덮어쓰지 않도록 한다.
- 긴 모션은 제한된 수의 프레임을 캐시하고 필요한 프레임을 미리 읽는다. 전체 모션을 무조건 메모리에 적재하지 않는다.
- 파일 누락·로딩 실패는 검수 영역에 표시한다. 오래된 이미지를 새 결과처럼 표시하지 않는다.

현재 원본 에셋과 생성 결과 재생은 [character_animation_app.py](../tools/review/ui/gradio/character_animation_app.py)의 Gradio 결과 플레이어를 기준으로 한다. 다른 페이지에서 같은 기능이 필요하면 공용 플레이어로 추출해 함께 사용한다.

## 9. 접근성과 검증

기본 HTML의 `button`, `label`, `select`, `details`, `progress`를 활용한다. 모든 컨트롤은 키보드로 조작할 수 있게 하고 포커스 표시를 유지한다. 상태 안내에는 `role="status"`, 슬라이더·캔버스에는 의미 있는 접근성 이름을 사용한다. 고빈도 로그 전체를 스크린리더에 계속 읽히게 만들지 않는다.

변경 범위에 맞게 다음을 검증한다.

1. 데스크톱·좁은 화면에서 입력, 결과, 이력이 잘리지 않고 읽히는가?
2. 생성 버튼의 비활성 이유가 보이며 입력 충족·작업 종료 후 활성화되는가?
3. 재진입 시 실행 작업을 찾고, 조회 오류·취소 요청·완료 상태를 구분하는가?
4. 로그 펼침과 자동 갱신이 마지막 줄을 표시하는가?
5. 과거 결과 선택, 페이지 이동, ID 복사가 올바른가? 생성이력 전체 초기화가 이전에 목록에서 제거한 작업까지 포함해 결과·실행 기록을 삭제하고, 실행·대기 작업 및 다른 생성기·정식 자산을 보호하는가? GUI/CLI의 삭제 범위와 안내가 일치하는가?
6. 모션·방향·FPS 변경, 중지, 한 프레임 이동이 의도대로 동작하는가?
7. GUI·CLI가 같은 요청과 이력을 사용하며 수정 불가 설정을 서버에서도 검증하는가?

브라우저 콘솔 오류, 잘못된 파일 요청, 자바스크립트 문법과 관련 계약 테스트를 확인한다. 생성·취소 테스트에는 모의 응답이나 별도 테스트 기록을 사용해 사용자의 실행 작업을 건드리지 않는다. 실제 GPU 생성 품질 검증과 UI 모의 검증을 구분해 보고한다. 단순 문구·스타일 수정에 구현을 그대로 반복하는 테스트를 추가하지 않는다.

## 공용 작업 영역 탐색

[management-workflow.js](../tools/review/ui/shared/management-workflow.js)는 `data-workflow-label`이 지정된 영역으로 이동하는 공용 메뉴를 만든다. `data-help-title` 영역은 접이식 도움말로 표시한다. 이동은 생성·취소·입력 변경을 실행하지 않는다. 캐릭터 애니메이션, MoMask, ANNY, Qwen 두 화면에 적용하며 키보드 포커스와 모션 감소 설정을 반영한다. 공용 이력 UI는 ID·입력 검색과 상태 필터를 제공하고, 필터 변경 시 첫 페이지로 이동한다. MoMask의 기존 전용 이력은 아직 이 검색 필터로 통합되지 않았다.



## 생성 예상 시간 표시 규칙

모든 생성기는 작업 서비스의 공용 추정 기능으로 예상 총 소요 시간·남은 시간·완료 시각과 현재 예상 진행률을 제공해야 한다. GUI·CLI는 게이트웨이가 제공한 같은 값을 사용한다. 이 규칙은 기존·신규 이미지·모션·렌더 생성기에 모두 적용하는 구현 의무다. 진행 이벤트와 최대 5초 간격 heartbeat마다 관측치를 반영하여 갱신한다.

실측 진행률과 예상 진행률은 구분해 표시한다. 예상 진행률에는 추정 범위·근거·표본 수·갱신 시각을 제공하고, 실측 분모가 없는 단계에 임의의 백분율을 표시하지 않는다.

- 실행 상태 가까이에 ‘예상 남은 시간’과 ‘예상 완료 시각’을 각각 배치한다. 시간 단위와 완료 날짜·시각을 함께 표시해 자정을 넘는 작업도 구분한다.
- 실측 근거가 생기기 전에는 ‘계산 중’과 계산이 가능한 조건을 안내한다. 근거 없는 숫자나 `0분`, `NaN`을 출력하지 않는다.
- 같은 작업의 완료 단위 처리 시간을 우선 사용한다. 기존 이력으로 시작 시 추정할 경우 모델·스텝·입력 크기·작업 종류 등 비교 조건을 맞추고 이력 기반 추정임을 표시한다.
- 추정 근거와 표본 수를 표시하고 완료 단위가 추가되면 갱신한다. GPU 대기·모델 준비·추론 시간이 추정에 포함되는 범위를 명확히 한다.
- 평균 처리 시간을 초과하면 지연 안내 후 재계산한다. 음수 시간이나 확정적인 완료 시각을 표시하지 않는다.
- 완료·실패·취소 시 예상 시간 갱신을 종료하고 최종 상태를 표시한다. 과거 이력 조회 때문에 실행 중인 작업의 예상 시간을 덮어쓰지 않는다.
- 화면 안내는 ‘약’·‘예상’ 표현을 사용하고 GPU 부하 등에 따라 달라질 수 있음을 설명한다.

현재 캐릭터 애니메이션 구현은 같은 작업의 최근 완료 이미지 최대 5장의 처리 시간을 사용한다. 첫 이미지 완료 전에는 계산 중으로 표시한다. 이는 현재 구현 사례이며 다른 모든 생성기에 이미 적용되었다는 뜻은 아니다.

## 프롬프트 단어 수 표시 규칙

기본·보조·방향별·최종 프롬프트 등 프롬프트 원문을 표시하는 UI는 해당 원문 옆에 단어 수를 함께 표시한다. 읽기 전용·편집 가능 여부와 관계없이 적용한다.

- 공백 기준으로 앞뒤 공백을 제거하고 연속된 공백·줄바꿈으로 나눠 센다. 빈 문자열은 0단어다. 단어 수를 모델 토큰 수로 표시하지 않는다.
- 기본과 보조의 개별 단어 수, 실제 모델에 전달하는 최종 결합 프롬프트의 합계를 구분한다.
- 방향·변수 치환과 추가 지시를 모두 적용한 최종 문자열을 기준으로 센다. 여러 방향은 각각 별도 입력이므로 전체 방향의 단어 수를 하나의 입력 합계로 더하지 않는다.
- 편집·방향 선택·기본 프롬프트 사용 여부 등이 바뀌면 원문과 단어 수를 함께 갱신한다.
- 이력의 프롬프트와 단어 수는 실행 당시 기록을 기준으로 표시한다. 현재 설정으로 과거 값을 재해석하지 않는다.
- 모델별 단어 수 제한이 있으면 적용 범위와 한도를 함께 안내한다. UI와 실행기의 계산 기준을 일치시키고 최종 원문·단어 수·해시는 실행 기록에 보존한다.

검증 시 빈 프롬프트·연속 공백·줄바꿈·방향 치환과 최종 합계를 확인한다. 예상 시간은 실측 없음·정상 진행·지연·종료 상태를 확인한다.

### 캐릭터 애니메이션 생성 배속

배속은 생성 설정이다. 기본 4 FPS·1배이며 1·1.5·2·4배를 제공한다. 생성 장수는 `ceil(원본 프레임 수 × 타겟 FPS / 원본 FPS / 배속)`이다. 타겟 FPS는 유지하며 생성 결과의 동작 시간이 짧아진다. 예: 16프레임·4 FPS 원본에서 2배·4 FPS로 생성하면 8장·2초다. 재생기에 별도의 배속 옵션을 표시하지 않는다. 원본 프레임 번호·배속·타겟 FPS를 이력에 기록하며 결과는 기록된 FPS로 재생한다.

### 전체 도구의 화면 밀도

- 모든 Gradio 진입점은 `tools/review/ui/shared/management-density.css`를 공용으로 적용한다. 개별 도구에 같은 여백 규칙을 복제하지 않는다.
- 작업 영역은 사용 가능한 화면 폭을 활용하고, 메뉴는 고정 폭과 독립 스크롤을 사용한다. GPU 상태 헤더는 스크롤 중에도 유지한다.
- 중복 제목과 긴 조작 설명을 줄이되, 필요한 안내는 펼쳐 볼 수 있게 한다. 입력·실행·취소·이력 기능을 공간 확보 목적으로 숨기지 않는다.
- 이미지 원본 크기와 게임 좌표 배율은 UI 여백 조정과 분리한다. 좁은 화면에서는 열을 세로로 배치하고 가로 넘침을 검수한다.

### 생성 이력 전체 폭 배치

생성 이력은 설정·미리보기의 분할 열 밖, 작업 영역 아래에서 가로 100%를 사용한다. 공용 `generation-history-workspace` 영역을 사용하며 조회·페이지네이션·입력 재사용·ID 복사·기록 경로·로그·수동 초기화 계약은 유지한다. 개별 생성기는 이력을 좁은 설정 열이나 결과 열 안에 배치하지 않는다.

### GPU 작업 이력 제어

생성이력은 `GPU 대기 중`, 실행, 완료, 실패, 중지 상태를 구분한다. 선택 작업의 중지 버튼은 대기열에서도 사용할 수 있다. 재개는 취소·실패 작업을 대상으로 하고 저장된 입력을 사용한다. 중지 요청 접수와 실제 종료를 구분하며, 대기 중에도 로그·상태 조회가 가능해야 한다. 대기 사유와 메모리 수치는 상태 기록에 보존한다.

### 상세 카드 선택 동작

- 넓은 화면에서는 여러 열, 좁은 화면에서는 1열로 표시한다. 카드 본문은 설정 이름과 값을 격자로 배치하고 긴 ID는 줄바꿈한다.
- 카드 전체를 클릭하거나 키보드로 선택한다. 선택 표시와 행동 버튼의 대상 ID를 일치시키며 자동 갱신에도 선택을 유지한다.
- 카드 선택은 결과 조회·생성·입력 복원을 자동 실행하지 않는다. 각 행동은 사용자가 해당 버튼을 눌렀을 때 실행한다.
- 기록에 없는 값은 임의 기본값으로 채우지 않는다. 프롬프트 원문·전체 입력·파일 경로는 접이식 상세에서 확인한다.

### 상세 카드 진행률

- 실행 중인 작업은 선택하지 않아도 이력 카드 안에서 진행률 막대·백분율·완료 수/전체 수를 확인할 수 있게 한다. 설정 요약 아래, 생성 ID 위에 배치하며 색상이나 막대만으로 표현하지 않는다.
- 진행률에는 범위를 명시한다. 예: `ANNY 렌더 90.5% · 579/640프레임 저장 · Fra:100`. 렌더 단계의 진행률을 모션 추론·후처리까지 포함한 전체 작업 진행률로 해석하지 않는다.
- MoMask의 전체 렌더 수는 해당 실행에 저장된 방향 수 × 방향별 출력 프레임 수로 계산한다. 완료 수는 선택한 모든 방향의 저장된 출력 프레임을 합산한다. 현재 UI 설정으로 과거 실행의 분모를 다시 계산하지 않는다.
- Blender 로그의 `Fra:N`은 최근 처리 중인 **원본 프레임 번호**다. 같은 번호의 로그가 여러 번 출력되거나 방향 전환 시 번호가 작아져도 완료 수를 중복 집계하거나 진행률을 되돌리지 않는다. 샘플 간격이 있는 경우에도 `Fra`를 출력 순번으로 사용하지 않는다.
- MoMask 생성 이력은 현재 공용 목록 갱신 주기인 3초마다 진행률을 갱신한다. 갱신 중에도 선택·페이지·스크롤 위치를 유지하고 결과 조회를 자동 실행하지 않는다.
- 분모나 실측 근거가 없는 모델 준비·추론 단계에는 임의의 백분율을 만들지 않는다. GPU 대기 상태와 렌더 진행률을 구분한다. 렌더가 100%여도 후처리 중이면 작업 상태는 실행 중으로 유지하며, 최종 완료는 작업 상태 기록을 따른다.
- 검증에는 다중 방향, 방향 전환, 반복 `Fra` 로그, 불연속 원본 프레임, 재개 시 기존 출력, 진행률 없는 준비 단계, 카드 자동 갱신을 포함한다.

### 상세 카드 썸네일

- 썸네일은 해당 생성 이력 카드 내부에 배치한다. 카드 목록 위의 별도 썸네일 갤러리는 사용하지 않는다. 왼쪽에는 이미지, 오른쪽에는 작업명·상태·시각·설정을 두고 ID와 선택 상태는 하단에 표시한다.
- 이미지 생성은 해당 작업의 결과 이미지를, 캐릭터 애니메이션은 해당 작업에서 실제 생성된 프레임을 사용한다. 입력 참조 이미지나 다른 작업의 결과를 결과 썸네일로 대신 표시하지 않는다. 생성 중·중지·실패 상태라도 생성된 프레임이 있으면 미리보기를 제공한다.
- 결과가 없는 대기·실행 작업은 `결과 준비 중`, 그 외 결과 이미지가 없는 작업은 `이미지 없음`으로 표시한다. 미리보기 존재 여부와 작업 완료 여부를 혼동하지 않도록 상태 표시는 유지한다.
- 원본 비율은 `object-fit: contain`으로 유지하고 이미지를 잘라내거나 늘리지 않는다. 좁은 화면에서도 이미지와 설정이 겹치지 않도록 공용 CSS의 크기 기준을 사용한다.
- 화면에 들어온 이미지를 지연 로딩하고 비동기로 디코딩한다. 카드 목록을 갱신할 때 썸네일 때문에 선택이나 페이지를 초기화하지 않는다.
- 썸네일 클릭은 카드 선택과 동일하게 처리한다. 결과 조회·재생·생성·입력 복원은 별도 행동 버튼으로 실행한다.
- 서비스는 이력 응답의 `image`에 해당 작업의 조회 가능한 이미지 경로를 제공한다. Gradio에서는 `collect_image_history_thumbnails`와 기본 `Gallery`로 공용 관리한다.

### 생성 버튼 중복 접수 방지

- 캐릭터 애니메이션은 요청 접수 중 버튼을 잠그고 `요청 접수 중…`을 표시한다. 접수 완료 후에는 즉시 버튼을 다시 활성화한다. 대기·생성 중에는 `대기열에 추가`로 표시하고 공용 GPU 실행 확인 모달을 거쳐 추가 요청을 접수한다.
- 요청 실패 또는 작업 완료·실패·중지 후에는 활성 버튼의 문구를 `애니메이션 생성 시작`으로 복원한다. 모달 확인 중에는 동일 이벤트를 반복 접수하지 않는다.
- GUI의 버튼 잠금만으로 중복 방지를 보장하지 않는다. 캐릭터 애니메이션 작업 서비스는 잠금 안에서 동일 입력의 대기·실행 작업을 확인하여 새 작업 대신 기존 ID를 반환한다. 완료된 작업은 같은 입력으로 다시 생성할 수 있다.
- 이 규칙을 다른 생성기로 확장할 때는 UI 이벤트뿐 아니라 서비스의 중복 요청 계약도 검증한다. 모든 서비스에 동일 입력 병합이 구현된 것으로 간주하지 않는다.

### GPU 대기열 실행 확인 모달

- 새 생성·재개 요청 전에 실제 GPU 사용 상태와 살아 있는 GPU 대기 작업을 확인한다. GPU가 유휴이고 대기 작업이 없으면 확인 없이 진행하고, GPU 사용 중 또는 대기 작업이 있으면 **GPU 작업 대기열에 추가할까요?** 모달을 표시한다.
- 모달에는 GPU 사용 중인 작업과 대기 작업의 종류·ID를 구분해 표시하고, 접수 순서대로 실행 가능 여부를 확인하며 GPU 메모리 여유가 있으면 동시에 실행된다는 설명을 표시한다.
- `대기열에 추가`를 누른 경우에만 생성·재개 명령을 전달한다. `추가하지 않기` 또는 Esc는 접수하지 않고 닫는다. 기본 포커스는 `추가하지 않기`에 둔다.
- 대기열 조회 실패 시 자동 실행하지 않고 오류를 안내한다. 모달은 작업 실행 잠금이나 메모리 검사를 대체하지 않으며, 실행 순서는 공용 GPU 작업 서비스가 관리한다.
- 공용 구현은 [gradio_gpu_confirmation.py](../tools/review/common/gradio_gpu_confirmation.py)와 [gpu-queue-confirmation.js](../tools/review/ui/shared/gpu-queue-confirmation.js)다. Gradio 생성·재개 버튼은 `bind_gpu_generation_confirmation`으로 연결하고 ANNY HTML 화면도 같은 확인 함수를 사용한다.

### 검증 항목

- 카드의 빈 목록·복수 항목·긴 ID·키보드 선택·페이지 이동·자동 갱신과 좁은 화면의 가로 넘침을 확인한다.
- 썸네일의 작업 ID와 실제 결과 경로가 일치하는지 확인한다. 결과 있음·없음, 생성 중 부분 결과, 화면 진입 후 이미지 로딩, 썸네일 클릭 선택을 검증하고 별도 갤러리가 남아 있지 않은지 확인한다.
- 연속 클릭 시 작업이 하나만 생성되는지, 요청 실패 뒤 버튼이 복구되는지, 완료 후 같은 입력으로 다시 생성할 수 있는지 확인한다.
- 대기열 없음·대기 작업 있음·조회 실패를 각각 확인한다. 모달 취소·Esc에서는 생성 명령이 호출되지 않고, 승인 시 한 번만 호출되어야 한다.
- UI 검증을 위해 사용자의 실행 중 작업을 중지하거나 새 GPU 작업을 생성하지 않는다. 요청 모의와 임시 저장소 테스트를 사용한다.

### 이력 페이지 이동 도구

- 건수·현재/전체 페이지는 왼쪽, 새로고침·이전·페이지 이동·다음은 오른쪽에 배치한다. 버튼과 숫자 입력은 같은 높이로 맞추며 페이지 입력의 장식용 라벨·컨테이너를 제거한다. 접근성 이름은 유지한다.
- 첫 페이지의 이전, 마지막 페이지의 다음은 비활성화한다. 한 페이지뿐이면 페이지 입력도 비활성화하고, 직접 입력한 페이지는 유효 범위로 제한한다.
- 좁은 화면에서는 건수 안내를 별도 줄로 배치하고 이동 버튼의 글자를 줄바꿈하지 않는다. 페이지 변경·초기화·자동 갱신 모두 같은 공용 상태 갱신을 사용한다.

- 페이지네이션은 보조 탐색 도구이므로 건수·페이지·버튼 글자는 **12px, 보통 굵기**, 버튼·입력 높이는 **32px**로 통일한다. 제목·생성 실행 버튼처럼 크게 강조하지 않는다. 이 기준은 공용 `.generation-history-toolbar`에만 적용하며 이력 카드 본문과 주요 실행 버튼에는 적용하지 않는다.

### 캐릭터 애니메이션 생성 영역

- 생성 설정과 미리보기·결과 영역은 좌우로 나누지 않고 **설정 → 미리보기·결과** 순서의 1열로 배치한다. 각 영역은 사용 가능한 전체 너비를 사용한다. 시작·종료 프레임 등 관련 입력 쌍은 영역 내부에서 나란히 배치할 수 있다.

- 미리보기 로딩 전에는 빈 이미지·탐색 슬라이더를 숨기고 안내와 불러오기 버튼만 표시한다. 미리보기 높이는 콘텐츠에 맞추며 고정 높이로 여백을 예약하지 않는다. 빈 생성 ID 입력이나 이력 결과 조회와 중복되는 빈 결과 안내는 생성 영역에 배치하지 않는다.

- 생성 이력 제목·도구 모음·카드 목록 사이 간격은 8px로 유지한다. 도구 모음에는 별도 상하 패딩이나 문단 기본 여백을 두지 않는다. 카드 안쪽 여백은 10px, 정보 간격은 4px로 구성하고 썸네일·상태·설정·ID의 가독성을 유지한다.

### 생성 화면 구성과 정보 우선순위

- 캐릭터 애니메이션은 **생성 설정 → 입력 포즈 미리보기(접기) → 생성 시작·상태 → 실행 로그(접기) → 생성 이력·결과 조회** 순서로 구성한다. 설정과 결과를 긴 좌우 열로 나누지 않는다.
- 모션·캐릭터, 포즈 입력·생성 방향, 시작·종료 프레임, 해상도·스텝, FPS·생성 배속은 관련 입력끼리 묶는다. 좁은 화면에서는 입력 행이 자연스럽게 줄바꿈되어야 한다.
- 미리보기 방향은 생성 방향과 구분하여 미리보기 영역 안에 둔다. 미리보기는 기본 접힘 상태이며 사용자가 불러오기를 눌러 준비한다. 펼치기나 설정 변경만으로 GPU 생성을 시작하지 않는다.
- 생성 실행 버튼은 입력 포즈 미리보기 다음에 한 번만 둔다. 사용자가 설정과 미리보기를 확인한 뒤 생성하도록 배치하며, 미리보기를 접어도 생성 버튼은 항상 노출한다. 작업 중지는 이력에서, 결과 재생은 선택 결과에서 제공한다. 빈 생성 ID·빈 결과 안내·고정 높이 빈 플레이어를 중복 배치하지 않는다.
- 공용 이력 카드·페이지네이션·로그 스타일은 공용 모듈에서 관리하고 페이지 전용 CSS로 덮어쓰지 않는다. 여백을 줄일 때 접근성 이름, 선택 상태, 오류 안내와 핵심 설정은 유지한다.

### 선택 이력 개별 삭제

- 캐릭터 애니메이션은 공용 이력에서 항목을 선택한 뒤 `선택 이력 삭제`를 제공한다. 동의 모달에 대상 ID와 삭제 범위를 명시하고 취소하면 변경하지 않는다.
- 현재 삭제 범위는 이력 목록의 해당 항목이다. 결과·참조 사본·로그 파일은 보존한다. 대기·실행 작업은 먼저 중지해야 하며 서버에서도 삭제를 거절한다. 삭제 후 목록·페이지 범위를 갱신하고 선택 결과를 비운다.
- GUI와 CLI는 `character-animation history-delete <id>` 공용 명령을 사용한다. 다른 도구는 서비스에서 개별 삭제를 지원할 때 공용 UI 옵션을 연결한다.

### 선택 카드의 행동 영역

- 선택 정보와 결과 조회·입력값 불러오기·생성 재개·작업 중지·개별 삭제는 **선택한 카드 바로 아래**에 표시하고 나머지 카드는 그 뒤에 이어서 배치한다. 미선택 상태에는 해당 영역을 숨긴다.
- 다른 카드를 선택하면 행동 영역도 해당 카드 아래로 이동한다. 페이지 이동·삭제·초기화로 선택이 사라지면 숨기며, 자동 갱신은 유효한 선택을 유지한다. 행동 버튼은 기존 작업 상태별 활성 조건과 삭제 동의 모달을 유지한다.

- 결과 조회 영역의 표시 순서는 **조회한 생성 ID·복사 → 결과 상태 → 이미지·재생기 → 기록 위치·저장 입력(접기)**로 통일한다.

- `결과 조회`가 성공하면 조회한 생성 ID를 기준으로 결과 영역 시작 위치로 자동 스크롤한다. 카드 선택·주기적 갱신·조회 실패에서는 이동하지 않으며, 동작 줄이기 설정에서는 부드러운 스크롤을 사용하지 않는다.

### 관리도구 주소 규칙

- 관리도구 루트 페이지는 `/`다. 도구 선택은 `/?tool=<등록 ID>` 쿼리 파라미터로 통일한다. 예: `/?tool=animation-1`, `/?tool=character-animation`.
- `/animation-1/anchors.html` 등의 파일·서브패스는 공개 메뉴 링크로 사용하지 않는다. 기존 주소로 진입하면 해당 도구의 루트 쿼리 주소로 정규화한다.
- `tool`은 선택 도구, `search`·`category`는 목록 필터다. 도구와 충돌하는 초기 필터는 해제하고 다른 도구로 대체하지 않는다.
- 초기 선택은 목록 순번 대신 등록 ID로 처리한다. 메뉴 선택은 루트 경로를 유지하며 쿼리를 갱신한다.
- `/management/frame/`과 실제 정적 파일 경로는 내부 콘텐츠 로딩에만 사용한다.

### GPU 메모리 기반 동시 실행

공용 대기열은 실행 허가·메모리 예약 시에만 잠금을 잡는다. 실행 중인 작업의 예약량 중 아직 사용하지 않은 부분과 안전 여유 512 MiB를 실측 여유 메모리에서 차감해 다음 작업의 실행 여부를 판단한다. 예약은 종료·실패·취소 처리 후 해제한다. 현재 사용량이 작아도 모델 로딩 중 증가를 고려해 예약량을 유지하며, 대기 사유에 실측 여유·예약량·추가 실행 가능량을 기록한다. 기존 실행 프로세스는 중단하지 않으며 새 대기열 실행기부터 이 정책을 사용한다.

명령별 GPU 메모리 집계는 실행 종료마다 갱신하며 서비스와 실행 스크립트·모듈별 최근 20회만 유지한다. 오래된 측정 기록만 정리하고 생성 결과와 실행 이력은 보존한다. 실패·취소·측정 오류도 20회에 포함하지만 필요 메모리 추정에는 정상 완료되고 측정에 성공한 기록만 사용한다. 예약량은 유효 실측 최고값을 사용하며 유효 측정값이 없을 때만 기존 서비스별 초기 기준을 사용한다. 안전 여유분은 GPU 전체에서 512 MiB를 한 번만 차감하며 작업별 비율·고정 여유분을 중복 가산하지 않는다. 입장 가능량은 현재 GPU 여유량 − 실행 중 작업의 미사용 예약분 − 512 MiB이다. 집계는 `.tmp/gpu-memory-history/summary.json`에 저장한다.

메모리가 부족한 선두 작업 때문에 전체 대기열을 멈추지 않는다. 실행 허가 잠금 안에서 모든 대기 작업을 접수 순서로 확인하고, 현재 메모리에 들어가는 첫 작업부터 실행한다. 실행 가능한 작업끼리는 접수 순서를 유지하며, 건너뛴 작업은 다음 검사에서 다시 확인한다.

대기 실행기는 실행기·메모리 추정 코드 변경을 감지하면 대기 상태에서만 동일 PID로 재실행한다. 접수 티켓과 생성 ID를 유지하여 부모 감시·취소 연결과 순서가 바뀌지 않게 한다. 실행 중인 작업에는 재실행을 적용하지 않는다. 이 자동 갱신 기능 도입 이전에 시작된 프로세스는 감지 코드가 없으므로 기존 정책으로 완료되며 강제로 교체하지 않는다.

공용 GPU 대기열이 발급한 활성 예약과 프로세스 계보를 확인한 이미지·캐릭터 작업은 내부 GPU 파일 잠금을 공유 모드로 사용한다. 허가받은 작업끼리는 병렬 실행하며, 직접 실행은 배타 모드로 유지해 충돌을 방지한다. 모델 다운로드 잠금은 계속 배타 모드다. 이미 실행 중인 구형 작업자의 잠금 방식은 종료까지 유지된다.

이미지 메모리 예측은 실행 스크립트와 `width×height`, `steps`, 참조 이미지 개수를 함께 키로 사용한다. 설정별 최근 20회 중 정상 완료한 실측 최고값을 예약하며 다른 해상도·스텝의 기록을 섞지 않는다. 기존 측정값은 보존된 생성 요청으로 설정을 복원할 수 있을 때만 해당 집계에 포함한다. 해당 설정의 유효 실측이 없으면 서비스 초기 예약량(이미지 6144 MiB)을 사용하고 상태의 `method=configured-initial-estimate`, `samples=0`으로 근거 부재를 표시한다. 스텝 수에 비례해 메모리를 곱하지 않는다. GPU 공통 안전 여유 512 MiB 규칙은 유지한다.

### 공용 참조 이미지 입력

참조 이미지 입력은 `tools/review/common/gradio_reference_images.py`의 `build_reference_image_inputs`를 사용한다. 건물 타일 생성기를 기준으로 최대 3장, 순서 라벨, 업로드·클립보드 아이콘과 한글 버튼, 반응형 배치를 공유한다. 생성기별 표시 조건과 이미지 모드·입력 검증은 유지하며 페이지별 UI를 복제하지 않는다.

### 스프라이트 정규화 편집기 원본 목록

- 게임 잠금 목록의 스프라이트와 에셋 등록부의 모든 `assets/characters/<character>/animations/` 원본을 함께 제공한다. 게임 적용 여부로 캐릭터 애니메이션을 제외하지 않는다.
- 같은 원본은 중복 표시하지 않으며 등록 해시를 검증한다. 컷인과 미등록 생성 후보는 이 목록에 포함하지 않는다.

### 생성 ID 표시

생성 ID와 조회한 생성 ID는 공용 `build_generation_identifier()`를 사용한다. 읽기 전용 한 줄과 복사 버튼을 유지하며, 공용 `management-generation-identifier` 스타일로 프롬프트의 최소 높이를 적용하지 않는다. 긴 ID는 필드 내부에서 가로로 이동하며 페이지 폭을 늘리지 않는다.

선택한 생성 이력의 상태·설정·명령 버튼은 공용 `build_history_selection_panel()`에서 구성한다. ID는 위 공용 한 줄 컴포넌트로 표시하여 복사할 수 있게 하며, 선택 변경·해제·이력 삭제·초기화 시 표시값도 함께 갱신한다.

### 시드 입력 기본 기능

시드를 사용하는 생성 UI는 공용 `build_generation_seed()`로 입력란과 랜덤 시드 버튼을 함께 제공한다. 랜덤 버튼은 허용 범위의 시드만 변경하며 생성은 실행하지 않는다. 직접 입력·이력 복원 값을 유지하고 실제 실행 시 표시된 시드를 요청·이력에 저장한다. 단계 재개는 저장된 시드를 유지한다.

## 폐기된 생성 화면

`three-reference-generator`(Qwen 2511 3참조), `image-generator`(Qwen 2512), `floor-tile-generator`(맵 타일 생성기), `seamless-tile-generator`(심리스 패턴 생성기) 화면은 폐기했다. 도구 목록에서 제외하며 기존 화면 URL은 HTTP 410을 반환한다. Qwen 2.1 생성기를 사용한다. 다른 제작 기능에서 사용하는 공용 실행 코드와 기존 생성 기록은 유지한다.

- 관리 메뉴의 검색·분류·도구 선택은 사용자 입력 이벤트로 처리한다. 선택지의 서버 갱신이 화면 선택을 재실행하지 않아야 하며, 필터 변경 후에도 같은 도구가 선택되어 있으면 iframe을 유지한다. 초기 선택도 이미 선택된 항목을 다시 클릭하지 않는다.

캐릭터 애니메이션의 등록 모션은 걷기 v13만 제공한다. 대기 v10·휴식 v3의 선택 항목·전용 프롬프트·참조 원본은 폐기했다. 걷기와 공용 리그·코드는 유지한다. 과거 생성 결과와 이력 조회는 유지하되 폐기된 모션의 입력 복원과 재개는 거절한다.

### 공용 위치·배율 조이패드

- 현재 게시 manifest를 다시 읽어 Gradio 39개·정적 기능 래퍼 21개·미지정 0개를 확인했다. 메뉴 기본 추가 항목을 포함한 64개 순회와 위 후속 결과·좁은 화면 검증으로 현재 관리도구 화면의 정렬 검수를 마무리한다.
- 외곽 탐색과 공용 입력·로그·이력·시드·조이패드·프레임 탐색은 Gradio 표준 구성으로 제공한다. 기능용 캔버스·동기 재생·이미지 스크롤은 유지하고, 게임 자체 화면 및 독립 리포트는 별도로 구분했다.
- 마지막 공용 이력·프로세스·표준 컴포넌트·스프라이트 v1·ANNY·Qwen 입력 검사 36건 통과(`/tmp/management-ui-final-contracts.log`). 추가 변경이 없는 저장·다방향 재생 계약은 위 검증 근거를 유지한다. `git diff --check` 통과.
- 새 브라우저에서 복장 분리 메뉴와 내부 화면을 다시 열어 정상 헤딩·생성이력·콘솔 오류 없음을 확인했다. iframe 주소에는 테마 강제 매개변수가 없다. 별도 테마 CSS를 추가하지 않았다.
- 검수 중 운영 작업 생성·취소·삭제·저장을 실행하지 않았으며 임시 검수 서버는 모두 종료했다. 기준 캐릭터 참조 누락 및 병행 에셋 변경은 수정·복원하지 않았다. 이는 별도 에셋 작업의 제한사항이며 본 UI 변경의 검증 통과로 에셋 무결성을 보증하지 않는다.

### v1 폐기 및 v2 입력 이미지 삭제

- 사용자 지시에 따라 스프라이트 정규화 편집기 v1을 게시 목록에서 제거하고 기존 메뉴·직접 화면 주소는 410 폐기 안내를 반환한다. v2와 기존 저장 자료는 유지한다.
- v2의 이미지 등록 영역에 레퍼런스 이미지 삭제와 선택 프레임 이미지 삭제를 제공한다. 레퍼런스 삭제는 실행 취소 스냅샷을 남기고 현재 문서의 참조만 해제한다. 원본 파일·과거 수정 이력은 삭제하지 않으며 수정본 저장 시 현재 편집본에 반영한다.
- v2 UI·저장 계약 13건 및 JavaScript 구문 검사 통과. 실제 브라우저에서 전체 도구 63개, v2 삭제 버튼 표시와 빈 레퍼런스 삭제 안내를 확인했다. 운영 작업 저장·이미지 삭제는 실행하지 않았다.

### v2 가이드라인 편집 사용성

- 가이드라인 패널을 기본 펼침으로 제공하고 이름·방향·좌표 입력과 추가·삭제를 모았다. 추가·수정·삭제 후 목록과 선택 값을 자동 갱신하며 변경은 기존 실행 취소·수정본 저장 구조를 사용한다.
- 기존 검증 작업을 저장 없이 읽어 가로선 추가 → 이름 `검수선`·좌표 100 수정 → 삭제 → 실행 취소 복원을 브라우저에서 확인했다. 원래 편집 상태까지 실행 취소하고 검수 탭을 닫았다. 콘솔 오류 없음, v2 관련 테스트 13건 및 JavaScript 구문 검사 통과.

### 가이드 수치 편집 동선 개선

- 가이드 전용 패널을 조이패드 앞에 배치하고 대상 적용→가이드 선택→위치(px) 입력→수정 적용 순서를 표시했다. 중복 가이드 수치 입력은 얼굴 원 패널에서 제거했다.
- 대상 적용과 패널 펼침 때 가이드를 자동 조회한다. 선택한 방향에 따라 위치 입력 라벨이 위에서부터 Y/왼쪽에서부터 X로 바뀌며 원점·증가 방향·출력 크기를 안내한다.
- 브라우저에서 기존 검증 작업의 대상 적용만으로 머리끝 Y=10이 표시되고 중심선 선택으로 X=128로 전환됨을 확인했다. 저장·좌표 변경 없이 콘솔 오류 없음. UI 계약 9건 통과.

### 양쪽 비교 화면의 가이드 표시

- 레퍼런스 가이드→프레임 표시에 더해 현재 프레임 가이드→레퍼런스 표시도 제공한다. 어느 쪽에 추가·수정한 가이드든 동일한 출력 좌표로 양쪽 캔버스에 표시한다. 다른 이미지의 선은 점선으로 구분한다.
- 표시를 위해 가이드 데이터를 복제하거나 과거 프레임을 수정하지 않는다. 레퍼런스에 프레임 가이드를 겹칠 때 프레임 얼굴 원은 추가로 그리지 않는다. JavaScript 구문 검사와 v2 UI 계약 9건 통과.

### v2 애니메이션 시트 분할 입력

- `애니메이션 시트 분할`에서 파일·클립보드 입력, 행·열 균등 분할, 빨간 경계선 드래그, 원본 픽셀 좌표 직접 입력을 제공한다. 외곽 경계도 이동하여 여백을 제외할 수 있다. 번호는 왼쪽→오른쪽, 위→아래 등록 순서다.
- 미리보기는 브라우저에서 처리한다. 적용하면 각 셀을 투명 PNG로 잘라 기존 공용 upload 명령을 통해 프레임 뒤에 추가한다. 작업 전환·128프레임 제한을 검증하고 전체 추가를 한 번의 실행 취소로 되돌린다. 원본과 기존 프레임은 덮어쓰지 않는다. 수정본 저장으로 보존한다.
- 시트 입력은 PNG/JPEG/WebP, 최대 32MB·3200만 픽셀이다. 개별 프레임은 기존 8MB 제한을 따른다. 경계 교차·중복·범위 초과·비정수 좌표를 거절한다.
- `light-armor-idle.png`(1457×1080)를 실제 브라우저에서 4열×2행으로 미리보고 분할선을 364→398px로 드래그한 뒤 좌표 읽기로 확인했다. 별도 임시 작업에서 8프레임 등록·저장·일괄 실행 취소를 검증했다. 저장된 8개 PNG의 크기·순서·알파가 원본 분할 영역과 일치한다. 운영 기록 변경 없이 검수 서버 종료. Python 계약 13건, 분할 계산 Node 검사 3건 통과.

- 프레임 목록은 파일명과 별개로 현재 전체 순서의 `프레임 N`을 표시한다. 원본 파일명은 툴팁으로 확인한다. 시트 분할 미리보기와 새 파일명도 기존 프레임 수 다음 번호부터 이어지며, 삭제·실행 취소·작업 변경 시 추가 예정 번호를 다시 계산한다.

### 도구 탐색의 반응형 사이드바

- 외곽 관리 메뉴의 도구 탐색은 Gradio 기본 `Sidebar`로 제공한다. 넓은 화면에서 폭은 320px로 고정하며 콘텐츠 너비에 따라 눌리지 않는다.
- 화면 폭 768px 이하에서는 자동으로 접고, ‘도구 탐색 열기 / 닫기’ 버튼으로 슬라이딩 메뉴를 연다. 좁은 화면에서는 Gradio 기본 전체 폭 패널을 사용한다. Escape로 닫을 수 있으며 768px를 넘으면 다시 펼친다.
- 검색·분류·선택 상태와 작업 화면은 메뉴를 여닫거나 화면 폭을 바꿀 때 유지한다. 별도의 장식 CSS·테마 덮어쓰기는 추가하지 않는다.

- 외곽 관리 화면과 스프라이트 정규화 편집기 v2는 Gradio `fill_width=True`로 남은 가로 공간을 사용한다. 탐색 사이드바를 접으면 콘텐츠 영역이 함께 넓어진다.

- 작업 iframe은 내부 콘텐츠 높이에 맞춘다(최소 240px, 하단 16px). 내부 Gradio의 화면 높이 채움 제약만 해제하고 콘텐츠 크기·접기/펼치기·도구 전환을 감지한다. 도구 문서의 별도 세로 스크롤 없이 바깥 페이지 하나로 이동한다. 로그·코드 입력 등 개별 컨트롤의 스크롤은 유지한다.

- 공용 생성이력 미리보기·생성 결과 Gallery는 `height="max-content"`로 내용 전체 높이를 사용한다. 관리 프레임의 기능용 크기 동기화는 해당 갤러리의 강제 내부 스크롤을 해제하고 외부 페이지 높이에 반영한다.

- 공용 조이패드의 `current_separate_axes=True`는 가로·세로 배율을 각각 입력·적용·0.001 증감한다. 스프라이트 v2는 두 축을 독립 저장하며 기존 단일 배율 작업은 두 축에 같은 값으로 읽는다. PNG·시트·GIF 출력에도 같은 배율을 반영한다.

## 도구 목록 정렬

도구 탐색 목록은 분류 접두어를 제외한 도구 이름의 오름차순으로 정렬한다. 영문 대소문자는 구분하지 않으며 같은 이름은 도구 ID로 순서를 고정한다. 전체 목록·검색 결과·분류 필터·이전/다음 탐색은 동일한 정렬 목록을 사용한다. 등록 순서로 표시하지 않는다.
