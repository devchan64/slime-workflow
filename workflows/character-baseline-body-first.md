# 전신 우선 캐릭터 베이스라인 제작

2026-10-04 테사 제작 기록을 바탕으로 정리한 수동 제작 절차다. 생성기 자동 파이프라인 구현을 뜻하지 않는다. 캐릭터의 비공개 설정은 백엔드 설계 원본에서 관리하고 이 문서는 입력 역할·제작 순서·검수·보존만 다룬다.

## 입력과 우선순위

1. 승인된 ANNY 정면 렌더: 체형과 자세의 주 기준. 머리 크기·어깨폭·몸통·골반·팔다리 길이를 함께 유지한다.
2. 선택한 얼굴 이미지: 얼굴 정체성 기준. 리그의 머리 크기 안에 적용하며 얼굴 때문에 전신 비율을 늘리지 않는다.
3. 복장 이미지: 의상 구조·색·재질만 제공한다. 해당 이미지의 체형은 상속하지 않는다.

공통 화풍 설명은 [베이스라인 프롬프트](../assets/animation-references/baseline-style/base-prompt.txt)를 사용한다. 이번 테사 실행은 각 단계의 최종 프롬프트를 별도로 기록했으며, 공통 파일을 자동으로 결합한 실행은 아니다.

## 제작 순서

1. **리그를 주 편집 대상으로 전신 생성.** 얼굴 사진에 몸을 붙이라는 지시보다 리그에 외형·복장을 입히라는 지시로 입력 역할을 분명히 한다. 실제 리그 비율과 별도의 등신 목표를 동시에 강제하지 않는다.
2. **전신에서 외형 보정.** 얼굴 구분 특징과 큰 눈의 공통 화풍을 함께 확인한다. 눈매의 형태와 눈 전체 크기는 별개다. 얼굴 차별화를 위해 눈을 사실적인 크기로 줄이지 않는다. 수정할 요소와 보존할 체형·의상·구도를 명시한다.
3. **전신 검수·채택·등록.** 사용자 선택 이미지를 불변 버전으로 보관하고 이미지·메타데이터·등록부에 경로와 해시를 연결한다. 프롬프트의 비율 지시는 검증 결과가 아니다.
4. **등록 전신에서 정면 얼굴 파생.** 전체 머리카락과 머리·목만 포함하고 어깨·가슴·옷깃은 제외한다. 눈 크기·눈매·코·입술·턱·헤어·피부색을 재설계하지 않는다.
5. **같은 등록 전신에서 4방향 파생.** 상단 후면 좌·우, 하단 전면 좌·우의 2×2 시트로 생성한다. 모든 방향에서 머리 크기·신장·체형·복장 구조를 유지하고 비대칭 소품은 캐릭터 본인 좌우로 지정한다.
6. **파생물 별도 검수·등록.** 전신 채택이 얼굴·4방향 후보의 자동 승인을 뜻하지 않는다. 시트는 런타임 스프라이트 패킹·애니메이션 등록과 구분한다.

## 검수 기준

- 원본과 후보를 같은 전신 높이로 비교해 머리/전신·어깨폭/전신·몸통/전신·다리/전신 비율을 확인한다. 머리카락 높이를 해부학적 머리 높이로 혼동하지 않는다.
- 리그 이미지를 참조한 생성은 리그 메시·관절을 기하학적으로 고정한 렌더가 아니다. 실측하지 않은 비율이나 방향별 일치를 검증 완료로 기록하지 않는다.
- 큰 눈을 유지하면서도 얼굴 구조가 다른 인물과 구분되는지 확인한다. 한 요소를 수정할 때 다른 부위·재질·그림자가 바뀌었는지도 살핀다.
- 얼굴은 목까지만, 전신은 머리와 발이 잘리지 않게 생성한다. 투명 배경의 잔여 바닥 그림자도 확인한다.
- 4방향에서 자세·시점·크기와 장비의 실제 좌우를 확인한다. 스트랩·파우치·헤어 묶음이 단순 좌우 반전으로 뒤집히지 않아야 한다.

## 실행과 보존

내장 이미지 생성 도구로 출력별 한 번씩 호출한다. 이번 실행에서 모델 버전과 시드는 노출되지 않았으므로 동일 출력의 재생성을 보장하지 않는다. 로컬 Qwen 실행이나 리그 직접 렌더 결과로 기술하지 않는다.

새 실행은 `.tmp/test/<experiment-name>/<한국시간>/`에 최종 프롬프트·단어 수·해시·입력·출력을 보관한다. 사용자가 기록 보존을 지시한 실행은 연결 자산·목적·출처·버전·SHA-256과 함께 `assets/generation-records/`에 보존한다. 같은 해시의 이미지는 기존 정식 자산 또는 보존 파일로 연결하여 중복하지 않는다.

실제 사례와 현재 상태는 [테사 제작 기록](../assets/generation-records/tesa-baseline-20261004/README.md)을 따른다.
