# 도시맵 스프라이트 생성·교체 가이드

## 범위와 원본 소유권

이 문서는 건물 이미지 생성과 에셋 교체 절차를 정리한다. 건물·소품·자연물 스프라이트를 대상으로 하며, 지형 타일 생성은 [맵 타일 생성](map-tile-generation.md)을 따른다. 건물과 빌보드는 지형 타일로 분류하지 않는다.

신규 수동 이미지 생성의 결과·후보·참조·검수 기록은 `.tmp/YYYY-MM-DD_HH-mm-ss/`에 보관한다. 시각은 한국 시간(Asia/Seoul)을 사용한다. 저장소 루트의 `output/`은 폐기한 과거 경로이며 새로 만들거나 복원하지 않는다. 후보 폴더는 게임의 원본 저장소나 자동 등록 대기열이 아니다. 채택된 게임 에셋의 유일한 원본은 `slime-assets`이며 프론트엔드와 검수 도구는 등록된 동일 버전·해시를 사용한다.

| 자료 | 관리 위치 |
| --- | --- |
| 채택된 건물 PNG | `slime-assets/assets/buildings/` |
| 채택된 소품·자연물 PNG | `slime-assets/assets/billboards/` |
| 지형 타일 | `slime-assets/assets/tiles/` |
| ID·버전·경로·출처·SHA-256 | `slime-assets/asset-registry.yaml` |
| 도시 배치·크기·앵커·건물 점유 영역 | `slime-assets/assets/maps/city_layouts/` |
| 제작 베이스라인 | 이 저장소의 `prompts/` 등 Git 추적 경로 |
| 수동 생성 후보·프롬프트·비교 결과 | `.tmp/YYYY-MM-DD_HH-mm-ss/` |

세계관 설계 원본은 비공개 `slime-backend/docs/design/`에서 확인한다. 공개 저장소에 설계 원본·복제본·요약본을 옮기지 않는다. 이 가이드에는 제작·전달에 필요한 기술 절차만 기록한다.

## 맵 모델링의 썸네일 참조

도시·필드 맵의 신규 모델링과 기존 지형·건물·소품·식생 수정에는 등록된 월드맵 썸네일을 시각 참고자료로 사용한다. 이 절은 스프라이트 생성뿐 아니라 맵 배치 작업에도 적용한다.

1. `slime-assets/assets/ui/world-map/thumbnails.yaml`에서 대상 맵 ID의 썸네일을 찾고 `asset-registry.yaml`의 관리 ID·버전·경로·SHA-256과 실제 파일을 대조한다. 생성 후보나 과거 비교 시트를 등록 원본 대신 사용하지 않는다.
2. 256×256 정사각형 썸네일에서 대표 지형·건축 재료·주요 실루엣·색감·분위기를 확인한다. 필요한 특징만 현재 맵의 지형, 건물, 식생과 소품에 반영한다. 썸네일은 지역의 특징을 압축한 그림이므로 세부 배치·수량·축척·원근·카메라를 모델링 규격으로 해석하지 않는다.
3. 실제 배치·통행·연결·시작점은 `slime-assets/assets/maps/`의 등록 원본과 승인된 설계를 기준으로 유지한다. 썸네일과 충돌하면 충돌 내용을 기록하고 설계 기준에 맞춘다. 썸네일에 보이는 길이나 건물을 이유로 새 연결·시설을 임의로 추가하지 않는다. 썸네일 누락·해시 불일치는 참조 미확인으로 기록하고 확인 완료로 보고하지 않는다.
4. 제작·검수 기록에는 참조 썸네일의 관리 ID·버전·해시, 반영할 특징, 반영하지 않는 요소와 사유를 남긴다. 비공개 세계관 설명을 공개 에셋 등록부나 기술 문서에 복제하지 않는다.
5. 8770 공용 관리도구의 실제 맵 화면과 썸네일을 나란히 확인한다. 주요 특징과 색감의 일관성을 검수하고, 실제 게임 카메라의 가독성·도로·출입구·통행·연결·가림은 별도로 확인한다. 썸네일과 유사하다는 이유로 맵 기능 검증을 생략하지 않는다.

썸네일은 분위기·특징 참조, 바닥 그리드 이미지는 투영·점유 영역 참조로 역할을 구분한다. 지형 타일 생성에서는 썸네일의 필요한 색·재료만 참고하며 풍경 전체를 반복 텍스처로 복제하지 않는다. 이 절은 제작 절차이며 관리페이지의 썸네일 자동 표시가 구현됐다는 의미는 아니다.

## 제작 준비

1. 현재 등록 에셋과 실제 맵 참조, [대상 맵의 등록 썸네일](#맵-모델링의-썸네일-참조)을 먼저 확인한다. 파일 이름이나 생성 시각만 보고 새 후보가 미적용이라고 판단하지 않는다.
2. 건물 용도, 점유 타일 가로·세로, 도로와 출입구 방향, 층수·목표 높이, 허용 돌출 범위를 정한다.
3. 실제 맵의 고정 카메라로 바닥 그리드와 점유 영역·출입구를 표시한 참조를 준비한다. 투영 참조와 외형 참조의 역할을 구분한다.
4. [건물 직교투영 베이스라인](../prompts/building-orthographic-v1.yaml)의 고정 문구 뒤에 대상별 입력을 조합한다. 기본 투영 계약을 바꾸려면 새 버전으로 비교 검수한다.
5. 호출 목적·예산·검증 가설·채택 기준을 기록한다. [이미지젠 사용 정책](imagegen-usage-policy.md)을 함께 적용하며, 사용자가 명시한 이미지젠 건물 생성·교체 요청은 실행 기록에 근거로 남긴다. 이 문서가 일반 호출 제한을 해제하지는 않는다.

`isometric`이라는 표현만으로 투영 각도를 결정하지 않는다. 현재 사용한 2:1 가이드의 바닥 축은 화면상 기울기 ±0.5지만, 다른 카메라에도 이를 무조건 적용하지 않는다. 기준은 실제 바닥 투영이다.

## 이미지 생성과 검수

내장 `image_gen`에는 투영 가이드 이미지를 참조로 제공하고 투명 배경의 단일 건물을 생성하도록 요청한다. 편집할 기존 이미지가 있으면 먼저 확인하고 필요한 참조로 전달한다.

- 수직선은 수직으로, 평행선은 평행하게 유지한다. 소실점 수렴이나 깊이에 따른 크기 축소를 넣지 않는다.
- 밑면·벽 하단·처마·지붕선이 바닥 두 축과 맞는지 확인한다.
- 건물 전체와 풍차 날개 등 부속물이 잘리지 않도록 여백을 둔다. 별도 바닥 타일·투사 그림자·가이드 선은 결과에 포함하지 않는다.
- 외형과 재료는 대상의 제작 요구에 맞춘다. 풍차·물레방아 등 설비는 실제 배치 환경과 맞아야 한다.
- 건물 1종을 실제 맵에 시험 배치해 투영·크기·앵커·가림을 확인한 뒤 나머지 교체로 확대한다.
- 생성 성공은 채택이나 적용 완료가 아니다. 부적합한 후보는 실패 이유를 기록하고 입력 조건을 바꾼다.

알파·축소·정렬·시트 패킹은 결정적 이미지 처리로 수행한다. 단순 크기 변경을 위해 다시 생성하지 않는다. 이미지젠 호출마다 최종 프롬프트 원문·단어 수·해시와 참조 역할·해시를 기록한다. 로컬 Qwen의 100단어 미만 규칙을 내장 이미지젠의 기록에 소급 적용하지 않는다.

## 가이드 기반 자연물 변형 제작

같은 점유 크기의 자연물을 여러 종 만들 때는 크기뿐 아니라 표면 무늬와 실루엣도 나눈다. 가이드 제작 원본은 `generators/image/config/billboard-layouts/`이며, 관리도구 사용은 [가이드 기반 빌보드 생성](management-clients.md#가이드-기반-빌보드-생성)을 따른다.

### 높이와 형태

- 1×1 바닥형은 동일한 260×130 바닥 투영에 높이 90·180·360 가이드를 사용한다. 각각 `1x1-low`, `1x1-low-2x`, `1x1-low-4x`다. 높이 배수는 가이드 체적 기준이며 PNG 크기나 런타임 `displayHeight` 배수가 아니다.
- 윗부분은 가이드 체적의 약 80%를 채우는 불규칙한 형태로 만들고, 아래로 갈수록 넓어져 바닥 경계에 접하게 한다. 모든 모서리를 직육면체처럼 채우는 뜻이 아니다. 높은 벽면용은 뒤쪽과 밑면의 밀착감을 확인한다.
- 석영맥 변형은 가는 평행맥·점상 조각·분기맥·망상맥·렌즈형 덩어리·수평층·수직맥·틈새 집중·분리된 반점처럼 방향, 굵기, 연결 방식, 노출 위치를 구분한다. 암반도 판석·오목한 암반·쌍봉·각진 바위·기울어진 암주 등으로 나눈다. 색만 바꾸거나 같은 굵은 대각선 맥을 반복하지 않는다.
- 완성 에셋 참조 때문에 기존 광맥과 실루엣이 반복되면 기하 가이드만 이미지 참조로 사용하고, 재질·색은 문장으로 명시한 후보를 비교한다. 참조를 바꾼 이유와 실제 사용한 참조를 실행 기록에 남긴다.
- 비교 시트에서 같은 카메라·바닥 크기로 전체를 확인한다. 원본 캔버스의 여백이 다르므로 PNG 전체 크기로만 비교하지 않는다. 패턴 구분과 접지 검수는 생성 결과를 직접 보고 수행한다.

- 벽면용 중간형은 3×1·2×1·1×2·1×3 규격에 높이 260을 사용한다. 높은형 520의 절반이며, 같은 밑면과 뒤쪽 밀착 기준을 유지한다. 생성기 규격 이름은 `*-medium`이다.
- 낮은 판형은 2×1·3×1 가이드도 제공한다(`2x1-low`, `3x1-low`). 높이는 90이며, 길쭉한 노출암반·파쇄암을 만들 때 점유 방향과 하단 접지 경계를 유지한다.

### 밑면 정렬과 등록

1. 긴 변을 최대 512px로 축소하고 투명도를 보존한다. 그림자를 원본에 덧붙이지 않고 공용 그림자 속성으로 관리한다.
2. 실제 불투명 밑면 폭과 앞쪽 접지점을 측정한다. 알파 임계값은 측정에만 사용하고 원본의 부드러운 가장자리를 제거하지 않는다. 먼 투사 그림자·후광·고립 픽셀이 있으면 측정 대상에서 구분하고 후보 적합성을 다시 확인한다.
3. 1×1 타일의 표시 폭에 밑면을 맞춰 표시 배율을 구한다. 전체 이미지 높이에 이 배율을 곱한 값이 `displayHeight`다. 높은 암주의 윗부분 돌출 폭이나 PNG 여백을 밑면 폭으로 오인하지 않는다.
4. `tile-intersection` 방식의 1×1은 앞쪽 타일 교차점을 기준으로 한다. 이미지 원점이 중앙 하단일 때 `anchorX = (이미지 폭/2 − 접지점 X) × 표시 배율 / 타일 폭`, `anchorY = (이미지 높이 − 접지점 Y) × 표시 배율 / 타일 높이`로 초기값을 계산한다. 타일 규격과 렌더러 계약을 확인하고 실제 미리보기에서 양쪽 밑변까지 검수한다. 이 식을 다른 점유 크기·앵커 모드에 그대로 적용하지 않는다.
5. 인접한 등록 에셋의 접지 그림자를 참고하되 이미지마다 실제 밑면과 맞는지 확인한다. 앵커·표시 높이·점유·그림자는 `sprite-display-properties.yaml`에 저장한다. 원본 이미지 해상도와 표시 크기를 구분한다.
6. 등록부와 프론트엔드 에셋 목록·잠금, 공용 속성의 백엔드 잠금을 함께 갱신한다. 카탈로그에는 직접 확인한 외형과 배치 용도를 기록하고 `sync_billboard_catalog.py --write`, `--check`로 파생 정보를 동기화한다. 등록 요청만으로 실제 맵 배치를 추가하지 않는다.

이 절은 제작·검수 절차다. 이미지 생성기가 접지점 계산이나 패턴 중복 검수를 자동 수행한다는 의미는 아니다.

## 크기·앵커·배치 규칙

- 정적 건물·빌보드 원본은 긴 변을 최대 512px로 맞춘다. 작은 원본을 이유 없이 확대하지 않는다. 비율과 RGBA 투명도를 유지하고 축소 방식(예: Lanczos)을 기록한다.
- 원본 픽셀 크기와 맵의 `displayHeight`는 별개다. 원본 축소 요청을 배치 크기 변경으로 대신 처리하지 않는다.
- 애니메이션 시트는 개별 프레임 기준으로 처리한다. 웨이포인트의 256px 프레임 6장을 3×2로 패킹하면 시트는 768×512px가 된다. 전체 시트를 무조건 512px로 축소하지 않으며 프레임·시트 메타데이터와 소비자 검증을 함께 맞춘다.
- 앵커는 최종 이미지의 실제 접지점을 기준으로 검수한다. 크롭하면 좌표를 다시 계산한다. 건물 `contentWidth`는 전체 날개·처마 폭이 아니라 바닥 점유 폭과의 관계를 확인한다.
- 건물의 점유 타일은 이동 금지 영역이다. 일반 주택은 출입하지 않으며 시설은 문 앞에서 메뉴를 이용하는 배치를 유지한다.
- 빌보드의 `groundFootprintColumns`·`groundFootprintRows`는 바닥 영역 검수 기준이며 건물 충돌 영역과 혼동하지 않는다.
- 동일 스프라이트는 명시적인 변형 의도가 없으면 동일한 표시 크기를 사용한다. 곡물 자루처럼 같은 소품이 혼합 크기로 보이지 않도록 모든 인스턴스를 대조한다.
- 배치를 옮기면 도로·출입구·시작점·맵 연결을 확보하고, 건물 뒤 가림·소품 겹침·자연물 밀도를 실제 화면에서 확인한다.

## 실행 폴더와 기록

신규 수동 생성은 `.tmp/YYYY-MM-DD_HH-mm-ss/`를 만들고 해당 작업의 자료를 함께 보관한다. 내장 이미지젠 결과를 작업 공간에 복사할 때도 이 경로를 사용한다. 후보·실행 기록은 자동 커밋하거나 런타임 참조로 사용하지 않는다.

관리도구 생성기의 기존 작업·이력 저장 경로는 [관리도구 클라이언트 가이드](management-clients.md)를 유지한다. 이 규칙을 이유로 생성기 이력을 이동하거나 저장 구조를 변경하지 않는다.

등록부의 `source.path`에 남아 있는 과거 `output/` 경로는 생성 당시의 출처 기록이다. 해당 경로를 생성·복원하라는 지시가 아니며, 삭제된 원본을 새 후보로 재생성하지 않는다. 채택 에셋은 등록된 현재 `path`에서 읽는다.

다음은 신규 기록의 권장 구성이다. 현재 모든 과거 폴더가 이 구조로 작성된 것은 아니며, 문서 추가만으로 자동 생성·검증기가 구현되는 것은 아니다.

```text
.tmp/YYYY-MM-DD_HH-mm-ss/
  generation.yaml        # 입력·실행·결과 기록
  projection-reference.png
  <에셋 ID>-candidate.png
  <에셋 ID>-prepared.png # 등록 크기로 처리한 후보
  applied.yaml           # 실제 등록·참조 갱신 결과
  review.png             # 실제 맵 검수 화면
```

`generation.yaml`에는 도구, 목적, 베이스라인 ID·해시, 최종 프롬프트 원문·단어 수·해시, 대상별 입력, 참조 역할·해시, 결과 파일·크기·해시, 후처리 방식, 검수 상태·사유를 기록한다. 비용·시간을 도구가 제공하지 않으면 미제공으로 남긴다. 재사용되는 기본 프롬프트와 참조는 실행 폴더에만 두지 않고 제작 기준 데이터로 Git 추적한다.

`applied.yaml`에는 이전 ID·버전, 새 등록 경로·버전·최종 해시·크기, 실제 맵 참조, 앵커·표시 크기, 검증 결과를 남긴다. 생성 당시의 큰 이미지 해시와 최종 축소 원본 해시를 구분한다. 개인 절대 경로가 담긴 실행 기록을 공개용 문서나 에셋 등록부에 그대로 복사하지 않는다.

## 등록과 교체 순서

1. 사용자 요청과 검수 결과로 교체할 후보를 확정한다. 이미 채택·교체가 지시된 범위라면 같은 승인을 반복 요청하지 않는다.
2. 최종 PNG를 준비하고 `slime-assets`에 등록한다. 재생성한 외형은 새 버전으로 관리한다. 원본 크기 편집은 기존 관리도구의 저장 계약과 이력을 따른다.
3. `asset-registry.yaml`의 경로·크기·출처·SHA-256을 실제 파일과 맞춘다. 빌보드 카탈로그가 관련되면 자연물·소품 분류와 참조도 갱신한다.
4. 프론트엔드의 `sprite-assets.lock.yaml` 및 에셋 목록과 실제 맵의 `textureKey`를 함께 갱신한다. 맵을 수정하면 등록부와 백엔드 `map-data.lock.yaml`도 동기화한다.
5. 공용 렌더러에 이미지 목록이 번들링되는 변경이면 새 배포 버전을 빌드하고 검수 도구의 manifest·번들을 정식 설치 절차로 갱신한다. 생성된 번들을 직접 편집하지 않는다.
6. 원본 존재·등록 해시·소비자 잠금·맵 스키마를 검증한다. 참조가 없는 오래된 파일 삭제는 사용자가 지시한 범위에서 수행한다. 이전 실행 기록은 현재 에셋으로 되돌리지 않는다.
7. 8770 실제 관리도구에서 해당 맵을 새로 불러와 전체 배치와 확대 화면을 확인한다. 데이터 검사만 통과한 상태를 브라우저 검수 완료로 보고하지 않는다.

등록부·잠금만 먼저 저장하고 이미지를 빠뜨리거나, 이미지 교체 후 이전 해시를 남기면 로딩이 실패한다. 커밋 전에 파일과 관련 메타데이터가 같은 상태인지 재확인한다.

## 미적용 후보 판별

생성 후보와 등록부의 해시가 다르다는 이유만으로 재교체하지 않는다. 등록 전에 축소·크롭·정렬했을 수 있다. 다음 세 가지를 따로 판별한다.

- **적용됨:** 등록된 원본과 기록된 후처리 결과가 일치하고, 실제 맵·소비자에서 그 버전을 참조한다.
- **이전 버전:** 동일 대상의 후속 버전이 적용되어 있다. 과거 후보로 덮어쓰지 않는다.
- **미적용 또는 확인 필요:** 후속 버전도 없거나, 출처·후처리·매핑 근거가 부족하다. 차이를 조사한 뒤 교체 여부를 결정한다.

투영 가이드, 비교 시트, 프롬프트, 생성 기록은 게임 에셋 교체 대상이 아니다. 동일 이름만으로 적용 완료를 판단하지 않는다. 단순 축소 작업은 등록 크기로 같은 리샘플러를 적용해 RGBA 픽셀을 비교할 수 있으며, 크롭·보정이 있으면 해당 변환 기록까지 대조한다.

2026-10-18 점검에서는 `output`의 건물 PNG 57개 중 39개가 현재 적용 버전, 18개가 후속 버전으로 대체된 이미지였다. 이는 당시 점검 결과이며 이후 작업의 자동 판정 근거가 아니다. 당시 로컬 보고서와 후보 폴더는 정리되었으므로 현재 존재하는 자료처럼 참조하거나 복원하지 않는다.

## 완료 보고와 커밋

변경 에셋·맵, 실제 수행한 검증, 미적용 또는 보류 항목을 구분해 보고한다. 커밋을 요청받으면 에셋 원본·등록부, 소비자 참조·잠금, 검수 도구 변경을 저장소와 작업 단위로 나눈다. 후보·캐시·개인 경로가 담긴 생성 로그를 일괄 포함하지 않는다. 이미지 커밋 검토의 파일 존재·파일명·목적 경로 확인과 제작 단계의 시각 검수는 별개다.
