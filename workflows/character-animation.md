# 캐릭터 애니메이션 제작 워크플로우

최종 캐릭터 애니메이션 이미지는 **Codex 내장 image_gen**으로 생성한다. 외형 참조는 승인된 **2×2 베이스라인 시트 전체**, 걷기 프레임 참조는 **동일 방향의 리그 8프레임 시트**다. Qwen과 OpenPose 직접 참조는 과거 비교 실험이며 최종 제작의 필수 단계가 아니다.

## 1. 베이스라인 생성과 선택

[통합 캐릭터 생성](character-baseline-sheet.md)에 따라 신규 캐릭터를 최대 지원 크기의 2×2 베이스라인으로 한 번에 생성한다. 기존 1장 베이스라인은 폐기했다. 현재 승인 외형은 프론트엔드 `src/assets/characters/baseline/character-default-white-shirt-four-directions-v2.png`다.

입력은 시트 전체이며 좌상/우상/좌하/우하가 `up_left`/`up_right`/`down_left`/`down_right`다. 방향별 걷기 생성에서는 필요한 셀의 역할을 프롬프트에 지정한다. 크롭한 단일 캐릭터를 기본 입력으로 사용하거나 생성 결과를 외형 기준으로 연쇄 참조하지 않는다.

## 2. MoMask 리그 8프레임 시트

```bash
.venv/bin/python generators/animation/resolve_default_rig.py
.local/blender-runtime/bin/python generators/animation/render_pose_frames.py
```

두 번째 명령은 샌드박스 밖 CUDA에서 실행한다. `walk-travel/v1` MoMask 원본과 승인된 `five-head-walk/v9` 리그의 해시를 확인하고 사용한다. 모션·체형은 재추론하지 않는다.

- 24개 시간 구간의 `0,3,6,9,12,15,18,21` 표본을 사용하며 중복 끝점은 제외한다.
- 4방향 각각 8프레임, 프레임당 150ms, 전체 1.2초 루프다.
- 출력은 `.tmp/YYYY-MM-DD_HH-mm-ss/` 아래 방향별 `rig-sheet.png`다. 2048×1024, 4열×2행이며 위 행 1~4, 아래 행 5~8 순서다.
- 재질의 명암, 카메라 기준 주광·보조광, 접촉부 AO를 사용하여 몸통·팔·다리 경계를 드러낸다. 과도한 환경광으로 실루엣이 평평해지지 않도록 한다. 설정은 `rig_builder.py` 상단 상수와 실행 manifest에 기록한다.
- 셰이딩 변경은 관절·체형·모션 변경이 아니다. 리그 관절 경계가 최종 캐릭터의 보호대나 장식으로 전사되지 않았는지 검수한다.
- Depth·마스크·개별 렌더·OpenPose·미리보기는 파생 실행 자료다. 삭제한 `assets/animation-loops/`를 복원하지 않는다. 기존 포즈 시트 자산은 비교 자료로 유지하며 최종 기본 입력으로 사용하지 않는다.

## 3. 이미지젠 최종 외형 생성

1. 새 `.tmp` 실행 폴더에 참조 사본, 해시, 방향 키, 프롬프트, 출처를 기록한다.
2. **이미지 1: 같은 방향의 리그 8프레임 시트. 이미지 2: 승인된 2×2 베이스라인 전체.** 두 참조를 확인하고 내장 image_gen에 전달한다.
3. 프롬프트는 리그의 각 셀 동작을 유지하고, 베이스라인에서 선택한 방향 캐릭터의 외형으로 표현하도록 간단히 지정한다. 공통 문구에 방향·베이스라인 셀만 바꾼 4방향 프롬프트를 관리한다. 프레임별 장문 설명을 추가하지 않는다.
4. 각 방향마다 4열×2행 8프레임 시트 한 장을 생성한다. 카메라·외형·신체 비율·셀 순서를 유지하고 투명 배경으로 요청한다. 요청 크기와 실제 출력 크기는 구분한다.
5. 생성 원본을 실행 폴더에 복사하고 도구·프롬프트·참조·출력 해시와 실제 크기를 기록한다. 내부 모델 이름은 추측하지 않는다.

스탠딩은 [별도 4×4 제작 절차](character-standing-sheet.md)를 따른다. 동일하게 내장 image_gen과 2×2 베이스라인 전체를 사용하며, 걷기용 8프레임을 스탠딩 16프레임에 억지로 대응시키지 않는다.

## 4. 정렬과 반복 검수

리그 참조 이미지젠 결과를 정렬하면 사용 가능하다는 사용자 판단을 반영한다. 근거 실행은 `.tmp/2026-09-20_20-47-07/`, 정렬 전 재생 비교는 `.tmp/2026-09-20_20-53-28/`다. 아직 정렬 완료나 게임 등록 상태로 간주하지 않는다.

1. 실제 크기로 셀을 나누고 공통 캔버스·지면 기준 anchor에 맞춰 위치를 정렬한다.
2. 셀 좌표·프레임별 이동량·anchor를 기록한다. 공중의 발을 접지점으로 삼거나 머리·바운딩 박스를 고정해 정상적인 상하 움직임을 없애지 않는다. 프레임별 비균등 배율로 체형을 변형하지 않는다.
3. 정렬 전후를 150ms×8로 반복 재생하여 마지막→첫 프레임 연결, 좌우 발 교대, 발 미끄러짐, 외형·방향·크기 변화와 잘림을 확인한다.
4. 리그와 오버레이 비교할 때 비교용 배율·이동량을 기록한다. 실제 관절의 정확한 추종과 육안상 유사성을 구분한다.
5. 투명 배경의 알파 및 잔여 배경 광채를 검수한다. 선택한 최종 결과만 사용자 지시에 따라 프론트엔드에 등록한다.

## 보관과 재사용

생성 방식·스크립트는 워크플로우, 정식 이미지 원본은 프론트엔드, 비공개 기획·설계는 백엔드에서 관리한다. 실험 이미지·프롬프트·중간 결과·로그는 `.tmp`에 보관한다. MoMask와 승인 v9 리그는 재사용 자산으로 유지한다. 단일 원화 폐기와 2×2 원본 채택은 기존 스탠딩 런타임을 자동 교체하지 않는다.
