# 캐릭터 애니메이션 제작 워크플로우

최종 캐릭터 애니메이션 이미지는 **Codex 내장 image_gen**으로 생성한다. 외형 참조는 승인된 **2×2 베이스라인 시트 전체**, 걷기 프레임 참조는 **동일 방향의 리그 8프레임 시트에서 추출한 4프레임 묶음**이다. 인체 비율 훼손을 줄이기 위해 **이미지젠 호출당 애니메이션 출력은 최대 4프레임**으로 제한한다. Qwen과 OpenPose 직접 참조는 과거 비교 실험이며 최종 제작의 필수 단계가 아니다.

## 1. 베이스라인 생성과 선택

[통합 캐릭터 생성](character-baseline-sheet.md)에 따라 신규 캐릭터를 최대 지원 크기의 2×2 베이스라인으로 한 번에 생성한다. 기존 1장 베이스라인은 폐기했다. 현재 승인 외형은 프론트엔드 `src/assets/characters/default/baseline/character-default-white-shirt-four-directions-v2.png`다.

입력은 시트 전체이며 좌상/우상/좌하/우하가 `up_left`/`up_right`/`down_left`/`down_right`다. 방향별 걷기 생성에서는 필요한 셀의 역할을 프롬프트에 지정한다. 크롭한 단일 캐릭터를 기본 입력으로 사용하거나 생성 결과를 외형 기준으로 연쇄 참조하지 않는다.

## 2. MoMask 리그 8프레임 시트

현재 재사용 참조는 `assets/rig-sheets/five-head-walk-8f/v1/`의 `down_left.png`, `down_right.png`, `up_left.png`, `up_right.png`다. 셰이딩 보강 실행 `2026-09-20_21-01-21`의 네 시트를 픽셀 변경 없이 등록했으며 출처·해시는 같은 폴더의 `manifest.yaml`에 기록한다. 기존 참조 사용 시 재렌더하지 않는다. 다음 명령은 새 렌더가 필요한 경우 사용한다.

```bash
.venv/bin/python generators/animation/resolve_default_rig.py
.local/blender-runtime/bin/python generators/animation/render_pose_frames.py
```

두 번째 명령은 샌드박스 밖 CUDA에서 실행한다. `walk-travel/v1` MoMask 원본과 승인된 `five-head-walk/v9` 리그의 해시를 확인하고 사용한다. 모션·체형은 재추론하지 않는다.

- 24개 시간 구간의 `0,3,6,9,12,15,18,21` 표본을 사용하며 중복 끝점은 제외한다.
- 4방향 각각 8프레임, 프레임당 150ms, 전체 1.2초 루프다.
- 출력은 `.tmp/YYYY-MM-DD_HH-mm-ss/` 아래 방향별 `rig-sheet.png`다. 2048×1024, 4열×2행이며 위 행 1~4, 아래 행 5~8 순서다.
- 재질의 명암, 카메라 기준 주광·보조광, 접촉부 AO를 사용하여 몸통·팔·다리 경계를 드러낸다. 과도한 환경광으로 실루엣이 평평해지지 않도록 한다. 설정은 `rig_builder.py` 상단 상수와 실행 manifest에 기록한다.
- 셰이딩 변경은 관절·체형·모션 변경이 아니다. 리그 관절 경계가 최종 캐릭터의 보호대나 장식으로 전사되지 않았는지 검수한다.
- Depth·마스크·개별 렌더·OpenPose·미리보기는 파생 실행 자료다. 삭제한 `assets/animation-loops/`를 복원하지 않는다. 기존 포즈 시트 자산은 비교 자료로 유지하며 최종 기본 입력으로 사용하지 않는다.

## 3. 이미지젠 최종 외형 생성

1. 새 `.tmp` 실행 폴더에 참조 사본, 해시, 방향 키, 프롬프트, 출처를 기록한다.
2. 같은 방향의 승인 리그 8프레임 시트를 1–4번과 5–8번으로 나눈다. 원본 셀을 변형하지 않고 각 묶음을 행 우선 순서의 **2×2 리그 시트**로 패킹한다. 현재 512×512 셀 기준 참조 묶음은 1024×1024다. 원본 자산은 유지하고 파생 참조와 원본 프레임 번호 대응을 실행 폴더에 기록한다.
3. **이미지 1: 이번 묶음의 리그 4프레임 시트. 이미지 2: 승인된 2×2 베이스라인 전체.** 두 참조를 확인하고 내장 image_gen에 전달한다. 두 묶음 모두 동일한 승인 베이스라인을 참조한다.
4. 프롬프트는 5등신 비율·승인 외형, 방향, 각 리그 셀 동작, 정확히 4프레임의 2×2 배치를 간결하게 지정한다. 공통 문구에 방향·베이스라인 셀·프레임 범위만 바꾼다. 프레임별 장문 설명을 추가하지 않는다.
5. 방향마다 **1–4번과 5–8번을 두 번에 나누어 생성**한다. 두 호출에서 같은 요청 해상도·카메라·캐릭터 배율·셀 여백 기준을 사용하고 투명 배경을 요청한다. 8프레임 전체를 한 번에 생성하거나 통합 시트를 이미지젠으로 다시 그리지 않는다. 요청 크기와 실제 출력 크기는 구분한다.
6. 생성 원본을 실행 폴더에 복사하고 도구·프롬프트·참조·출력 해시, 실제 크기, 묶음별 원본 프레임 번호를 기록한다. 내부 모델 이름은 추측하지 않는다.
7. 각 2×2 출력의 셀 경계를 `x[i]=floor(i*W/2)`, `y[j]=floor(j*H/2)`로 분할한다. 최종 셀 규격을 먼저 정하고 균일 배율·투명 여백·평행이동으로 맞춘다. 두 묶음의 머리·몸통 크기와 5등신 비율을 대조하며 자세별 바운딩 박스 높이로 키를 강제 일치시키지 않는다. 비균등 확대·축소는 금지한다.
8. 정렬한 셀을 **최종 4열×2행 8프레임 시트**로 패킹한다. 위 행은 1–4번, 아래 행은 5–8번이다. 최종 크기는 셀 너비×4, 셀 높이×2이며 각 rect·배율·이동량·앵커를 기록한다. 150ms×8의 1.2초 루프 규격은 유지한다. 오류 프레임만 아래 절차로 개별 생성·교체한다.

스탠딩은 [방향별 4×1 시트 제작 절차](character-standing-sheet.md)를 따른다. 동일하게 내장 image_gen과 2×2 베이스라인 전체를 사용하며, 걷기용 8프레임을 스탠딩 16프레임에 억지로 대응시키지 않는다.


### 오류 프레임 개별 생성·동일 크기 교체

기본 생성 단위는 방향별 최대 4프레임이다. 걷기는 두 묶음을 통합한 8프레임 시트를 검수하며, 오류 수정은 1프레임 단위로 수행한다. 4프레임 제한은 인체 비율 보존을 위한 제작 기준이며 포즈·비율 검수를 생략하는 근거가 아니다.

1. **원본 보존·분할:** 생성 원본의 실제 너비 W·높이 H를 기록한다. 4×2 셀의 경계는 `x[i]=floor(i*W/4)`, `y[j]=floor(j*H/2)`로 계산하고 각 rect를 저장한다. 생성기가 요청 크기를 지키지 않아도 이미지를 늘여 맞추지 않는다. 예를 들어 1774×887은 셀 너비·높이가 443/444px로 달라지므로 교체 대상 rect의 정확한 크기를 사용한다.
2. **프레임별 판정:** 같은 번호의 리그와 골반→무릎→발목 연결, 지지발·이동발, 발 방향, 외형과 5등신 비율을 비교한다. 정상·오류·보류 상태를 기록하고 오류 번호만 선택한다.
3. **개별 생성:** 선택 프레임의 원본 리그 셀과 승인된 2×2 베이스라인 전체를 참조한다. 한 장의 전신·투명 배경을 요청하고 방향·좌우 연결·해당 오류만 간결하게 명시한다. 오류 이미지의 잘못된 포즈를 참조 기준으로 고정하지 않는다. 출력은 새 `.tmp/한국시간/`에 저장한다.
4. **정확한 셀 크기 보정:** 개별 출력 전체를 대상 rect 크기로 강제 늘이지 않는다. 캐릭터는 균일 배율로 조정하고 투명 여백과 평행이동으로 대상 셀 크기에 맞춘다. 원본 시트의 승인 프레임을 기준으로 머리·몸통 배율을 확인한다. 걷기 자세마다 달라지는 전체 바운딩 박스 높이를 기준으로 매번 키를 맞추지 않는다. 배율·이동량·원본/출력 크기를 기록한다. 신체가 잘리거나 투명 여백으로 담을 수 없으면 실패 처리하고 재생성·재보정을 요구한다.
5. **앵커 정렬:** 선택 프레임의 지면 기준 앵커를 수동 검수한다. 개별 이미지의 앵커 a, 대상 셀 앵커 b, 균일 배율 s에 대해 이동량은 `t=b-s*a`다. 공중 발 중간점으로 접지 위치를 추정하지 않는다. 반올림 규칙과 최종 정수 앵커를 기록한다.
6. **셀 교체:** 기존 시트를 복사한 새 수정본에 대상 rect를 먼저 투명하게 비운 후 같은 크기의 RGBA 교체 셀을 그대로 넣는다. 알파 합성으로 기존 팔다리가 남지 않게 한다. 정상 셀은 재생성·리사이즈하지 않는다. 교체 영역 밖 RGBA 픽셀과 전체 시트 크기가 원본과 동일한지 검증한다. 여러 오류도 선택된 셀만 교체한다.
7. **재검수·채택:** 교체 프레임 전후, 묶음 경계인 4→5와 루프 경계인 8→1 연결을 같은 속도로 확인한다. 발 교대·외형·배율·앵커 흔들림·잘림을 검수하고 사용자가 채택한 수정본만 프론트엔드 정식 에셋으로 전달한다.

교체 기록은 애니메이션 ID·버전·방향·프레임 번호, 원본 시트/리그/베이스라인/개별 출력/교체 셀/수정 시트의 해시, rect, 크기, 배율·이동량·앵커, 오류 사유·검수 상태를 포함한다. 원본·실험 프롬프트·개별 출력·교체 셀·수정본·검증 로그를 실행 폴더에 함께 보관한다. 정상 픽셀 보존은 파일 해시가 아닌 디코딩된 RGBA 값으로 비교한다.

검증 근거: 좌하 4프레임 묶음 실험에서 사용자는 1–4·6–8번을 사용 가능으로 판단하고, 5번은 개별 생성으로 포즈 오류 해결을 확인했다. 실행은 `.tmp/2026-09-20_23-02-11/`과 `.tmp/2026-09-20_23-07-17/`이다. 개별 수정의 유효성을 확인한 사례이며 모든 출력의 성공을 보증하지 않는다. 현재 이 절차의 자동 셀 보정·교체 CLI는 미구현이다. 기존 비교·앵커 검수 도구를 사용하며 교체 자동화 구현 시 위 보존 검증을 필수로 한다.

## 4. 정렬과 반복 검수

리그 참조 이미지젠 결과를 정렬하면 사용 가능하다는 사용자 판단을 반영한다. 근거 실행은 `.tmp/2026-09-20_20-47-07/`, 정렬 전 재생 비교는 `.tmp/2026-09-20_20-53-28/`다. 아직 정렬 완료나 게임 등록 상태로 간주하지 않는다.

1. 실제 크기로 셀을 나누고 공통 캔버스·지면 기준 anchor에 맞춰 위치를 정렬한다.
2. 셀 좌표·프레임별 이동량·anchor를 기록한다. 공중의 발을 접지점으로 삼거나 머리·바운딩 박스를 고정해 정상적인 상하 움직임을 없애지 않는다. 프레임별 비균등 배율로 체형을 변형하지 않는다.
3. 정렬 전후를 150ms×8로 반복 재생하여 묶음 경계 4→5와 마지막→첫 프레임 연결, 좌우 발 교대, 발 미끄러짐, 외형·방향·크기 변화와 잘림을 확인한다.
4. 리그와 오버레이 비교할 때 비교용 배율·이동량을 기록한다. 실제 관절의 정확한 추종과 육안상 유사성을 구분한다.
5. 투명 배경의 알파 및 잔여 배경 광채를 검수한다. 선택한 최종 결과만 사용자 지시에 따라 프론트엔드에 등록한다.

## 보관과 재사용

생성 방식·스크립트는 워크플로우, 정식 이미지 원본은 프론트엔드, 비공개 기획·설계는 백엔드에서 관리한다. 실험 이미지·프롬프트·중간 결과·로그는 `.tmp`에 보관한다. MoMask와 승인 v9 리그는 재사용 자산으로 유지한다. 단일 원화 폐기와 2×2 원본 채택은 기존 스탠딩 런타임을 자동 교체하지 않는다.
