# 캐릭터 애니메이션 제작·검수

## 현재 제작 경로

MoMask 모션 생성과 AnyPose 기반 캐릭터 애니메이션 생성은 2026-10-09에 폐기했다. 구형 `walking-v12`·`walking-v13` 안내, AnyPose 단일·배치 실행 및 오류 프레임 재생성 절차는 사용하지 않는다. 폐기 범위와 남은 편집 명령은 [관리도구 클라이언트 가이드](management-clients.md#anypose-애니메이션-생성기-폐기)를 따른다.

현재 모션·포즈 준비는 [HY-Motion](hy-motion.md), 캐릭터 외형의 단일 포즈 변환은 [VNCCS 포즈 변환](pose-transfer.md)을 사용한다. 두 도구는 별도의 생성 ID·기록을 가지며, 모션 전체를 자동으로 캐릭터 프레임으로 변환하는 통합 배치 생성기를 제공한다는 뜻은 아니다. 과거 `character-animation generate`·`resume`·`record-alpha-vnccs`는 사용할 수 없다.

## 1. 모션과 참조 준비

HY-Motion은 원본 모션을 생성한 뒤 ANNY 변환·정사영·원근투영 렌더와 투영 OpenPose를 저장한다. 모션의 원본 프레임 번호·방향·투영·리그 및 카메라 설정·출처·해시를 확인한다. 생성 이미지에서 추측한 관절을 모션 원본으로 사용하지 않는다.

등록된 기본 제작 모션은 [HY-Motion 걷기 v2](../assets/motion-sheet/hy-motion-walking-v2/README.md)다. 선택 실행의 원본 9~43번을 채택한 35프레임·30FPS 자산이며, 4방향 원근투영 ANNY RGB와 OpenPose를 포함한다. 에셋 번호 1~35와 원본 번호 9~43의 대응은 매니페스트를 따른다. `generators/animation/config/character_animation.yaml`의 `walking-v2` 등록은 자산 선택 정보이며 폐기된 생성 명령을 다시 활성화하지 않는다. 설정의 표시 FPS와 원본 30FPS도 구분한다.

방향별 외형 참조는 사용할 포즈와 동일한 방향으로 선택한다. ANNY 렌더와 OpenPose는 서로 다른 참조 표현이며, VNCCS의 포즈 추종 품질이 같다고 가정하지 않는다. 우선 해당 방향의 ANNY RGB 포즈와 캐릭터 참조로 단일 프레임을 검수한다.

## 2. 단일 포즈 변환

관리도구의 **포즈 변환 생성기** 또는 공용 게이트웨이 `pose-transfer`를 사용한다.

```bash
python3 tools/manager.py help pose-transfer generate
python3 tools/manager.py command pose-transfer generate --reference /path/identity.png --reference /path/pose.png --resolution 512 --steps 40 --detach
python3 tools/manager.py command pose-transfer history
```

사용자 입력 순서는 아이덴티티 → 포즈이며, VNCCS 실행기는 모델에 포즈 image1 → 아이덴티티 image2 순서로 전달한다. 모델·LoRA·BF16 정밀도는 고정하고, 신규 출력은 512×512·25/40스텝(기본 40)이다. 입력·프롬프트·모델·시드·출력 해시는 해당 작업에 저장한다. 자세한 입력·재개 계약은 [포즈 변환 안내](pose-transfer.md)를 따른다.

기본 프롬프트는 `generators/image/config/pose-transfer-prompt.txt`에서 Git으로 관리한다. 실제 모델 입력은 100단어 미만이며 방향·사용자 보조 지시를 포함한 최종 원문·단어 수·해시를 기록한다. 프롬프트를 바꾸면 1프레임 샘플부터 확인한다. 폐기된 `.local/production-prompts/anypose-v5-v1/` 전달 절차는 사용하지 않는다.

GPU 추론은 샌드박스 밖에서 실행한다. CUDA 부재·모델 또는 LoRA 누락·해시 오류는 즉시 실패하며 CPU 추론이나 AnyPose로 대체하지 않는다.

## 3. 프레임 검수와 수정

- 참조와 결과의 방향, 골반→무릎→발목 및 어깨→팔꿈치→손목 연결을 비교한다.
- 지지발·이동발, 접지, 손발 위치, 가림, 신체 비율과 외형·복장·색 유지 여부를 확인한다.
- 같은 모션의 프레임은 원본 번호를 맞춰 비교하고, 크기·지면 앵커·잘림·프레임 간 흔들림을 확인한다.
- 문제가 있는 프레임만 올바른 외형·포즈 참조로 다시 생성한다. 잘못 생성한 결과를 새로운 포즈 원본으로 사용하지 않는다.

VNCCS의 완료 상태·어댑터 로드 성공은 포즈·아이덴티티·시간축 일관성의 품질 승인이 아니다. 같은 시드와 참조를 사용해도 연속 프레임 품질은 별도 검수가 필요하다. 최종 채택은 사용자가 결정한다.

## 4. 정렬·재생·패킹

포즈 검수를 통과한 프레임에 캐릭터 기준의 균일 배율과 앵커를 적용한다. 프레임마다 바운딩 박스 높이를 맞춰 자세 변화까지 지우거나 비균등 확대·축소하지 않는다. 캐릭터 기준 높이는 최종 스프라이트에서 최소 384px을 확보하며, 자세별 높이를 같은 값으로 강제하지 않는다.

검수 재생은 원본 프레임 번호·선택 간격·출력 FPS를 명시하고 루프의 마지막→첫 프레임 경계까지 확인한다. HY-Motion 출력이나 반복 재생 자체가 닫힌 루프를 보장하지 않는다. 과거의 4방향×8프레임·150ms·4×4 시트 두 장 규격을 모든 신규 모션에 고정 적용하지 않는다.

스프라이트 정규화 편집기·앵커 저장은 유지한다. GUI·CLI 계약은 [관리도구 클라이언트 가이드](management-clients.md#스프라이트-정규화-편집기-v2)를 따른다. 시트에는 프레임 순서·rect·방향·원본 번호·재생 시간·배율·앵커·출처 해시를 함께 보존한다. 구형 고정 8프레임 패커를 새 모션에 그대로 적용하지 않는다.

## 5. 기록과 전달

- HY-Motion·포즈 변환 작업은 각 서비스의 기존 기록 경로를 유지한다. 일반 후보·검수·패킹 실험은 `.tmp/test/<실험명>/<한국시간 실행일시>/`에 보관하며 덮어쓰지 않는다.
- 재사용 승인 모션·리그는 `assets/`에서 버전·출처·해시를 관리한다. 생성기 폐기를 이유로 보존 자산을 삭제하거나 현행 기본값으로 다시 지정하지 않는다.
- 채택된 캐릭터 스프라이트와 애니메이션·앵커 메타데이터의 관리 원본은 `slime-assets/assets/sprites/`다. 사용자 채택 후 등록·검증하여 전달하며, 프론트엔드 사본을 직접 편집하지 않는다.
- 이 문서는 현행 실행·검수 절차다. 과거 MoMask·AnyPose 실험의 원본 기록과 당시 파라미터는 재작성하지 않는다.
