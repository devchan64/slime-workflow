# Hermes 관리 에이전트 변경 기록


- 대화에서 상세를 열 때만 격리 코딩 작업과 diff·로그 영역을 펼친다.
- 공용 GPU 예약 기록의 서비스·작업 ID·예약량을 제한적으로 조회하고 상태에 표시한다.

- GPU 확인창을 연 뒤 입력이 바뀐 경우 Hermes 대화·코딩·위임 접수를 거부한다.

- 위임 입력 변경 시 이전 검토와 접수 버튼을 해제하고, 확인 시에도 검토본 일치를 검사한다.

- 작업 이력과 세션 상세에 전달된 전체 지시를 읽기 전용으로 표시하고 새 지시 입력을 보존한다.

- 실제 bubblewrap 프로세스의 호스트 루프백·홈·환경변수 차단 회귀를 추가했다.

- 격리 HTTP 게이트웨이 재시작 시 세션·위임 기록 복구와 중복 요청·외부 출처 거절 회귀를 추가했다.

- 주요 관리 명령의 입력·영향·GPU·재시도 범위를 화면과 Codex MCP에서 확인하도록 했다.

- 공용 읽기 관측에 최근 Hermes 작업 ID와 상태를 제한적으로 추가했다.

- 긴 변경 diff를 화면에서 처음부터 부분별로 이어 볼 수 있도록 기존 바이트 조회를 연결했다.

- 대화의 검증된 Kimodo 제안을 내부 형식 대신 검토 안내로 표시한다.

- 세션 대화에 최근 도구 호출·대상·결과와 확인 시각을 표시한다.

- Kimodo 시험 작업의 실제 GPU 적재 중 중지와 프로세스·예약 해제를 확인했다.

- 실제 Kimodo 시험 작업의 실행 중 중지 요청과 프로세스·GPU 예약 해제를 확인했다.

- 관리 메뉴와 페이지 이름·설명을 관리 상태, 대화, 생성 위임, 격리 코딩 기능에 맞게 정리했다.

- Kimodo 작업 상태 요약에 DWPose 출력 형상 경고와 품질 확인 안내를 표시한다.

- 실제 Hermes 후속 대화와 Kimodo 생성의 GPU 예약 인계를 시험하고, 작업 상태를 읽기 쉬운 요약으로 표시한다.

- 실제 Hermes 모델로 상태 조회와 Kimodo 제안 출력을 시험하고, 메모리 수치만으로 즉시 실행 가능성을 단정하지 않도록 안내를 보완했다.

- Hermes 상태에 공용 대기열의 VRAM·GTT 영역과 호스트 여유, 예약 기준 비교를 표시한다.

- 화면 새로고침 후에도 최근 위임 접수 이력을 찾아 확인하도록 화면과 Codex MCP 조회를 추가했다.

- 접수 ID에서 Kimodo 작업 상태를 확인하는 공용 명령과 Codex MCP 도구를 추가했다. 기존 중단 작업 상태 복구 동작을 유지한다.

- 접수 ID와 작업 ID가 일치하는 Kimodo 위임 작업의 중지 요청을 화면 확인과 Codex MCP에 연결했다.

- 위임 접수 ID로 기존 작업 ID 또는 확인 필요 상태를 재접수 없이 확인하는 화면·MCP 조회를 추가했다.

- 완료된 Hermes 답변의 Kimodo 위임 제안을 검증해 화면과 Codex MCP에서 읽고 사용자 검토 입력으로 불러오도록 했다. 자동 접수는 하지 않는다.

- Hermes 화면에 Kimodo 위임 입력 검토, 공용 GPU 확인·취소, 기존 작업 상태 조회를 추가했다.

- Codex MCP에서 Kimodo 공용 생성 접수를 비동기 위임할 수 있도록 연결했다. 동일 접수 ID는 중복 실행하지 않고 응답 유실 시 확인 필요 상태로 유지한다.

- 공용 관측에 Kimodo 모델 준비와 활성 작업 상태를 추가하고 화면·MCP·격리 상태 조회에 제공했다.

- 모델 준비·GPU·대기열의 읽기 전용 공용 관측을 Hermes 화면, Codex MCP와 격리 작업자에 연결했다. 조회 실패는 준비 완료나 유휴로 표시하지 않는다.

## 미출시

- 세션에서 연결된 작업을 선택해 기존 diff·검증·로그 상세로 연다.

- 세션 메시지와 연결 작업 상태를 한 번에 조회하고 실행 중에만 자동 갱신한다.

- 세션 선택·대화 조회와 GPU 확인을 거친 세션 메시지 접수 화면을 추가했다.

- 세션 메시지를 기존 격리 작업으로 접수하고 완료된 이전 대화 일부를 다음 요청에 포함한다.

- 세션 생성·조회·목록을 공용 게이트웨이와 Codex MCP에 연결했다. 메시지 전송과 대화 문맥은 후속 구현이다.

- 격리 작업자에 GPU 상태·대기열의 고정 읽기 전용 조회 경로를 연결했다.

- Codex MCP에 공용 GPU 상태와 대기열의 읽기 전용 조회를 추가했다.

- 작업 상세에서 Hermes 최종 응답과 독립 검증 상태를 별도로 표시한다.

- 작업 이력 행을 선택하면 해당 작업 ID와 상태·결과·diff·로그를 불러온다.

- Qwen3.8-27B IQ4_XS 로컬 모델과 Hermes를 공용 GPU 대기열에 연결했다. GPU를 다른 작업과 배타적으로 사용하며 진행 중 작업을 선점하지 않는다.
- 현재 관리도구의 격리 사본에서 코딩 작업을 실행하고 요청 식별자별 접수·상태·이력·중지·검토용 diff를 제공한다.
- 모델 로드와 격리 작업 및 취소를 실제 GPU에서 시험했다. 브라우저와 Codex MCP 연결 검증은 진행 중이다.
- Codex MCP 서버를 등록하고 실제 Codex의 작업 위임부터 GPU 코딩과 독립 검증까지 별도 시험 게이트웨이에서 확인했다. 기존 운영 게이트웨이 적용 검증은 남아 있다.
- GPU 대기열 실행기 비정상 종료 시 Hermes 프로세스 그룹을 회수하고 작업 상태를 실패로 표시한다. 그룹 정보가 없으면 안전하게 대기한다.
- 긴 diff를 MCP에서 바이트 단위 조각으로 끝까지 회수한다.
- 격리 임시 메모리 파일 시스템을 최대 2 GiB로 제한한다.
- 기존 관리도구 Python 환경을 격리 공간에 읽기 전용으로 연결해 공용 회귀 실행기를 사용할 수 있게 한다.
- 선택한 공용 회귀 모듈을 최종 수정 후 독립 실행하고 실패·시간 초과를 작업 결과에 반영한다.
- Hermes와 독립 검증의 호스트 환경변수 상속을 차단하고, 작업 중 공용 회귀 실행기가 바뀌면 독립 검증을 거부한다.
