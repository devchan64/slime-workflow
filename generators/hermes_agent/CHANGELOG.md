# Hermes 관리 에이전트 변경 기록

- 격리 Hermes의 문맥 파일 자동 주입 한도를 40,000자로 늘리고 대화 준비와 실제 실행에 동일하게 적용한다.

- 공통 워크플로우 입문 지침과 업무별 스킬을 추가하고, 현재 요청과 최근 사용자 발화에 맞는 스킬을 선택해 작업 프롬프트에 포함한다.

- 대화 원문을 보존하면서 Hermes 기본 정책으로 문맥을 자동 정리하고, 대화 화면에서 자동 설정·수동 정리·요약과 작업 상태를 확인한다.

- 작업·대기열에서 직접 접수한 생성 작업의 관련 대화 메시지로 이동하고 이력 변경 시 재조회 방법을 안내한다.

- 대화와 작업 목록의 연결 오류에 재시도와 마지막 조회 안내를 제공하고, 완료 결과 및 실패 응답 표시를 정리했다.

- 대화 메시지 입력창의 기본 높이를 늘렸다.

- 대화 스크롤이나 이전 페이지에서 최신 메시지로 바로 이동한다.

- 이전 메시지는 대화 스크롤의 맨 위에서 열고 이후·최신 대화는 페이지 아래에서 돌아간다.

- 대기열과 작업 결과를 하나의 오른쪽 작업 패널에서 조회한다.

- GPU 정보는 오른쪽 패널에서 확인하고 Wan Fun Control 생성 폼은 도구 탐색에서 연다.

- 세션 대기열에 워크플로우 단계와 대화에서 직접 접수한 Wan Fun Control 작업을 함께 표시한다.

- 대화의 워크플로우 결과에서 상태와 작업 ID, 모션 영상 및 다운로드를 정리하고 표만 가로 스크롤한다.

- 대화 화면은 한 번에 최근 기록 6건을 표시하고 이전·다음 페이지로 오래된 대화를 확인한다.

- 세션 도구를 입력창의 개별 버튼으로 표시하고 대기열 조회를 대화 영역에 표시한다.

- 세션 도구 메뉴를 대화 입력창으로 옮겨 GPU 정보·입력 폼·대기열을 열 수 있다.

- Wan Fun Control 생성 진행 상황을 보이는 동안 30초 간격으로 자동 갱신하며 끌 수 있다.

- 입력과 결과를 함께 확인하는 대화 카드를 생성 작업으로 표시한다.

- 대화에 저장된 생성 폼을 일반 사용자 메시지와 구분해 생성 폼 카드로 표시한다.

- 접수된 Wan Fun Control 폼 메시지에서 작업 ID를 확인하고 복사할 수 있다.

- 도구 탐색과 Wan Fun Control 입력에 같은 대화 측면 패널을 사용하고 전환 중 작성 내용을 유지한다.

- 대화와 Wan Fun Control 생성 폼을 분리하고 시드 비교와 결과 입력 재사용을 제공한다.

- Wan Fun Control 시드 변경 요청에 확인된 원본 작업의 입력을 복원하는 검토 폼을 제공한다. 원본이 모호하면 작업 ID를 요청하며, 확인 전에는 접수하지 않는다.

- Wan Fun Control 폼을 대화 메시지에 저장·복원하고 접수 기록으로 중복 실행을 방지하며 결과를 다시 열 수 있다. 접수 결과가 불확실하면 자동 재접수하지 않는다.

- 대화에서 번역·FLUX 단계의 입력과 결과 연결을 편집해 등록하고, 세션별 실행 검색·결과 조회·대기 작업 우선 실행을 검토할 수 있다. 번역문과 생성 PNG를 후속 단계에 전달하는 경로를 모의 게이트웨이에서 검증했다.

- 음악·효과음·번역·캐릭터 애니메이션 원 서비스도 같은 저장소의 이력 중복 순회를 해당 프로세스에서 거부한다. 번역은 서비스 잠금 대기 전에 검사한다.

- 공용 이미지·영상 원 서비스도 같은 저장소의 이력 동시 조회를 프로세스 내에서 거부하고 응답 전송은 공유 이력 잠금 밖에서 한다. 다른 저장소와 프로세스의 경쟁은 기존 잠금 정책을 따른다.

- 원본 이력의 동일 소유 서비스 동시 조회를 프로세스 내에서 거부한다. 건물 호환 경로와 빌보드는 같은 원본 잠금을 사용하며 직접 호출·타 프로세스·시간 초과 후 순회는 보호 범위 밖이다.

- 생성기·오디오 원본 이력 요청의 페이지 범위·스냅샷·검색어를 원 서비스 호출 전에 검증한다. 잘못된 요청은 MCP와 Hermes에서 각각 원 서비스 호출 전에 거부하며 후속 페이지에는 같은 검색어와 스냅샷이 필요하다.

- GPU 예약 정리·우선 실행을 다시 검토할 때 이전 확인 창과 요청을 즉시 지운다. 모의 GPU 비활성 브라우저에서 두 기능의 재검토 중 숨김과 새 확인 표시를 검증하고 예약 정리 체크 초기화도 확인했다. 실제 작업은 실행하지 않았다.

- 우선 실행 검토 중 모의 대기열을 새로고침하면 이전 확인 창이 숨겨지고 새 행을 다시 검토할 수 있음을 GPU 비활성 브라우저로 확인했다.

- GPU 대기열 우선 실행 검토는 대기 행과 요청 식별값이 바뀌면 이전 확인 창을 표시하지 않는다. 임시 대기 행과 GPU 비활성 브라우저에서 이전 응답 숨김·새 검토 표시를 확인했으며 대기 순서는 바꾸지 않았다.

- GPU 예약 정리 검토는 선택 대상과 요청 식별값을 다시 비교해 다른 행 선택 뒤 늦은 확인 창을 띄우지 않는다. 임시 운영 화면과 GPU 비활성 브라우저에서 검토 중 다른 행을 선택하면 이전 확인 창이 숨겨지고 새 대상 검토가 표시됨을 확인했다. 실제 예약 정리는 실행하지 않았다.

- 과거 Wan Fun 준비 예약은 임시 MCP·게이트웨이를 거쳐 작업 ID·원 서비스·정리 확인 필요 상태를 전달하며 예약 파일을 변경하지 않는 것을 확인했다. GPU 관측은 모의했다.

- 색인 없는 과거 Wan Fun 준비 작업 이력을 새 MCP stdio → 임시 게이트웨이 → 원 서비스 경로에서 조회했다. 임시 상태 파일은 변경되지 않았고 GPU는 사용하지 않았다.

- 운영 이력에서 지시 행을 연속 선택하면 각 원문 조회를 허용하고 마지막 선택만 표시한다. 지연된 첫 응답과 빠른 다음 응답을 GPU 비활성 브라우저로 확인했다.

- 운영 이력에서 선택한 지시 원문과 링크는 조회 후에도 세션·페이지·행 선택 식별값이 일치할 때만 표시한다. 임시 운영 화면과 GPU 비활성 브라우저에서 행 선택 후 세션을 바꿀 때 이전 원문은 숨겨지고 새 선택 원문은 표시됨을 확인했다.

- 운영 지시 페이지를 조회하는 동안 처음·이전·최근 버튼을 함께 비활성화해 중복 클릭 경쟁을 막는다. GPU 비활성 브라우저에서 이전 조회와 최근 복귀를 확인했다.

- 운영 접수 조회도 진행 중 중복 클릭을 막아 결과가 사라지는 경쟁을 방지하고 세션·페이지 변경 시 조회 버튼을 복원한다. 임시 화면과 GPU 비활성 브라우저에서 재조회와 페이지 전환을 확인했다.

- 운영 지시를 연속 클릭할 때 두 번째 요청이 시작되지 않았는데 첫 결과만 무효화되는 현상을 방지한다. 조회 중 지시 조회 버튼을 잠그고 완료 또는 세션 변경 시 복원하며 GPU 비활성 브라우저에서 확인했다.

- 운영 이력의 지시 페이지 조회도 세션·요청 식별값을 비교해 늦은 결과와 그에 따른 접수 표 초기화를 막는다. 임시 운영 화면과 GPU 비활성 브라우저에서 지연 조회 중 세션을 바꾸고 이전 응답 숨김과 새 조회 표시를 확인했다.


- 운영 이력의 접수 조회에서 세션 식별·메시지 오류도 빈 표와 재조회 안내로 처리해 이전 접수 행이 남지 않게 한다.

- 대화에서 세션 작업을 찾을 때 첫 페이지에도 요청한 세션 ID가 명시되어야 한다. 누락 또는 다른 세션 응답으로 제안을 열지 않으며 운영 이력의 지시·접수 연결도 같은 검증을 적용한다.

- 이력·대기열·게이트웨이·대화 화면 관련 CPU 테스트 391건을 통과했다. 화면 구성은 운영 ASGI처럼 실행 중인 이벤트 루프에서 시험하도록 바꿨고 화면 테스트 320건에서 이벤트 루프 자원 경고가 재현되지 않았다.

- 대화의 원본 이력에서 응답 서비스·실제 소유 서비스·페이지 범위와 후속 스냅샷을 확인하고 불일치 시 목록을 비운다. 공통 검증도 전체 건수를 초과한 위치와 스냅샷이 없는 후속 페이지를 거부한다.

- 작가·번역·오디오·영상·FLUX 결과 조회는 알 수 없는 접수 상태를 거부한다. 일반 FLUX도 확인 불가·기록 없음 응답의 명시적인 접수 ID·서비스 불일치를 거부한다.

- MCP와 관리 게이트웨이의 HTTP 오류 응답은 최대 16KB를 읽고 잘림을 알리며 스트림을 닫아 반복 오류 시 자원 누수를 줄인다.

- 관리 기능 검색에서 영상·FLUX의 구형 직접 재개 제한과 별도 검토 후 재개 경로를 함께 안내한다.

- 운영 이력에서 Wan Fun 생성과 모델 준비의 GPU 대기·예약 기록을 구분해 표시하고, 준비 작업도 원 서비스 경로를 검증한다. 색인이 없는 과거 `-prepare` 작업도 Wan Fun 원본 이력에서 조회하며 해당 예약을 준비 서비스에 한해 표시한다. 과거 `-prepare` ID는 기존 명령 계약상 우선 실행 대상이 아니다. 표시는 조회 시점의 기록이며 실행 상태를 보증하지 않는다.

- Wan Fun 재개의 응답 유실·준비 충돌 시 불명확 접수 보존과 중복 차단을 검증했다.

- Wan Fun의 새 모델 준비도 확인 불가 이력에서 중복 접수를 보류한다.

- Wan Fun 재개의 대화 제안·접수·상태 확인과 운영 이력 흐름을 모의 검증했다.

- Wan Fun의 기존 직접 재개도 준비·검토 재개와 같은 접수 잠금을 사용한다.

- Wan Fun 준비 작업을 생성 재개 예비 검토의 상태 복구 전에 제외한다.

- Wan Fun 재개 시 과거 형식의 준비 작업도 충돌 검사에 포함했다.

- Wan Fun 준비 요청의 공유 접수 잠금 경합을 임시 HTTP 게이트웨이로 검증했다.

- Wan Fun 생성 재개를 Hermes 대화·운영 이력·MCP의 중복 방지 접수에 연결했다.

- Wan Fun 준비·생성·검토 재개 접수에 프로세스 간 잠금을 추가했다.

- Wan Fun 원 서비스의 검토 지문 기반 재개를 준비했다. Hermes 접수는 아직 제외한다.

- Wan Fun 원 서비스의 준비 작업 충돌 관측을 추가하고 Hermes 접수 제한을 유지했다.

- 임시 MCP·게이트웨이에서 Wan Fun 예비 검토와 재개 접수 차단을 검증했다.

- Wan Fun 재개 입력의 예비 검토를 Hermes와 MCP에 연결하되 접수는 계속 제외한다.

- Wan Fun 원 서비스의 생성 재개 예비 검토를 등록했다.

- Wan Fun 생성 재개 검토를 위한 참조·영상 지문을 준비했다.

- Wan Fun 원 서비스 재개 입력의 참조·영상 무결성 검사를 보완하고 Hermes 재개 미지원 범위를 명시했다.

- 정리 미리보기 호출과 기능 목록이 소유 서비스 폐기 정책을 동일하게 확인한다.

- 실행 중인 로컬 게이트웨이에서 폐기된 서비스의 정리 미리보기 거부를 확인했다.

- 폐기 정책으로 차단된 서비스의 정리 미리보기 연결 표시와 호출을 바로잡았다.

- 통합 초기화의 세션·작업 양쪽 이벤트 연결과 출력 수를 화면 구성에서 검증했다.

- 대화의 세션·작업 선택 변경 시 분산된 초기화를 통합해 초기 요청을 줄였다.

- 초기 브라우저 요청을 화면 이벤트와 대조해 선택 변경 초기화 호출이 다수임을 확인했다.

- GPU 비활성 임시 브라우저에서 유휴 대화 요청 빈도를 측정하고 초기 요청 집중 현상을 기록했다.

- 대화 자동 갱신의 초기 상태·주기와 작업 종료 시 중단을 구성 및 콜백 검사로 확인했다.

- Hermes 모델 충돌 검사 전에 대기열 작업자 그룹 등록을 확인하도록 순서를 조정했다.

- 모델 사용 충돌 사유의 대기열 종료 처리 보존과 대화 표시를 모의 검증했다.

- Hermes 작업자의 모델 사용 충돌을 이력 상태 오류로 남겨 대화에서 이유를 확인할 수 있게 했다.

- 준비 상태 JSON을 제한된 크기로 읽고 원 서비스 직접 호출의 확인 불가 처리를 검증했다.

- Hermes 모델 준비 기록을 확인할 수 없으면 유휴로 판단하지 않고 준비 요청을 접수 전에 보류한다.
