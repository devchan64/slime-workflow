# MiniMax H3 이미지 생성

텍스트 프롬프트로 한 장을 생성하는 실험 기능입니다. INT8 ConvRot 이미지 변환기와 기존 INT8 텍스트 인코더, 이미지 전용 VAE를 사용합니다. 기본 크기는 1024×1024이며 6스텝입니다. 생성 요청에 최대 두 장의 참조 PNG를 포함할 수 있습니다.

GUI는 832×480, 512×512, 1024×1024 직접 생성을 선택할 수 있습니다. 512×512는 실제 GPU 생성과 품질을 아직 검증하지 않았습니다.

입력한 프롬프트에 공용 화풍 v1.5.0을 적용합니다. 이미 원문이 포함되어 있으면 중복하지 않습니다. 화면에서 실제 최종 프롬프트와 단어 수를 검토한 뒤 접수하며, 저장 기록에 사용자 입력·화풍 원문과 해시·최종 프롬프트를 보존합니다. 검토 후 화풍이나 입력이 바뀌면 다시 검토해야 합니다. 이전 실험 기록은 당시 입력을 유지합니다.

작업을 시작할 때 모델을 GPU에 올리고 작업 프로세스가 종료되면 해제합니다. GPU 상주 서버는 사용하지 않습니다. 기본 SDPA에서 유한한 출력도 잘못될 수 있습니다.

## 샘플러와 비교 실험

독립 생성 화면의 **샘플러**에서 `LCM · 기본 · 실험` 또는 `Euler`을 선택하고, 생성 요청 검토 화면에서 선택값을 확인합니다. 선택만으로 생성하지 않습니다. 생성 이력의 입력 적용으로 저장된 선택을 다시 불러올 수 있습니다. 샘플러 기록이 없는 이전 이력은 Euler로 취급합니다. 헤르메스 대화의 저장 접수폼에는 샘플러 선택이 없으며 새 접수에는 LCM을 사용합니다.

두 방식 모두 6스텝과 같은 sigma 스케줄을 사용합니다. LCM은 마지막을 제외한 각 단계에 새 노이즈를 넣습니다. 배율은 전체 6단계 기준 1.10에서 0.90까지 선형으로 계산하며, 마지막 단계는 sigma가 0이어서 노이즈를 추가하지 않습니다. 노이즈는 입력 시드로 초기화한 별도의 CPU 난수 생성기를 사용합니다. 요청에는 `sampler`, 결과에는 샘플러 버전·배율·난수 방식·시드가 기록되고 로그에서 단계별 값을 확인할 수 있습니다.

LCM은 **실험 옵션**입니다. 격리 작업 한 건에서 실행됐지만 생성기 옵션의 실제 GPU 경로와 반복 품질은 아직 검증하지 않았고, ComfyUI와 난수열이 완전히 같다는 보장도 없습니다. 표정·화풍·캐릭터 유지가 개선된다고 단정하지 않습니다.

통합 CLI에서 `--sampler lcm`을 지정합니다. 생략하면 LCM이며, `--sampler euler`를 지정하면 Euler를 사용합니다. 예를 들어 다음 명령은 참조 PNG 한 장을 사용합니다.

```bash
python3 tools/manager.py command minimax-h3-image generate --prompt 'A small red house in a meadow' --reference /absolute/path/reference.png --sampler lcm --seed 42 --detach
```

샘플러 비교에는 같은 참조 이미지와 순서·프롬프트·공용 화풍·시드·생성 크기·축소 설정을 사용하고 샘플러만 바꿉니다. 실제 저장 요청과 결과, 로그의 설정을 확인한 뒤 얼굴·체형·의상·선·명암과 자세를 각각 비교합니다. LCM은 단계별 새 노이즈를 사용하므로 같은 시드라도 Euler와 전체 난수열이 같지는 않습니다. 여러 시드로 반복하고, 다른 설정까지 바뀌었다면 샘플러 하나의 효과로 단정하지 않습니다.

## 참조 화풍과 캐릭터 유지

참조 기반 편집 프롬프트에는 첨부 순서대로 `<Picture 1>`, `<Picture 2>`를 지정하고 각 이미지가 제공할 인물·화풍·구도의 역할을 적습니다. 얼굴·머리·체형·복장과 윤곽선·음영처럼 유지할 속성과 자세·소품처럼 바꿀 속성을 구분합니다. 참조에 보이지 않는 특징을 추정하지 않습니다. 이는 [MiniMax 공식 편집 프롬프트 가이드](https://github.com/MiniMax-AI/MiniMax-H3-Image/blob/main/skills/h3-image-prompt-writing/references/edit-en.txt)에 따른 작성 방법이며 동일성 보장은 아닙니다.

공용 화풍 v1.5.0은 자동 결합되므로 참조와 다를 수 있습니다. 최종 프롬프트를 검토하고 유지 결과를 얼굴·체형·의상과 선·명암·질감으로 나누어 참조와 비교합니다. 한 장의 결과만으로 반복 일관성을 판정하지 않습니다. 비교 실험은 참조·시드·크기·모델·공용 화풍을 기록하고 한 번에 바꾸는 조건을 제한합니다. 현행 INT8 로컬 구현과 공식 서비스의 출력은 동일하다고 가정하지 않습니다.

독립 화면의 `2배 크기로 생성 후 축소`는 선택한 최종 크기의 두 배로 생성하고 OpenCV `INTER_AREA`로 축소합니다. 832×480 선택 시 1664×960으로 생성합니다. `raw-result.png`와 `result.png`에 원본과 축소본을 각각 보존합니다. 대화 저장 폼은 이 옵션을 지원하지 않습니다. 큰 생성 크기가 화풍 일치를 보장하지는 않습니다.

## 확인한 사용 경험

2026-11-24 Radeon 8060S에서 공용 화풍을 적용해 초원의 빨간 집을 1024×1024, 시드 42, 6스텝으로 생성했습니다. 대기 제외 약 2분 6초, 관측 GPU 메모리 피크 47,886 MiB였고, 종료 뒤 장치 전체 사용량은 약 1.3 GiB로 시작 전과 비슷했습니다. 생성 결과는 게임풍 빨간 집과 초원을 보여 주었습니다. 한 번의 실행이며 다른 입력의 품질·SDPA 정확도·TLB 안정성을 보증하지 않습니다.

통합 CLI: `python3 tools/manager.py command minimax-h3-image generate --prompt 'A small red house in a meadow' --seed 42 --detach`. 생성 ID로 `status`, `logs`, `cancel`, `prioritize`, `history-delete`를 사용합니다. 게이트웨이가 이전 코드로 실행 중이면 새 서비스를 인식하지 못하므로 기존 작업을 확인한 후 정식 절차로 재시작해야 합니다.

모델은 MiniMax-H3-Image Community License와 해당 지역의 별도 사용 허가 조건을 따릅니다. 이미지 모델의 허가는 영상 모델과 별개입니다.

## 헤르메스 대화 자동 보고

헤르메스 대화에서 제안을 확인하고 접수한 작업은 생성 완료 후 원 대화에 분석 보고서를 전달합니다. 생성 상태와 보고 상태는 별도로 표시합니다. 시각 모델을 사용할 수 없으면 관찰 불가로 기록하며, 영상 분석은 최종 MP4의 시작·중간·끝 표본과 첫 참조를 사용하므로 전체 동작과 재생 품질을 보증하지 않습니다. 오디오는 파일 정보만 확인하며 내용은 분석하지 않습니다. 독립 생성기에서 접수한 작업은 대화에 자동 연결하지 않습니다.

보고서 작성이 실패했거나 시각 관찰이 불가능했던 경우 대화의 보고 상태에서 재분석할 수 있습니다. 재분석은 생성 결과를 다시 만들지 않으며, 이전 보고서가 있으면 대화에 유지합니다. 시스템 메모리가 부족하면 분석을 대기하고 상태에 사유를 표시합니다.
