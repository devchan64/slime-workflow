# VACE-Fun 부분 편집 실험

## 영상 전체 조건 실험

`video_condition`은 RGB 원본 MP4와 외형 참조 PNG 1장을 입력한다. 모델에 전체 검정 마스크를
전달해 영상 전체를 조건으로 사용한다. 입력·출력은 자동 합성하지 않으며 자세·외형 보존과
셰이딩 개선은 보장하지 않는다. 사용자가 마스크를 입력하지 않으며 기존 부분 마스크 검증은
유지한다. GUI와 공용 게이트웨이는 동일한 `edit_video` base64를 사용하며 832×480·16fps·
32MiB 이하, 요청 프레임 이상이어야 한다. 8GB 실행 및 품질은 별도 검증한다.

`video_edit`는 완성된 원본 영상에서 지정 영역을 재생성하는 실험 모드다.
GUI·공용 게이트웨이 `wan22-vace generate`에서 기존 입력에 `mode: video_edit`,
`edit_video`, `edit_mask` MP4 base64를 추가한다. 외형 참조 `images`는 PNG 1장이다.
두 영상은 832×480·16fps·각 32MiB 이하이며 요청 프레임 이상이어야 한다.
마스크는 무채색이며 128 이상은 편집, 미만은 보존 조건으로 이진화한다.

공식 [마스크 편집 예제](https://github.com/aigc-apps/VideoX-Fun/blob/main/examples/wan2.2_vace_fun/predict_v2v_mask.py)의
`video`, `mask_video`, `subject_ref_images` 조합을 공식 파이프라인에 전달한다.
공식 pipeline의 `input_video = init_video * (mask_condition < 0.5)`에 맞춰
공식 파이프라인이 편집 영역을 정규화 중립값으로 지운다.
조건 강도는 전체 VACE 조건에 적용하며 얼굴 참조 전용 강도가 아니다.
원본과 자동 합성하지 않으므로 마스크 밖도 생성 결과에서 달라질 수 있다.

입력 사본 `edit-video.mp4`, `edit-mask.mp4`와 해시를 작업 폴더에 보존한다.
결과·로그·이력·GPU 측정은 기존 공용 작업 서비스에 저장한다.
원본·참조·편집 결과를 같은 프레임으로 비교하여 외형 개선과 동작 손실을 함께 평가한다.
영상·마스크를 불러온 뒤 다른 모드로 전환할 때는 두 첨부를 지워야 한다.

## 공식 실행부 전환 검증

공식 소스 커밋 `13bb3c625e8b1e457d7124d92207b49e00e4a6fe`와 기존
QuantStack 리비전 `93b339260b1d819e2c171dd7ca9e66a761d4a84d`를 유지한다.
`official_gguf.py`는 공식 모델 구조에 기존 GGUF를 연결한다. 양쪽 전문가의
1,331개 텐서 이름·형상을 엄격히 검사하며 Q4_K·Q6_K는 바이트를 CPU에
보관하고 계층별 CUDA FP32 역양자화 후 BF16 행렬 연산을 수행한다.
GGUF를 새로운 정밀도로 재양자화하지 않는다. UMT5는 기존 BF16 원본을
공식 인코더에 strict 로드하고 Accelerate 계층 오프로드로 CUDA에서 연산한다.
VAE도 기존 가중치를 공식 모델에 strict 로드한다.

공식 소스·토크나이저 파일 해시와 검증 환경 패키지 버전은
`config/official-runtime.yaml`에 기록한다. 공식 파이프라인과 별도 GGUF
연결부를 사용하므로 BF16 공식 예제와 동일한 수치 결과를 의미하지 않는다.
`official_prepare.py`는 고정 소스·토크나이저를 준비하며 전체 BF16 확산 모델을
다운로드하지 않는다. 작업 실행부는 공식 파이프라인을 사용한다.
공식 `VIDEOX_OFFLOAD_VACE_LATENTS=1` 옵션으로 제어 중간 텐서를 CPU에 보관하며
모델 연산은 CUDA에서 수행한다. 시간축 분할 VAE 래퍼는 사용하지 않는다.

2026-11-01 검증: 832×480 영상 부분 편집 21프레임·2스텝이 약 111초에 완료됐다.
공식 제어 텐서 오프로드와 디코딩 전 확산 모델 CPU 이동을 적용했다.
이는 실행 검증이며 20/50스텝 잔상·외형 품질과 81프레임 실행은 미검증이다.

## 키모도 DWPose 입력

`mode: pose`는 키모도의 처리된 DWPose MP4를 `pose_video` base64로 받는다.
캐릭터 외형 참조 PNG 1장을 `images`에 함께 전달한다. 영상은 832×480·16fps,
32MiB 이하이며 요청 프레임 이상이어야 한다. 재검출·프레임 반복을 하지 않는다.
`pose-video.mp4` 사본·SHA-256을 작업 폴더에 보존하고 이력에서 불러올 수 있다.
공식 `predict_v2v_control_ref.py`와 같이 `control_video`와 `subject_ref_images`,
빈 `video` 및 전체 생성 `mask_video`를 전달한다. 사용자 마스크는 받지 않는다.
GUI·CLI 모두 같은 `wan22-vace generate` 명령과 누적 이력을 사용한다.

## 공식 파이프라인 보존 정책

[모델카드](https://huggingface.co/alibaba-pai/Wan2.2-VACE-Fun-A14B)가 안내하는
VideoX-Fun 공식 파이프라인을 고정 소스 해시로 검증한다.
허용되는 구현 차이는 CPU 가중치·활성값 오프로드와 고정 Q4_K_M 모델 연결이다.
RoPE·FFN·잔차 연산 분할 및 AST forward 재작성은 제거했다.
스케줄러 step 교체와 자동 단계별 진단 실행도 제거했다.
공식 텍스트 인코딩·VACE 조건 구성·난수 생성·전문가 전환·VAE 연산을 유지한다.
가중치는 계층 forward 전후에 이동하며 연산은 CUDA에서 한다.
공식 구현의 VACE 잠재 CPU 오프로드 옵션은 보관 위치만 변경한다.

고정 소스의 `videox_fun/utils/gpu_memory_mode.py`에서 공식 순차 오프로드는
modulation과 RoPE 주파수를 먼저 CUDA에 배치한 뒤
`enable_sequential_cpu_offload()`를 적용한다. 현행 GGUF Linear는 일반 Parameter가
아닌 압축 레코드를 CPU에 보관하고 호출마다 CUDA에서 역양자화하므로 같은 훅을
중복 적용하지 않는다. 공식 코드도 호출별 역양자화와 그룹 오프로드의 저장소
소유권 충돌을 검사한다. 현행 연결부는 블록 및 비블록 모듈 이동을 별도로 관리한다.

추가 활성값 오프로드는 인코딩 완료 영상·마스크·잠재값, VACE 분기 계산 중의
본체 입력, K의 RoPE 계산 중 완료된 Q 결과를 CPU에 보관한다. 값·dtype과
Q→K 계산 순서는 유지하고 필요 시 CUDA로 복귀시킨다. 원본 소스는 수정하지
않으며 실행 시도 폴더에 파이프라인·VACE 모델의 이동문 추가 사본과 전후 해시,
변경 목록을 기록한다. 따라서 `official_forward_unmodified`는 false이고
`official_math_unmodified`는 true이다. RoPE 자체의 공식 계산 함수는 유지한다.

CUDA OOM 발생 시 `cuda-oom-tensors.json`에 예외 스택의 텐서 형상·dtype·저장소를,
`cuda-oom-snapshot.pickle`에 PyTorch 할당 이력을 보존한다. 저장소 주소별로
중복 제거하며 예외 처리 시점의 allocated와 OOM 메시지의 순간 allocated는
임시 텐서 해제 때문에 다를 수 있다. 이 기록은 외부 CUDA 할당을 포함하지 않는다.

기존 93프레임 실행 성공은 제거된 연산 패치가 포함된 기록이므로 현재 경로의
8GB 실행 보장으로 사용하지 않는다. OOM 발생 시 프레임·해상도·연산을
자동 변경하지 않는다. 양자화 어댑터는 BF16 원본과 동일 출력 보장이 아니며
가중치 이름·형상·지원 자료형 검증을 유지한다. 이전 진단·결과 파일은 보존한다.

### 활성값 오프로드 회귀 검증

2026-11-01 동일 입력의 21프레임·20스텝 비교에서 공식 연산 복원 기준 작업
`2026-11-01_21-29-29-96c0dfdd`와 활성값 오프로드 적용 작업
`2026-11-01_23-16-34-9e832cb4`의 PNG 21장이 픽셀 단위로 일치했다.
적용 작업은 약 1,042초에 완료됐고 프로세스 VRAM 관측 피크는 6,470MiB였다.
별도 CUDA 소형 텐서 검사에서도 BF16·FP32 및 배치 1·2의 Q/K RoPE 결과가
원본과 일치했다. 이 검증은 해당 입력·환경의 결과이며 모든 입력의 동등성을
실험으로 증명하는 것은 아니다.

93프레임·2스텝 작업 `2026-11-01_23-10-45-e542da67`은 고·저노이즈 전문가를
각 1회 사용하고 디코딩·저장까지 약 512초에 완료됐다. PNG 93장과 MP4를
출력했으며 프로세스 VRAM 관측 피크는 7,438MiB였다. 5초 간격 관측값은
순간 피크를 놓칠 수 있다. 2스텝 결과는 메모리 검증이며 품질 승인 기준이 아니다.

93프레임 실패의 마지막 진단 작업 `2026-11-01_23-06-28-e9c0654d`에서는
K RoPE 출력 할당 761.72MiB가 부족했다. 할당 이력에는 RoPE의 FP64 임시값이
각 1,523.44MiB, FP32 Q·K 및 완료된 Q 결과가 각각 761.72MiB로 관측됐다.
완료된 Q 결과만 CPU에 보관한 뒤 K 계산 후 CUDA로 복귀시키면 공식 dtype과
연산 순서를 유지하면서 이 중첩을 줄일 수 있었다. 따라서 이 실패는 Q3 변경보다
활성값 보관 위치 조정을 우선 적용했다. 할당 이력은 최대 20,000개 이벤트의
순환 기록이므로 이력에서 재구성한 합계를 장치 전체 점유량으로 해석하지 않는다.

2026-11-02 최종 작업 `2026-11-01_23-37-20-77f00893`은 실패 기준 작업과
동일 요청·참조·포즈 입력 및 모델 버전으로 93프레임·20스텝을 완료했다.
832×480·16fps MP4와 PNG 93장을 저장했으며 총 약 4,486초(74분 46초),
프로세스 VRAM 관측 피크 7,580MiB, 장치 전체 관측 피크 7,697MiB였다.
고노이즈 13스텝·저노이즈 7스텝이며 RoPE 정밀도·스케줄러·CFG는 유지했다.
이는 해당 환경·입력의 성공 기록이며 모든 8GB 환경의 실행 보장은 아니다.

전체 프레임 접촉 시트와 참조 비교에서 보행 동작과 머리·의상 색은 유지되지만
참조보다 흉부·근육 표현이 강해졌다. 얼굴은 대부분 옆·뒤로 돌아가 있어 얼굴
아이덴티 일치 판단이 제한된다. 큰 신체 분열·이중 잔상은 관찰되지 않았으나
손·발 세부 형태와 초기 배경 얼룩이 남는다. 실행 성공을 품질 승인으로 대체하지 않는다.
사용자 검수에서는 93프레임에 동일한 품질 오류가 남는 것으로 확인했다.
따라서 이 변경의 검증 범위는 OOM 개선이며 영상 품질 문제 해결을 의미하지 않는다.
동일 입력·20스텝에서 프레임 수만 41로 변경한 후속 작업
`2026-11-02_09-06-08-36627bde`를 등록했다. 후속 결과는 별도 검수한다.

### 초기 노이즈 통제 실험

공용 `wan22-vace generate --payload-file` 요청에 `noise_prefix_frames: 21`을
명시하면 `pose` 모드의 41프레임 작업에만 적용한다. 일반 GUI 생성에는 이 필드를
추가하지 않는다. 기본 경로는 그대로이며 실험 이력의 요청에 해당 값이 남는다.
동일 시드·CUDA·텍스트 인코더 dtype으로 21/41프레임 노이즈를 각각 생성한 뒤,
41프레임 노이즈의 첫 7개 잠재 슬롯(참조 1개 포함)을 21프레임 노이즈로 교체한다.
나머지 슬롯은 원래 41프레임 노이즈를 유지한다. 공식 파이프라인의 `latents`
인자를 사용하며 모델 연산은 바꾸지 않는다. 실행 시도에 `initial-noise.safetensors`와
형상·dtype·해시·공통 구간 일치를 담은 `noise-experiment.json`을 기록한다.
입력값 재사용 시 이 실험 필드를 누락하면 일반 실행이므로 기록을 구분해야 한다.

동일 요청에 `attention_prefix_frames: 21`을 추가하면 진단 전용으로 모든
self-attention에서 앞 7잠재 슬롯의 질의가 뒤쪽 슬롯을 참조하지 않게 한다.
뒤쪽 질의와 텍스트 cross-attention은 유지한다. 이는 공식 연산을 변경하는
원인 분리 실험이며 일반 생성의 품질 개선 옵션이 아니다. 실행 기록에
`official_math_unmodified: false`, `custom_math_patches: true`와
`attention-experiment.json`을 남긴다. `final-latents.safetensors`를 저장하고,
참조 슬롯을 제외한 앞 6잠재 슬롯을 별도로 디코딩한 21프레임 결과를
`comparison-prefix/`에 보관한다. 기본 GUI는 진단 필드를 추가하지 않는다.

분기 비교는 `attention_branch_scope: base`(본체) 또는 `vace`(제어 분기)를
추가한다. 생략하거나 `all`이면 두 분기를 제한한다. 고·저노이즈 전문가에
동일하게 적용하며 선택하지 않은 분기의 attention은 그대로 유지한다.
